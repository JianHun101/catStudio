# 评估体系（eval-system）定稿规格

> **定稿规格**（2026-09-30 写入）。源活：`eval-system` 票族（P1 / P2 / R 系列 / T 系列 / A 系列 / J1 等 20+ 票）。本文把其中**仍然有效且会被人重复问到的裁决**收成一份规格；票单与地图随在飞目录清理，过程留痕在 git 历史。
> ⚠️ **本文不是进度表**。哪些票已关、哪些还挂着，看文末「未闭项」；中间各节的判据是**定稿口径**，引用前先读该节的边界。

## 1. 形态：自建、零新依赖

评估体系**自建**，不引入外部平台。这不是偏好，是**两条排除**：

| 类别                                                                               | 对账结果                                                                                                                                                | 结论                 |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| 13 件 RAG 评估工具                                                                 | **无一件**提供不含参考答案的 `recall@k` / `precision@k`——「漏了哪一篇」这个信息只能靠标注；各家的 context precision / recall 一律要参考答案             | 加依赖买不到要的东西 |
| 6 家 trace 平台（Langfuse / Phoenix / LangSmith / promptfoo / Weave / Braintrust） | **全是查看器**——价值在「收 span + 画瀑布」，而缺口 100% 在**产出 span**，换平台省不掉最重那块；且**无一做卡点检测**，宣称「自动异常检测」的一律归商业版 | 换平台不解决缺口     |

**表按 `gen_ai.*` 语义命名，当词汇表、不当运行时依赖**：今天零新进程零新依赖；将来若接 OTLP，退化成「加一个导出器」，不必重新埋点。**存储面必须服从本仓词汇，不得为对齐 OTel 而造同名不同义的列**（本仓已栽两次：`chainRole` / `chainType`、`final_rank`）。具体：链锚列名取 `chain_id`（既有词汇），**不建** `trace_id` 列。

> ⚠️ **形态的唯一例外要明写**：检索链上后来进过一个**模型**（cross-encoder 重排候选）。它经离线三臂对照**净收益为负**（同预算下 23 < 27，动对 4 处、丢 8 处），已判**不接入生产检索链**，读数是 `docs/eval/rerank-offline-ab-2026-09-22.*`。⇒ 「零新依赖」在**运行时**成立；评估面/离线面的模型不进这条约束。

## 2. 观察单位与链锚（两处口径，改任一处都要重算全部历史读数）

- **观察单位 = 执行跳**（`execution_logs` 的一行），**不是消息行**。三条依据：
  1. **失败的跳不产生消息行**——按消息行分组会把卡点本身**静默吞掉**（页面显示「27 行都回了」，实际 25 跳里 4 跳死了、`reply_chars=0`）；
  2. 耗时/瀑布只能从执行的 `started_at` / `ended_at` 算，两张表分组口径不一致 ⇒ 「页面显示 27 跳、瀑布只画 25 条」的自相矛盾；
  3. 链锚覆盖率：触发侧 67.5% / 回复侧 92.5% / **coalesce 97.4%**。
- **链锚 = `coalesce(回复消息.task_id, 触发消息.task_id)`**。单用任一侧都会丢（触发侧丢 32.5%——用户消息多数没有 `task_id`；回复侧丢 7.5%，其中多数是失败跳、根本没有回复消息可 join）。
  - 剩余无锚的行必须**显式呈现为「孤儿跳」**（默认收起、数量恒显示、带解释文案），**不得静默丢弃**。孤儿在 dev 库的实测量级：28 行 / 2.6%。
  - **「链长」= 执行跳数**，不是消息行数。任何早先记的链长数字，凡是口径未标明的，**一律作废、不要引用**。
- **`trace_id` 是「当轮执行 id」，与链锚同名不同义**：二者不等率实测主库 18.8% / dev 库 21.7%。**禁止把 `trace_id` 当链锚用、禁止搬进 OTLP 语义位**——搬进会把整条链碎开。凡说「整条 trace」一律指链锚，不指 `trace_id`。

## 3. 耗时分解

- 一次执行的耗时只分两段，**两段都以执行行为单位**：
  - `replyMs` = 上下文过滤 + 记忆检索 + LLM 流式 + 落库（**不只是 LLM** —— 计时起点在处理函数**内部**，而令牌获取在它**之前**）；
  - `nonReplyMs` = 等令牌锁 + 编排收尾 + 建行开销（等锁是主要成分，**占比未实测**）。
- **禁用 `lockWaitMs` / 「等锁段」这类字段名与文案**——它会把「含编排与建行的混合段」报成纯等锁数字，**把假数报成真数**。要拿到纯等锁数字须新增列（动表），不属现有口径。
- **瀑布图以根段 `invoke_agent` 为轴，禁止加总子段**（加总必 >100%）：至少有一段（自动提交）的时间窗**落在根段之外**，加总子段得到的百分比是错的。终端答案以**根段**为准。
- **`running` 跳的段尚未落库**（一次执行一个事务、收尾时写）⇒ 必须与「`null` ＝无数据」**分开呈现**，不得显示为空白或 `0`。同款判据在链路 tab 已有先例（`null ≠ 0`，平均耗时显示 `—` 而非 `0`）。

## 4. 记忆检索的采集：三表

**拆三表的理由**：原先的单表方案把**三种粒度**（检索级 / 查询级 / 候选级）压进一张表，导致检索级的列被复制到每个候选行（一次检索约 23 遍）。判据是「**一张表主要代表一类东西**」。

- 三表：`retrieval_events`（检索级）/ `retrieval_queries`（查询级）/ `retrieval_candidates`（候选级）。**列数不是契约，语义边界是**。
- **凡事后无法可靠重算的值，一律冗余进表**（参数快照）——引入新的可调常量时必须同批加列快照，否则**历史行不可解释**。
- **身份键用三元组 `(doc_path, section_anchor, content_hash)`，不用 `chunks.id`**：索引是可重建的派生投影，重扫会换 chunk id。
- **`injected` 与 `dropped_reason` 必须分开**：「没被选上」与「被选上又因某原因丢了」是两件事，合成一列就再也分不出。
- **`body_head` 存正文全文，不截断**（曾截 120 字符，已去掉）。若只给 `injected=1` 的行落全文，会让该列**按 `source` 语义不同**——正是要消灭的形态。
- **`final_rank` 有前后两代语义**（旧＝名次最小 / 新＝跨查询累加分最大）⇒ 两段数据不可比，分析须按 `created_at` 或参数快照列（`param_pool_n IS NULL`）切窗口。**同名的列不代表同义的数**。
- 三表今天**无消费端点**（原始观测面暂不上页面）——数据持续在采，随时可再上。**跑批（受控测量、有 `expect`）与三表（真实流量的无对照观测、只能出分布）是两种东西，不可互替。**

## 5. 检索末次截断：按节计名额（与 `MEMORY_TOP_K=5` 绑定）

- **末次截断的粒度是「节」，不是「片」**。片级下 K 个名额会被同节的重复片白占（实际注入节数恒 ≤ K）；节级按定义填满 `min(K, 库内可用的不同节数)`。
- **绑定条款（本节的生效条件，不许只读前半条）**：节级**必须与 `MEMORY_TOP_K=5` 配套**。
  - 实测依据：节级 k=3 的可用收益 = **0**（与片级逐值相等），却要付注入 **+15.4%** 的代价；k=5 才是全表唯一显著收益格（constructed 0.8261 → **0.9565**）。
  - **若 `topK=5` 最终不落地（维持 3），本节改动应单点 revert**（`packages/server/src/memory/index.ts`）——不留「零收益 + 更多注入 + 断了下游自证」的改动在 `dev` 上。
- **卖点别读错**：节级的收益**只在 k≥5 兑现、且全落在构造组**；real recall 对截断粒度完全不敏感。同 K 下注入节数**恒增**是机制使然，不是实现偏差。
- **一处连带代价**：统计字段「候选片数」的语义由「融合 topK 片数」漂成「入选节的代表片数」（列名未改，属跨层契约债）。

## 6. 检索评估尺：黄金集与跑批

- **黄金集** = `docs/eval/retrieval-golden.json`，**40 条 = 真实 12 + 构造 23 + 负例 5**（v1，冻结基点见文件内 `meta`）。
  - 真实条目按**参考性六标准**选（有真实命中证据 / 跨域分层 / 形态多样 / 时间分散 / 过可答性闸 / 不够就如实报缺口，**禁止拿次品凑数**），且经**用户复核闸**（负例全部 + 真实 12 条）。
  - 负例 = query + **禁止命中锚点**，跑批时 forbid 锚点出现即整条判红。
  - 黄金集放在扫描白名单**之外**（`docs/eval/` 不被切片索引）——**天然防自指**：若考题进索引，跑批会捞到考题自己 ⇒ 假绿。
- **标注粒度 = 节**（`doc_path + section_anchor`，**不带** `content_hash`——片级哈希随语料腐烂）。
- **跑批跳过改写器**（条目内含冻结改写文本）⇒ 跑批是**纯确定函数**。代价明牌：**改写器质量不进本评估面**。
- **两个读数分开报、不合成总分**：真实组与构造组各出各的分——两组测的是不同面（现有负载精度 vs 全域覆盖洞）。
- **canary 反对照（测量工具的真空性）**：一条**必中**条目 + 一条**必不中**条目（语料外话题）。二者有任何一条不符 ⇒ 跑批脚本自身是恒绿/恒红假尺，**禁止出报告**。
- **指标定义**：recall（单条 = |expect ∩ 注入节集| / |expect|）+ 阈值前命中率（expect 中进了候选池但被阈值档杀的占比）。被测出口 = **全链最终注入节集**（改写之后的完整链段）。
- **索引新鲜度不可复原**：采集侧只记「当次召回了什么」，不记「当次索引里有什么」。凡语料写入时间与查询时间接近的读数，**一律按「不可判」处理**，不计入任何结论桶。

## 7. 判官与人的可信度

**先把口径纠正过来：缺的不是「度量」，是「常驻形态」。**

- **已有资产**（别重造）：一致性口径（三值判定：≥4 pass / ≤2 fail / **3 不计**）、排序相关性（Spearman）、闸门阈值（Spearman ≥0.7 + 一致率 ≥80% + 族间差 ≤15pp）、判官调用、人工回标路由与表——全部已实现且投产过。
- **Phase 0 选型定型**（离线一次性，50 条样本）：`kimi-k3` Spearman **0.754** / 一致率 **97.1%** / 族间差 **5.6pp**，三闸门全过；两个候选全灭。
- ⚠️ **2026-09-20 订正（本节最重要的一句）：「三闸门全过」撑不住「判官可用」。**
  - 一致率的分母被「两边都打 3 不计」压到只剩 **16/50** —— 那个 97.1% 是在一个很窄的可判子集上算出来的；
  - 判别力集中在**「好坏分明」的样本**上（判别力主要来自一批人造对照），**模糊带不可靠**；
  - ⇒ 结论修正为「**粗带可用、细带不可用**」。**要重测的不是判官，是标定集。**
- **用户裁决（2026-09-20，原话「保留但是暂时不使用」）**：判官链路**保留、暂不投入使用**——不砍、不降级采样链与看板，采样率维持现值。用户给的判据是「目前内容不好评估，且没有上下文联系，无法判断回复内容的真实性和可靠性」——⚠️ 这是**对判官输入面的判据，不是对成本的判据**，别读成「省钱所以先不做」。
- **一致性的分母端如今是关的**：采样率 = 0 ⇒ 活库评分表 0 行、回标表 0 行；且即使打开采样率，也**依然没有人算一致性**（一致性函数的唯一非测试调用点在一次性离线 CLI 里，回标数据会进表然后躺着）。这是自指环的**双重空缺**。
- **同一条判据同构适用于人工标注面**：标注样本**必须带上下文**（它回应的那条用户消息 + 当时的任务），否则人工标注会**继承它本该替代的那个缺陷**（人看孤立回复也只能打「读着顺不顺」）。补上下文**不违反盲标**——盲标禁的是判官分，从未禁上下文。
- **指标方向的分水岭（用户 2026-09-22 裁决）**：从「1-5 打分」转向「**二分类计数**」（如「100 个问题里有几条没用检索到的文档」）。它恰好绕开上面暴露的病灶——**粗带可用、细带不可用**。
  - ⚠️ **一条会得出相反结论的陷阱**：**文件名级检测恒等于 0**。注入的是 `docs/` 规格文档，而回复引用的是**文档正文里提到的源码路径** ⇒ 判「用没用」**只能做内容级判断**，便宜方法（grep 文件名）在这里是恒假门。
- **κ 类一致性指标暂不入闸**（入闸 = 给一把尺加否决权，而尺的标定集本身待重做）；**再启条件** = 标定集重做落地。
