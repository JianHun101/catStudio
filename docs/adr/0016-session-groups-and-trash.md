# ADR 0016: 分组管收纳、回收站管删除——退役「用户态删除 = 归档」

> **状态**：`accepted`（2026-11-15 用户拍板「按这版开票」）。**本 ADR 推翻** 2026-09 定稿的
> 「用户态删除 = 归档」（`docs/plans/db-schema-governance.md` §4.1 及票 7 产物）。
> **范围**：会话的收纳/删除两个用户态语义、`session_groups` 表、`sessions.group_id` /
> `sessions.deleted_at`、相关接口与事件。**不含**消息物理合并、多标签、拖拽排序。

## 1. 背景与摩擦

票 7 把用户态「删除」实现成 `sessions.archived_at`（归档 = 数据全留、列表默认隐藏）。
新的需求把「把会话收起来」和「删掉一个会话」拆成两件事，原模型有三处咬合不上：

| #   | 摩擦                                                                                                               | 证据                                                                         |
| --- | ------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| F1  | **一个开关承担两种意图**：想「按项目分组收纳」和想「删掉、别出现在任何地方」都落到归档上，用户无法表达「我要删」   | `listActiveSessions` 只按 `archived_at` 过滤；没有删除态                     |
| F2  | **归档没有分组概念**：37 条旧归档会话平铺在「显示已归档」里，「合并一系列会话（尤其 handoff `（1）` 链）」无处落地 | dev 库实测 60 会话 / 37 归档 / 32 交接子会话                                 |
| F3  | **组级动作缺落点**：整组收起、整组删除、整组恢复都要一个「组」实体；单会话归档只能是单条操作                       | `SessionList.vue` 逐行归档按钮；无 `session_groups` 表                       |
| F4  | **误删不可逆**：现有 `DELETE /api/sessions/:id` 是物理删除链（执行日志→消息→依赖行→会话），点错即丢                | `routes/sessions.ts` 的 DELETE 走 `purgeSessionDependents` + `deleteSession` |

**关键判据**：归档与删除若并存，左栏会同时出现「折叠 / 归档组 / 删除」三种让内容离开视野的
动作，用户分不清哪个是「删」。**收纳与删除必须是两条互不重叠的轴**，且「删除」必须可反悔。

## 2. 判定

> **分组负责收纳（可折叠、可改名、可整组删），回收站负责删除（7 天可恢复、到期物理清除）。
> 归档退役。**

「合并一系列会话」在本模型里 = **把一串会话归到同一组**，不是把多条会话的消息拼成一条
时间线。后者要动消息归属、摘要重算与 handoff 边界，是另一条独立的链，本 ADR 不混入。

## 3. 决策

### D1 · 两轴模型

- **分组**：单归属（一个会话最多属于一个组），无嵌套、无多标签。`session_groups` 表。
- **回收站**：`sessions.deleted_at`（ISO 毫秒 UTC，NULL = 未删除），保留 7 天。
- 两轴可叠加：组内会话可以先被单删（进回收站），组之后再被整组删——两次删除动作各自独立。
- **撤销/恢复**只回退一次删除动作；整组恢复不复活组内更早单独删除的会话。

### D2 · 归档退役，`archived_at` 冻结

- 旧归档会话在迁移时迁入一个**普通分组「归档」**（`collapsed=1`），`archived_at` 列**保留但
  冻结**：运行时代码不读、不写、不 DROP（迁移 / `PRAGMA` / 测试断言除外）。删列要连带删
  索引，收益为零，且列上还有历史数据。
- 归档写接口、`SESSION_ARCHIVED` 事件、前端归档按钮与「显示已归档」开关全部退场。
- **前端只有一个「收起」入口**：组头折叠箭头。折叠态存服务端 `session_groups.collapsed`，
  多 tab 一致，也让迁移出来的「归档」组默认折叠。

### D3 · 整组删除 = 组软删 + 同批会话同一时间戳

- `session_groups.deleted_at`；删组时**一个事务**内：给组打 `deleted_at`，并只给
  `deleted_at IS NULL` 的会话打**同一个时间戳**（字符串精确相等）。
- 组 **id 不变**；恢复 = 清组与同批会话的 `deleted_at`；恢复不碰 `updated_at`。
- 组内更早单独删除的会话时间戳不同，**不随整组恢复**，在回收站单列。
- 回收站条目粒度 = **删除动作粒度**：整组删 = 一条组记录，单删 = 一条会话记录。
  实现**不得按 `group_id` 聚合**。
- **仅解散**是另一个动作：硬删组行、组内会话 `group_id = NULL`，会话不进回收站。
- `?withSessions=1` 但组内**零未删会话**（含空组）→ 降级为仅解散，不产生回收站条目：
  组条目恒有 ≥1 条同批会话，`sessionCount` 不会出现 0。属于某次整组删除的成员只能经
  组级恢复 / 组级清除处理，单条接口返回 409 `SESSION_IN_TRASH_GROUP`。
- 组名唯一索引只约束**活组**：`UNIQUE(name COLLATE NOCASE) WHERE deleted_at IS NULL`（只折叠
  ASCII 大小写）。回收站里的组名不占位；恢复时若已有同名活组，**先**改名 `name（恢复）`
  （仍冲突则递增，计入 24 字上限）**再**清 `deleted_at`，同一事务——顺序反了会撞索引。

### D4 · 单删、忙碌与绑定守卫

- 单删默认**不弹确认**，直接进回收站 + 5 秒撤销 toast；`DELETE` 幂等，重复调用**不重置**
  7 天计时（保留第一次 `deleted_at`）。幂等靠 `getSessionByIdIncludingDeleted` 回读区分
  「从未存在 / 已清除」（404）与「已删但重复调用」（200 + 首次时间戳）；忙碌/绑定守卫只在
  `deleted_at IS NULL` 时跑，否则第二次删除会被自己的忙碌状态挡回 409。
- 会话有猫正在执行（`status==='busy' || queueLength>0`）或排队 → **409 SESSION_BUSY**，
  不落任何修改。v1 **不做「确认后自动停止」**：`disposeSession` 只清内存槽位、不中断在途
  stream，可靠停止需要新状态机（等 run settle），本版不承担。
- 会话绑定了外部群（`connector_bindings`）→ **409 SESSION_BOUND**，列出平台与外部 id；
  先解绑再删，否则外部消息会继续写进已删会话，静默丢消息。
- 整组删除时任一成员忙碌/绑定 → 同样 409，**一行都不改**（原子拒绝）。
- 删除后 `getSessionById` 默认排除已删行；另开 `getSessionByIdIncludingDeleted` 只给
  回收站 / 恢复 / 清除 / 清理任务 / 单删幂等回读用。点对点给约 30 处调用加过滤必漏
  （`routes/sessions.ts` 独占 16 处；全量清单以 T0 审计为准）。

### D5 · 7 天清扫

- `purgeAfter = deleted_at + 7×24h`，**服务端计算**（不信任前端时钟），接口按需返回。
- 服务启动扫一次 + 每小时扫一次；清扫主体**两类**：会话与组。契约是可注入时钟的导出函数
  `purgeExpiredTrash(now = Date.now())`（由 `trash-purge.ts` 的 `runTrashPurge` 调度，
  `index.ts` 只调 `runTrashPurge`）；**每条会话一个事务**，失败记
  日志继续；probe 模式跳过。整组删除的同批会话归组条目清（`deleted_at` 与组精确相等），
  其余已删会话归会话条目清，同一行不会被两条路径各清一次。
- 物理清除复用现有链：执行日志 → 消息（自带子行）→ 会话依赖（flow / verdict /
  connector_bindings 等）→ 会话行；组条目先清同批会话，全部成功后再删组行（零同批的防御
  分支直接删组行）。
- 删除后所有用户面读取（详情、消息、搜索、标记已读、回退、handoff 复用、socket join、
  `includeArchived` 列表）一律当不存在。**评估/记忆检索不套回收站过滤**：`saveMemory` 零
  实现消费、记忆只读 `docs/` 白名单 MD，「回收站退出记忆检索」是伪任务，从票面删除。

### D6 · 分组的其余口径

- 组顺序按 `created_at ASC`，**不建 `position`**（要拖拽再加列，`ALTER TABLE` 很便宜）。
- 组内会话按 `updated_at DESC`；「未分组」不是真组，只作兜底容器并排最后。
- 移动会话、改名、折叠**不碰** `sessions.updated_at`：分组是组织动作，不是会话活跃。
- handoff 新建的子会话自动继承父会话 `group_id`（父会话已删则落未分组）。
- 索引：`idx_sessions_active` 退役，换 `idx_sessions_live ... WHERE deleted_at IS NULL`；
  `listActiveSessions` 的 WHERE 与索引谓词逐字同形；回收站另建
  `idx_sessions_trash ... WHERE deleted_at IS NOT NULL`。

## 4. 备选方案（未采纳）

| 方案                                          | 为何不采纳                                                                                             |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **A1 保留组级归档，另加回收站**               | 左栏出现「折叠 / 归档组 / 删除」三种收起方式，用户分不清；确认框的说服力被稀释                         |
| **A2 整组删除时拷副本进回收站、恢复时新建组** | 组 id 变了，handoff 子会话与组的引用断；恢复改 `updated_at` 让会话凭空跳到列表顶部；会复活早先单删会话 |
| **A3 多标签（一个会话进多个组）**             | 「从这个组删除」是删会话还是只摘标签无法回答；恢复回原组、整组删除都失去唯一落点                       |
| **A4 物理合并多条会话的消息成一条时间线**     | 动消息归属、摘要与 handoff 边界，另一条链；本版用「归到同一组」表达合并意图                            |
| **A5 删除时自动停止在途执行**                 | `disposeSession` 不中断 stream；可靠停止是新状态机，v1 只返回 409 让用户先停                           |
| **A6 建批次号记录「哪条会话属于哪次删除」**   | 同批会话的 `deleted_at` 精确相等，本身就是批次标记；少一层数据模型                                     |
| **A7 删掉 `archived_at` 列**                  | 加列条目带 verify、删列要连带删索引，收益为零；冻结即可                                                |

## 5. 影响与代价

| 面       | 变化                                                                        | 代价 / 风险                                                                  |
| -------- | --------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 数据迁移 | 新建 `session_groups` + 两列 + 三段索引；37 条旧归档迁入「归档」组          | 迁移是一条多语句 `sql` 条目（runner 单事务包住），失败整体回滚               |
| 读取语义 | `getSessionById` 默认排除已删，新增 `...IncludingDeleted`                   | 约 30 处调用点需按「活 / 含删」分类；漏改会把回收站会话当活跃（T0 审计先行） |
| 用户面   | 归档按钮/开关退役；新增左栏分组、批量归组、删组确认、回收站主区、撤销 toast | 前端两票（T3/T4）+ 一票归档面清退（T5）                                      |
| 系统链路 | handoff 子会话复用、socket join、绑定写入必须排除已删会话                   | 不做会出现「删了还在写」的静默缺陷                                           |
| 运维     | 每小时清扫 + 启动补扫                                                       | 逐会话事务，单条坏数据不阻塞整轮；probe 模式跳过                             |

## 6. 决策留痕

- **用户拍板**（2026-11-15）：删除进回收站 7 天、归档交给分组、整组删除要确认、
  「合并一系列会话」= 归到同一组；并确认「按这版开票」。
- **店长自我推翻两处**：① 上一轮提的「确认框里给停止按钮」不成立——需新状态机，v1 只 409；
  ② 「回收站退出记忆检索」是伪任务——`saveMemory` 零实现消费，从票面删除。
- **采纳的实施侧事实**（吐槽猫实测）：`getSessionById` 约 30 处 / 8 文件；`disposeSession`
  不中断 stream；忙碌判据必须含 `queueLength>0`；`created_at/updated_at` 秒级 vs 新列 ISO
  毫秒禁止同框比较；`saveMemory` 零消费。
- **原型**：`workspace/session-manage-final.html`（gitignored，三场景 + 边界数据，Playwright
  实点通过）。悬停「移动到分组」出侧框，指针离开侧框即收起、主菜单不跟关。
