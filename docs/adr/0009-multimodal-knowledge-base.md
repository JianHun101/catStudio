# ADR 0009: 多模态知识库架构——文档块契约 + 跨模态向量子空间分离

> **背景**：用户定位多 agent 平台、对标生产环境、要求精确识别。知识库需订阅 AI 平台论文/博客/文档 + 网络知识，后续支持 PDF/Word 录入与图片语义检索。本 ADR 从目标愿景反推演进路径，钉死「一期内容不会被二期改掉或删掉」的两条不变量。
> **过 ADR 0007 四步检查单**：能力对账前置（视觉模型矩阵）／假设标红 + 实测对称（🔴 待验证项分列）／简单形态默认复杂举证倒置（DINOv2 判死，不做混合融合排序）／决策留痕（本 ADR 即留痕，证据段引用 2026-08-20 HF 实时下载榜 + transformers.js 4.2.0 源码实测）。

## 目标愿景（反推终点）

知识库四层：

1. **摄入层**：订阅/抓取（论文、博客、文档、网络）——调度 + 去重 + 增量
2. **解析层**：异构格式（PDF/Word/HTML/图片）→ 文档块
3. **嵌入层**：分模态嵌入（文本/图像各自向量空间）
4. **检索层**：跨模态检索 + 重排序 + 元数据过滤

## 反推路径

| 阶段 | 交付                                                                          | 落在哪层                    |
| ---- | ----------------------------------------------------------------------------- | --------------------------- |
| 现状 | 文本向量（bge 512）+ `memories`/`knowledge` 表 + sqlite-vec + FTS5 混合       | 嵌入/检索（文本单模态）     |
| 一期 | 视觉分支（`embedImage` + `image_embeddings` 表）+ 跨模态路由 + pHash 精确去重 | 嵌入层视觉分支 + 检索层路由 |
| 二期 | 订阅抓取 + PDF/Word/HTML 解析 → 文档块                                        | 摄入层 + 解析层             |

## 两条不变量（扩展性论证核心）

阶段一做的每件事，都满足「阶段二不需要改、不需要删」。审计结论：**无返工点**，前提是下面两条不变量钉对。

### 不变量 1：文档块契约（解析层 → 嵌入层的 ABI）

```
块 = { 类型: text | image | table, 内容, 元数据: 来源/页码/标题层级/抓取时间 }
```

- `类型` 是**开放枚举**：一期只用 text/image，`table` 槽位现在预留、结构到二期解析层再定义——预留槽位 ≠ 提前实现。
- `元数据` 是 JSON 对象：核心字段集（来源/页码/标题层级/抓取时间）现在钉死，其余字段自由扩展。
- 二期解析层是「新生产者」，只往契约里灌块，不改契约本身。契约的可扩展性是阶段一不返工的第一前提。

**物化落点**（契约须有可执行机制，非纸面语义）：

- 契约落 `packages/shared/src/schemas.ts`，Zod schema 命名 `DocumentBlockSchema`，TS 类型由 `z.infer` 派生——单一事实源。
- 开放枚举实现为 `z.discriminatedUnion('type', [text, image, table])`；`table` 是 schema 占位成员（`z.literal('table')`）、一期无生产者产出，未来新块类型追加 discriminator 成员属 additive 扩展，不改既有成员。
- `元数据` = `DocumentBlockMetaSchema`：核心字段 `source`/`crawledAt` required 钉死；`page`/`headingLevel` optional（分页文档 PDF/Word 的结构元数据，图片块无页码不填，二期分页文档可填）。其余字段 `.passthrough()` 自由扩展、向后兼容。

### 不变量 2：跨模态向量子空间分离

- 文本子空间：bge 512 维，`memories`/`knowledge` 表（现状不动）。
- 视觉子空间：SigLIP 768 维，独立 `image_embeddings` 表。
- **禁止**将 512/768 异构维度塞同一列做 sqlite-vec 余弦（ill-defined）。
- 跨模态召回由**查询路由器**按意图选索引：文本 query 找文本 → bge；图找图 → SigLIP 图像塔；文本 query 找图 → SigLIP **文本塔**（🔴 待验证，见下）。
- 视觉模型升级（如 768→1024 的 siglip-so400m）只重建 `image_embeddings` 一张表，文本表零触碰——子空间分离是「换模型 ≠ 换架构」的第二前提。

| --- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | ----------------------------------------- |

## Considered Options

- **单模态文本 + caption 降维**（图片转文字描述再走 bge）：零架构变更，但「同一张图两次描述可能不同、不同图描述可能撞车」，质量上限被文字卡死，不满足精确识别，弃。
- **单一混合向量空间**（全部投影到同维度同表）：过度工程，需强行投影归一，弃。
- **文档块契约 + 子空间分离（选中）**：诚实最小架构，两条不变量撑住跨期扩展性。

## Consequences

- 一期落地：`embedImage` 接口 + `image_embeddings` 表（768 维）+ 查询路由器 + pHash 去重（需新增图像解码依赖，走安装审批）。
- 二期落地：摄入层 + 解析层（PDF/Word），作为独立 ADR 对账，不绑一期。
- 维度迁移代价：老库少、重建成本低（用户已确认），视觉模型升级只需重建 `image_embeddings` 单表。
- 本 ADR 只钉契约与子空间，不锁低风险边界（四层内部细节边做边定）。
