# ADR 0007: 外部工具形态选型前置检查单

> **背景案例（opencode serve 立项回退）**：opencode 接入立项时，路线图把 `run` 形态定性为「单轮切片（消息进→文本出）」、agent 循环被认定只在 `serve`/`acp`——该定性未经验证即进入路线图前提，协议实测只覆盖 serve 形态，拍板基于被前提收窄的报告。事后实测 `opencode run --agent build --auto` 原生跑通工具循环（写盘+读回 7.7s），且 `--agent`/`--auto` 两个选项一直躺在 `--help` 里——对开源工具，能力对账比立项实测便宜一个数量级。回退 run 形态后，serve 特有的 4 个坑（守护进程死亡 / undici 300s 掐断 / SSE 缓冲非实时 / 「完成才响应」哨兵竞态）形态性消失。教训：拍板链上任何一环有机制卡住（前提未验证、实测不对称、复杂形态默认、决策无留痕），都不会走到回退这一步。

外部 CLI / 工具 / 框架（LLM CLI、agent 框架等）做形态选型时，必须走四步前置检查单；违反检查单的选型立项视为不合格打回。

## 检查单（四条，对治拍板链四环）

1. **能力对账前置**（对治「前提是猜的」）：候选形态 × 能力维度列矩阵；每条定性附三源证据之一（`--help` 原文 / README / 源码），拿不出证据的条目强制标「待验证」，不得以事实身份进入推理。
2. **假设标红 + 实测对称**（对治「实测被前提收窄」）：立项文档把「已验证事实」与「待验证假设」分列，每条假设配验证方式；候选池内形态的协议实测必须对称覆盖，「淘汰」只能发生在实测之后——实测只覆盖一个形态的立项视为不合格。
3. **简单形态默认，复杂举证倒置**（对治「复杂形态默认当选」）：默认最简形态（一轮一进程 > 长驻服务；stdin/stdout > HTTP/SSE）。要上复杂形态，立项必须附「简单形态为什么不可行」的证伪证据。
4. **决策留痕**（对治「复盘翻消息坟场」）：架构拍板记录必含证据段（help 对账结果 / 实测输出 / 文档链接），拍板无证据段视为不合格。

## Considered Options

- **经验把关（维持现状）**：零机制成本。但 serve 立项实证：查 help 就能推翻的前提，一路绿灯到拍板——经验把关在前提被污染时全线失守。
- **一刀切禁止复杂形态**：最安全但过刚。确有场景需要长驻形态（未来多客户端 attach 等），禁令会变成绕行理由，不如把举证责任放对位置。
- **前置检查单（选中）**：把「对账 → 标红 → 对称实测 → 留痕」固化为流程闸门。保留复杂形态的可行性，只要求举证。代价是立项流程变重——但相比回退一个形态 + 修 4 个形态特有坑的实付成本，便宜一个数量级。

## Consequences

- 新选型立项无证据段 / 假设未标红 / 实测不对称 → 打回，作者补齐重投。
- CLAUDE.md Architecture 区加一行引用本 ADR，全猫可见。
- 存量选型不追溯：serve 适配器代码保留为回滚路径（d555732 已收口），不因本 ADR 要求拆除。
- 本检查单是流程约束，不是代码——无测试，靠审查链执行（审查员按本文档核对立项单）。
