# ADR 0015: 一猫一 worktree——把「并行」从纪律变成结构

> **状态**：`accepted`（2026-09-15 起草并批准进入 Phase T；2026-09-30 由 `docs/run/` 转正为本文件，**同期订正三处**——D1 命名、D3 审查侧形态、§7-2 命名子决策状态，见各节内的「转正订正」块）。
> **范围**：**隔离模型**（分支 / worktree 粒度、命名、审查侧形态、存量处置）**+ 合并策略（fan-in no-ff / 幂等 / 中断守卫 / 回收）**。后者原属 T-3，经实测前移进本 ADR，T-3 已消解（§6.5）。
> **实现分段**：Phase S（模拟勘验）→ Phase T（仓内测试先行）→ Phase I（生产改动，已收口）。
> **上游问题**：用户提出「一个会话一个猫一个 worktree」；grilling 四问已闭环（Q1 = B 合并策略、Q2 = A/B auto-commit、Q3 = B 审查侧隔离、Q4 = A 收口后会话可继续使用）。

## 1. 背景与摩擦

现状：**一个会话一个 worktree**（`ensureSessionWorktree` 建，分支 `session/<shortId>`，路径 `<主仓库>/../catStudy-sessions/<shortId>`），**会话内多猫共用同一物理目录**。由此咬合出四条摩擦：

| #   | 摩擦                                                                                                                                                | 证据                                                                                                                        |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| F1  | **跨猫误提交**：auto-commit 用 `git add -A` 收整个工作区 ⇒ 别猫未提交的改动被按**提交者自己的 uuid** 收走                                           | 三次实证。`gitCommit()` 的 catch **不回滚索引**，且文案 `auto commit skipped (no changes)` **恒真**——钩子红被记成「没改动」 |
| F2  | **pre-commit 互锁**：pre-commit = `npx lint-staged; pnpm lint; pnpm test`，**全仓、无路径过滤** ⇒ 一猫的红**必然**挡死另一猫                        | 派活期间一只实施猫**连续 8 次提交全废**、跨约 6 分钟，失败面完全稳定                                                        |
| F3  | **审查面 ≠ 被判面**：审查猫跑测试跑的是**工作区**，而工作区里可能躺着别人的未提交文件 ⇒ 绿 / 红是**混合态**的颜色                                   | 一只猫受审时，工作区里同时躺着另一只猫未提交的三文件                                                                        |
| F4  | **脏检查抹别猫**：执行后清理 `git checkout -- .` + `git clean -fd`（`cleanWorktreeResidue`）作用域是**整个会话 worktree**，注释却写「本次执行遗留」 | 与 F1 是一枚硬币两面：一个把别人的改动收走，一个把别人的改动抹掉                                                            |

**F2 是关键判据**：它证明「票面文件零交集 ⇒ 可并行」这个判断**不成立**——pre-commit 是**仓级作用域、不是票级**。在共用 worktree 下，「零交集」不构成并行，只构成**互相拖死**。

## 2. 判定

> **隔离的独特价值，是把「并行」从纪律变成结构。**

必须诚实区分：四条摩擦里，**只有 F1/F2/F4 与粒度有关，F3 与粒度无关**。

| 摩擦 | 靠「串行派活」能解？ | 靠「一猫一 worktree」能解？ | 靠「一次性 detached 审查 worktree」能解？ |
| ---- | -------------------- | --------------------------- | ----------------------------------------- |
| F1   | ✅（无并发即无共写） | ✅ 结构性                   | ❌                                        |
| F2   | ✅                   | ✅ 结构性                   | ❌                                        |
| F3   | ❌                   | ❌                          | ✅                                        |
| F4   | ✅                   | ✅ 结构性                   | ❌                                        |

⇒ **「一轮一只猫」是用纪律买到同样的安全，代价是放弃并行。** 本 ADR 选择**结构**：不依赖「店长记得别并发」这条纪律——实践已经证明过这类纪律会失守（按「零交集」派的并行，代价是 6 分钟全废）。

## 3. 决策

### D1 · 粒度：worktree 与工作分支从「按会话」改为「按 (会话, 猫)」

- **工作分支**：`session/<sid8>-<catSlug(猫名)>`（**连字符**，不是斜杠——见下方命名修正）
- **worktree 路径**：`<主仓库>/../catStudy-sessions/<sid8>-<catSlug(猫名)>`
- **分叉点**：猫分支从 **`session/<sid8>`（集成分支）分叉**，**不从 dev 分叉**。这是 §6.3 方案 (a) 与 D2「收口链一行不改」共同成立的前提。
- `sid8` = 会话 id 前 8 位（沿用 `sessionShortId`）。

> **转正订正 · 后缀含义（2026-09-30）**：原文写 `cat8 = agent id 前 8 位`——**实现不是这样**。落地形态的后缀是**猫名**，经 `catSlug` 清洗后原样进分支与目录名（`catBranch` / `catWorktreePath` 定义处）。中文名无需转义，已由命名票 A1–A5 真机实证。
> 两条**显式抛错**（不静默降级为 id / 空串）：猫名含 `/`（静默剔除会把 `a/b` 折成 `ab`、与真名 `ab` 共用同一棵树）、清洗后为空（会造出空后缀分支，撞 S3-5 同形静默）。

> **命名修正（起草期实测推翻初稿）**：初稿写 `session/<sid8>/<cat8>`——**不可实现**。git 的 ref 是一棵文件树，`refs/heads/session/<sid8>` 与 `refs/heads/session/<sid8>/<cat8>` 构成目录 / 文件冲突：`git branch` 与 `git worktree add -b` **双双被拒**（`fatal: cannot lock ref`），`git pack-refs` 也绕不过，反序创建（先子后父）失败形态相同。改连字符后实测两者可共存。**后果等级**：建分支失败走「catch → 返回 null」= **静默降级、猫拿不到 worktree**——正好撞在降级路径收窄刚堵上的那条路上。故这是**开工前必须修掉的项**，不是实现细节。

- **`session/<sid>` 分支保留**，降级为**会话集成分支**（店长侧的集成入口 + 收口器的输入）。它不再由实施猫直接提交。

### D2 · 会话级 worktree 保留为**店长的** worktree（兼 fan-in 冲突隔离区）

`ensureSessionWorktree(sessionId)` **保留现有语义与路径**（`catStudy-sessions/<sid>`）。理由：① 收口器（`session-closeout.ts`）与 `removeSessionWorktree` 的自指守卫、`mainRoot` 探测等既有机制**一行不用改**；② **它还兼任 §6.3 的 fan-in 冲突隔离区**——主工作区被收口 preflight 钉死在 dev，而 fan-in 的 no-ff 合并必须发生在某个 checkout 了 `session/<sid>` 的地方，会话 worktree 是唯一现成的那个。**这不是「给店长分块地盘」，是保住一套按会话算的机制。**

> **措辞修正（起草期实测推翻初稿）**：初稿写「店长本来就在会话 worktree 里读写票面，语义自然」——**是错的**。所有猫（含店长）的执行 cwd 由 `reply.ts` 统一分派，**无角色区分**；但**店长的文档提交一律落主工作区（dev）**，因为票面是派活依据，实施猫从 dev 分叉、只看得见 dev 上的文件。

- **派活前置（两步，缺一即静默失效）**：① 店长文档提交落主工作区；② 派活前把 `session/<sid>` 同步到 dev HEAD，否则实施猫的票面是旧的。
- **现状**：这两步目前**全靠肌肉记忆**，零机制保证——与「通知没投出去」同族（靠人记，不靠结构）。

⇒ 净变化：**实施猫 / 审查猫从「共用店长的目录」变为「各有自己的目录」**，店长不动。

### D3 · 审查侧：把本会话全部猫分支合进审查者自己的树（**形态 G**）

> **转正订正 · 形态（2026-09-30）**：原文写「**一次性 detached worktree**」——**该形态实测不可达**，落地的是本节的形态 G。原文的 detached 方案是在「审查者已有的树够不够用」这个问题的第一轮答案，第二轮实测（审查者 cwd 内 `git merge-base --is-ancestor <被审 sha> HEAD` = `not-ancestor`、工作区文件读出旧版内容）证明它解决不了 F3，遂改判。

- **形态**：审查者（`role === 'reviewer'`）走**自己的猫 worktree**，建树后额外把本会话全部猫分支（`listCatBranches()` 枚举）合进**它自己的猫分支**。入口是 `ensureExecutionWorktree`（执行 cwd 的单源：建树 → 审查者额外合并），调用点在 `reply.ts` 的 `cwd:` 分派处。
- **只对审查者生效**：非审查者的树**不进**他猫提交——灌进去等于把刚建立的隔离拆掉。判据取 `role` 而非投递信号（投递级判据对审查者执行恒真）。
- **修 F3 的根**：审查者的树 = 集成分支 ∪ 全部猫分支 ⇒ 验证面与被判面**同一棵树**。
- **冲突 ⇒ fail-closed**：合并冲突时**显式抛错**，审查者**不开跑**、不产出回执；抛错**之前**先 `notifyConflictSource` 把返修单投回实施猫（否则审查者静默死掉、实施者不知道要动，重试永远撞同一堵墙）。投递与抛错**互不绑定**：投递怎么失败都不改 fail-closed。冲突仲裁归店长。
- **代价已实测**：幂等性代价**不存在**（同序重跑全 `SKIP(已合)`）；冲突代价**存在且形态明确**（审查者与被审改同一处 ⇒ 冲突，不重叠 ⇒ 干净，两向都有读数）。零分支移动：只动审查者自己的分支与集成分支，被审猫分支与 dev 逐字节未变。
- **硬前提**：必须是 `git worktree add`（**共享同一 object store**），**绝不可用 `git clone`**——clone 会切断 object store，那时审查才需要 push/fetch 中转，且跨会话按 sha 读的能力一并丧失。
- 读 diff 无需额外机制：`git -C <自己的 worktree> show <sha>` 直接可读（同 `.git/objects`）。
- **可审计性**（形态 G 的已知代价 = 审查者分支混入实施猫提交、归属面变模糊）：审查者树 HEAD = 目标分支上的 merge commit（`git log -1 --format=%s session/<sid8>-<猫名>`），且每次准备成功都留一条 `review view prepared` 日志（带 `merged` / `skipped` 计数）。

### D4 · auto-commit 限定提交范围（Q2 = A 打底、B 随本 ADR 落地、C 不做）

- **B 随本 ADR 天然达成**：一猫一 worktree 后 `git add -A` 只扫得到**该猫自己**的目录。
- **A（止血）已完成**：降级路径收窄——无 worktree 时**不提交**而非落主仓库。
- **C（彻底删 auto-commit）不做**：它与脏检查是**配对**的——`git add -A` 先收进 index，`checkout -- .` 才能从 index 恢复。单独删它会静默删除改动，比误提交更不可逆。
- **仍保留待修的一条**（本 ADR 范围内，小改）：`gitCommit()` 的 catch **不回滚索引**且文案恒真——失败后残留索引会被下一个裸 `git commit` 收走。**这是 F1 的残留通道，隔离后仍会在单猫范围内复发。**

### D5 · 存量处置：**不迁移**

现存会话 worktree（2026-09 之后的全部）**保持原状**，不迁移到新命名。新命名只对**新建**生效。理由：迁移要动几十个目录 + 同数量的分支，而收益只是命名统一；旧 worktree 随收口 / 废弃自然消失。旧命名分支与新命名并存期间，`session/<sid8>-*` 通配须能同时命中两者（枚举侧按后缀逆推猫名时**照着 `catSlug` 正着算**、不做字符串反解析）。

## 4. 备选方案（未采纳）

| 方案                                                  | 为何不采纳                                                                                  |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| **A1 只改 `git add -A` 为限定路径，不做隔离**         | 只堵 F1，F2/F4 原样在；且「哪些路径算这次改的」本身要一套推断，脆弱                         |
| **A2 靠「串行派活」纪律**                             | 复现成本已实证：按「零交集」判并行，6 分钟全废。**纪律会失守，结构不会**                    |
| **A3 每猫一个 `git clone`**                           | **切断 object store** ⇒ 跨 worktree 按 sha 读不到，审查链断；且磁盘 ×N 倍                   |
| **A4 每猫一条分支但共用一个 worktree（频繁 switch）** | `git checkout` 切分支会带走工作区未提交内容，且同一分支不能被两个 worktree 检出；比现状更糟 |

## 5. 影响与代价（要认的账）

| 面             | 变化                                                                                                  | 代价                                                                   |
| -------------- | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| **分支模型**   | 实施猫 = `session/<sid8>-<猫名>`；审查 = 自己的猫树 ∪ 本会话全部猫分支；`session/<sid>` 降为集成分支  | 店长收口从「单链一条」变成「N 条按序合进集成分支」，**冲突仲裁归店长** |
| **磁盘**       | worktree 数 ≈ 会话数 × 平均活跃猫数                                                                   | 回收由 §6.4-4 与 fan-in 同批落地（否则只增不减）                       |
| **启动开销**   | 每猫首次执行各建一次 worktree（实测**现建 368ms / 复用 51ms**）                                       | 可接受                                                                 |
| **pre-commit** | 不再跨猫互锁 ✅ 但每个 worktree **各跑一遍全量 vitest**                                               | 成本 ×N；这是**用算力换正确性**                                        |
| **既有机制**   | `removeSessionWorktree` 的自指守卫、`mainRoot` 探测、收口器五步**均不需改**（店长 worktree 路径未变） | —                                                                      |

## 6. fan-in 的接口与重切

> 本节初稿含一条**错误判断**（「no-ff 会破坏现有幂等，中断重跑会再产生一个 merge commit」）——五组实测推翻。

### 6.1 实测结论（临时仓实跑，非推演）

| #   | 问题                                                  | 实测结果                                                                                                                                                                |
| --- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| E1  | `session/<sid>` 与 `session/<sid>/<猫名>` 能否共存    | **不能**。`git branch` 与 `git worktree add -b` 均 `fatal: cannot lock ref`；**pack-refs 绕不过**；反序（先子后父）同样失败 ⇒ D1 初稿命名**不可实现**（已修正为连字符） |
| E2  | 两条猫分支自同一点切出，按序 `merge --ff-only`        | 第一条快进 OK；**第二条「非快进」失败** ⇒ 原预言**成立**                                                                                                                |
| E3  | `merge --no-ff` 重跑同一条已合分支                    | **`Already up to date.`，HEAD 不变** ⇒ **no-ff 自身是幂等的**（原判断「会再产生 merge commit」**错误**）                                                                |
| E4  | 真冲突后的仓库态                                      | 留 `MERGE_HEAD` + `UU` 半合并态；重跑 merge 报 `Merging is not possible because you have unmerged files`                                                                |
| E5  | `session/<sid>` 停在分叉点时 `closeoutSession` 会怎样 | `merge --ff-only` 输出 `Already up to date.`，**退出码 0**                                                                                                              |

### 6.2 由 E5 得到的硬结论：fan-in 是隔离落地的**必备件**，不是后继

实施猫只在自己的分支提交后，`session/<sid>` **不再收到提交**，而 `closeoutSession` 只合这一条分支，`removeSessionWorktree` 也只删这一条。E5 证明这条路径会：

**空合并成功（退出码 0）→ 写 gate → 删掉会话 worktree + 会话分支**，而**猫的分支与猫的 worktree 全部留在原地、从未进过任何地方**。失效形态是**静默的**——工具返回 `ok:true`。

⇒ 「N 条猫分支按序合进集成分支」必须与隔离**同批落地**；原 T-3 定义（把 dev 侧合并改成 no-ff + 补幂等）**方向是错的**：它假设合并发生在 dev 侧，而真正需要 no-ff 的是集成分支侧的 fan-in。**退出码 0 不等于活落地**——本 ADR 最容易被误读成「稳妥增量」的一处。

### 6.3 合并落点：fan-in 关进集成分支，dev 侧保持 ff-only

| 方案                                                                                 | 冲突落在哪                         | `mergeSession` 的幂等基石                          | 新增面                    |
| ------------------------------------------------------------------------------------ | ---------------------------------- | -------------------------------------------------- | ------------------------- |
| **(a) fan-in 在会话 worktree（checkout `session/<sid>`）里 no-ff；dev 侧仍 ff-only** | **不落 dev**                       | **原样保留**（收口链的 "Already up to date" 判据） | fan-in 枚举 + 幂等判断    |
| (b) 直接把 N 条猫分支 no-ff 合进 dev                                                 | 冲突落 **dev 主工作区 ⇒ 全仓阻塞** | 被替换                                             | 更大：`mergeSession` 重写 |

⇒ **取 (a)**。它同时给了 D2 一个比「机制不用改」更硬的理由：**会话 worktree 是唯一能安全承载 fan-in 冲突的地方**（主工作区被收口 preflight 钉死在 dev）。

### 6.4 fan-in 的四个新面

> 本节经 Phase S 模拟勘验修订（12 格实测）。四条全部有改动，**第 1 条是阻断级**。

1. **枚举**：按 **`refs/heads/session/<sid8>-*`** 列猫分支——**通配符 `*` 不可省**。裸前缀 `session/<sid8>-` 只命中**精确同名**那一条，`-猫A` / `-猫B` **一条都收不到**——git 对不含通配符的 pattern 按 `/` 边界匹配。失败形态**全链静默**：枚举 0 条 → 循环 0 次 → 零报错，猫的提交（确实存在）完全不在集成分支上。与 E5 叠加 = **全链零报错的静默不合并**。
2. **幂等**：每条猫分支合并前判 `git merge-base --is-ancestor <cat> <integration>`——已合即跳过，给中断重跑兜底（E3 证明 no-ff 本身已幂等，这层是双保险）。整链重跑（非单条）同样幂等。
3. **中断态守卫**：preflight 探测 **`MERGE_HEAD` 存在性**（E4）⇒ 显式失败交店长仲裁，**绝不在半合并态上继续跑 writeGate / checkoutDev**。冲突码**不止 `UU`**：分叉点上不存在的文件被双方各自新增 ⇒ `AA`；已存在的文件被两边改 ⇒ `UU`；两者**可在同一次 merge 内并存**。⇒ **判据取 `MERGE_HEAD`，不按冲突码枚举**（`MERGE_HEAD` 非恒真：非冲突态 `rev-parse` 返回 code=1）。
4. **回收**：fan-in 完成后按同一枚举删猫 worktree + 猫分支——否则只增不减。**硬前提**：只回收**已合入集成分支**的猫分支（判据同第 2 条），**未合分支绝不回收**——否则删掉未合的活。`*` 可匹配空串 ⇒ 分支 `session/<sid8>-`（猫名为空）会被枚举命中，枚举侧须过滤空后缀。
   附：`removeSessionWorktree` 有**自指守卫**（收口者正站在被收口的 worktree 里时**跳过物理残留清理**）。D2 把 fan-in 落在会话 worktree 上 ⇒ 收口时 cwd 与该目录的关系会决定残留清不清。既有机制、非本 ADR 引入，但回收实现必须知道它存在。

### 6.5 结论：T-3 消解

原 T-3「no-ff 合并策略 + 幂等」**整体前移进 fan-in**；dev 侧维持 ff-only、幂等基石不动 ⇒ **T-3 不再是一张独立票**。

- `cherry-pick` **仍排除**：它改变 sha，而**审查链的锚就是 sha**。
- `--no-ff` 不是新形态：远端 dev 上就有 PR 的 merge commit。

## 7. 三点确认记录

1. **主决策**：一猫一 worktree（D1–D3）**+ §6.4 fan-in 四个新面**（原 T-3 前移）。
2. **命名子决策**：分隔符经实测定为**连字符**（`session/<sid8>-<猫名>`）。
   > **转正订正 · 状态（2026-09-30）**：原文写「`cat8` = agent id 前 8 位，保留；这仍是**唯一可无痛替换的子决策**」——**该替换已执行**：后缀现为 `catSlug(猫名)`（D1 订正块）。替换理由是实现侧的：id 前 8 位人眼认不出是谁，而猫名让 worktree 目录、分支名、`git worktree list` 一眼可读；代价（中文需清洗 + 碰撞处理）由 `catSlug` 的显式抛错兜住，不静默。
3. **D5 存量**：**不迁移**——存量是**会话级** worktree，不适用新命名，随收口 / 废弃自然消失。

## 决策留痕

- **起草前的存量清理**（用户指令「删 9 月之前的 worktree、分支」）：删 18 个 session worktree + 18 条分支，判据是分支末次提交日与目录 mtime 均早于 2026-09-01 且 DB `sessions.updated_at` 无 9 月活动；删除前实测 18 个 worktree 脏文件数全为 0 ⇒ 无未提交的活被删。
  **安全约束**：worktree 内的 `node_modules` 是指向**主仓库**的链接（junction）；`git worktree remove` 只注销 git 层并留下链接空壳，残留清理由 Node `unlinkSync` 逐链接删除（**绝不 recursive 跟随**），删除前后主仓库 `node_modules` 顶层条目数不变（未跟穿）。
- **E1–E5 的取证方法**：在**仓外临时目录**建一次性 git 仓复现（不碰本仓），五组对照；E1 只判死「斜杠命名」，**整套隔离设计本身未被推翻**——改一个字符即可落地。真正被推翻的是初稿的幂等判断与「T-3 在后」的排序。
- **Phase S 模拟勘验**：仓外一次性 git 仓，12 格矩阵 / 68 断言，全绿 + 变异验证（把判据改回票面原文写法 ⇒ 真变红，证明判据非恒真）。**方法教训**：模拟只看 git 层，会把「实现已经做对的事」列成待办 ⇒ **缺口清单必须与既有实现逐条对账后才能定级**。
  **覆盖边界**：各格起独立仓，故「fan-in 产物 → ff 进 dev」这条跨格拼接面无人验；且模拟跑的是**手工 git 命令序列**，证不了「生产代码会这么写」——这正是 Phase T（仓内测试先行）存在的理由。
- **一条独立缺陷的归因订正**：Phase S 期间实测到「`execute crash` 判死后原进程未被终止、同一 agent 两条 CLI 同跑同一票单」。当时归因为**进程管理缺陷**；后续实测推翻——根因是 `executeRun` finally 段的**误收口**：本帧在 `Promise.all` 的 await 窗口让出控制权，新触发见槽位 idle 即开跑；本帧 await 结束 return 后，finally 见 busy 便收了**别人的槽位**（单槽位 FIFO 被击穿 ⇒ 同 agent + 同 session 双执行）。修复 = finally 段加槽位归属校验（只收本帧槽位）。**与隔离粒度无关**，本 ADR 不解决它。
