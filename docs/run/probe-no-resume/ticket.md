# 探针实例禁恢复开关（probe no-resume）

**状态**：已立票，未派
**来源**：T2 审查 OQ-5（吐槽猫提议，店长裁决立票，2026-09-28）
**优先级**：P2 —— 任何做真机自证的猫都会踩

## 问题

真机自证的标准口径是「worktree 自起 vite + 自有 server 探针实例（自有端口）+ 无头 Edge CDP」。但**只读意图的探针实例在本仓并不只读**：

- 启动序列有两条恢复路径会捡起库里的 in-flight 执行（`server_restart` / `running` 状态行），探针实例一旦用**活库副本**启动，就会真实恢复执行——spawn 真 CLI、cwd 落在工作树里，产生真实副作用。
- T2 真机自证时 ds猫 的 workaround 是环境侧硬压：副本库先摘掉 `server_restart`/`running` 行 + 清空 API key，才让探针实例「安分」。这层压制每次靠实施者自觉，漏一步就出事。

## 修法方向（裁决：启动序列加显式开关）

新增显式禁恢复开关（形态示意：`CATSTUDY_PROBE_MODE=1` 环境变量），开启时：

1. 跳过全部 in-flight 恢复路径（`server_restart` / `running` 行不捡）；
2. 不 spawn embed sidecar 之外的任何常驻子进程 / CLI 执行；
3. 探针口径文档（真机自证一节）改为「起探针实例必须带此开关」，替代「摘行 + 清 key」的手工压制。

## 验收（行为可验）

1. 活库副本 + 开关启动：日志零恢复记录、零 CLI spawn；不带开关启动同一副本：恢复路径照常触发（反对照）。
2. 既有恢复行为测试全绿（默认路径不受影响）。
3. 探针口径复述面同批更新（AGENTS.md Gotchas / 派活单模板中的自证口径）。

## 边界

不改正常启动序列语义；开关只收「恢复 + spawn」两面，不做成通用只读模式（读口写口不在本票范围）。
