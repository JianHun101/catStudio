## 结论

**票 B §5 那句未经实测的断言——「G-1~G-6 是令牌与全局层问题，必然同样命中 App.vue/ChatPanel.vue」——
逐条实测后：4 条命中、1 条部分命中、1 条在本页被证伪、1 条不落本页。**
「必然」不成立：主交互面存在**同一个令牌问题的四种落点、三种命运**，
按令牌一刀切修会漏掉硬编码那一路（详见 §2）。

**本页真正拦路的，是三件票 B 两页都没暴露的事**：

1. **主输入框没有焦点环。** 全站有全局 `:focus-visible`（`index.html:257-261`，2px accent 实线），
   实测对照按钮确实吃到了它；但 `.chat-input { outline: none }`（`ChatPanel.vue:1743`）经 scoped
   `[data-v]` 特异性（0,2,0）压过全局规则（0,1,0），且本文件**没有** `.chat-input:focus` 兜底
   ——真机聚焦后 `:focus-visible=true` 而 `outline-style: none`。**全站唯一一个「看得见光标、看不见焦点」的控件。**
2. **一个完全不可见的按钮在键盘 Tab 序里。** `.scroll-down-btn` 靠 `opacity: 0` + `pointer-events: none`
   隐藏（为保 `scrollHeight` 稳定，注释已写明是有意为之），但**没摘 Tab 序、没加 `aria-hidden`**——
   真机键盘实测 **第 69 跳**命中它，`:focus-visible` 匹配成功，焦点环连同元素一起被 `opacity: 0` 抹掉。
   键盘用户会「Tab 进一次虚空」，读屏念「0 条新消息」。
3. **冷色岛比票 B 那处大一个量级。** 票 B 记的是设置页一处 `rgba(96,165,250,.12)`；
   本页 `ToolRow.vue` 整个组件建立在 9 处硬编码冷色上（`#4a9eff`/`#58c97b`/`#ff6b6b` +
   `rgba(130,170,220,*)`），`DiffViewer.vue` 直接用 GitHub Primer 色值。
   **暗色下全部达标，浅色下全部崩**（`#58c97b` 1.98:1）——因为它们是硬编码、不随 token 走。

**另有两条本页独有、票 B 结构上不可能有的对比度塌陷**：
`--accent` 当文字色在浅色下 2.76:1（猫名 `.msg-sender`、`.status-name`、`.streaming-indicator`），
以及 `SessionList` 的重试按钮浅色下 **2.04:1**（`--accent` on `--accent-soft`）。

**反向结论（避免误伤）**：**票 B 的 S-1「placeholder 当唯一标签」在本页不成立**——
新建会话弹窗有 `<label>`（真机探针证实）；**且本页藏着 S-1/S-4 的正确解法范例**：
右栏 picker 用 `<label><input type="checkbox">`，而左侧 `.agent-select-item` 用 `<div @click>`
（真机 `tabIndex: -1, role: null`）——**同一个「选猫咪」，同一份代码库，两套做法、一好一坏。**

## 6. 一句话总评

**主交互面是「工程判断力强、设计系统性弱」的又一例证，且它的短板与票 B 两页**不同源**：
票 B 的病是「设计系统只做了一半」，本页的病是「**同一个决定在不同文件里被做了四次，四次的答案都不一样**」——
浅色主按钮修了一个漏了四个（`.btn-send` 4.63 过线，`.btn-create`/`.btn-ok`/`.btn-restart:hover`/`.btn-retry` 全 2.5 左右），
选猫咪有 `<label><input>` 与 `<div @click>` 两套（相隔两个文件），
加载态有骨架屏与圆周转圈两套，`:focus-visible` 全局定义被一个 `outline: none` 单点抹掉。
**它不缺判据、不缺范例、甚至不缺注释（源码里为每个取舍都写了理由）——缺的是把已有正解横向拉齐的那一步。**
