无箭头、无方块，滑块默认半透明。

为什么之前写了 ::-webkit-scrollbar-button { display: none } 还没用： 会话列表和聊天区又同时设了 scrollbar-width: thin 与 scrollbar-color。Chromium 121 起，这两个标准属性一旦出现，整块 ::-webkit-scrollbar-* 定制就被忽略，浏览器回落到系统默认滚动条 —— Windows 上默认滚动条两端就是带箭头的。所以那行 display:none 等于没写。 修法：把标准属性只留给 Firefox（用 @supports 包住），Chromium 走纯 WebKit 定制。

② 会话前的复选框 → 改成按钮触发

可点 · 右边点「多选」试试

③ 未读提示的大小与位置

三案 · 等拍板

现在那个红色数字块挂在行尾、和第二行的「日期」同一水平带，宽 20px，日期只能往左让。 三个方向：A 保持原位、只缩小；B 缩小并挪到第一行；C 只留一个 6px 红点，日期完全不受影响。 三行用的都是真实右栏宽度，可以横着比。

A · 现状 20×18，行尾

红色块占 20px，日期被往左挤；视觉上也最重。

B · 小号数字 16×15，标题行右端

数字还看得见，日期这一行彻底让开；标题可用宽度少 16px。

C · 只留红点 6px，标题行右端

最安静；条数放进 hover 提示（title），不再占行内宽度。

我的建议是 C。未读提示要回答的是「有没有新东西」，不是「有几条」；真要数量，hover 或者点进去都看得到。B 也能用，代价是标题少 16px —— 右栏只有 236px，标题本来就常被截。 A 只是把同一个问题缩小，日期还是被挤。

④ 聊天区的「N 条新消息」

若你指的是这个 · 三档大小

左栏那个是「会话未读数」，聊天区这个是「你往上翻时，底下又来了新消息」的回跳按钮。 两者不是同一个东西。如果你说的「挤占日期位置」是左栏的，看 ③ 就够；如果指的是聊天区这个， 这里给三档。它浮在消息流底部，尺寸大时会把底部的日期分隔线顶上去一截。
