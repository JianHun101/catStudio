# 票面 · A2A 派发被队列 drain 延迟 —— 症状、取证与待证格

> 立项时间：2026-09-16（本地 12:1x）
> 来源：店长复盘自己 12:01 给 ds猫 的派活单为何没被执行
> 状态：**已立 · 未派活**（等用户点名时机）

## 结论先行

执行者一轮的收尾若**同时**满足两条：

1. 该轮回复有 A2A 派发目标（@ 了别的猫 / `post_message` 投了靶）；
2. 该执行者**自己的队列非空**（有排队命令待执行）

则第 1 条的派发**不是丢掉，是被排在 drain 之后**——而 drain 的分支是一条可任意长的 A2A 嵌套链。实测里它已经挂起 8 分钟以上仍未发出，形态上等同丢单。

## 一、现象（实测，非推断）

| ------------ | ------- | ------------ | ---------- | --------------------------------------------- |
| 11:43:14     | flash猫 | 吐槽猫       | 空         | ✅ 日志有 `agent-to-agent dispatch`           |

两条未派发的消息实测：

- 消息列 `mentions` **已写入**目标名（`["店长"]` / `["ds猫"]`）——即 `post_message` 的 route signal 落库成功；
- `dispatch_state` 为 `null`（从未作为触发被排队）；
- 全日志区间 `12:00–12:20` 的 `agent-to-agent dispatch` 行**只有 吐槽猫↔店长 一条链**，无 ds猫；
- 全日志无 `agent-to-agent mention limit filtered`、无 `mention blocked by role policy`——**排除配额与角色白名单**；
- 该时刻 `queue → next` + `draining queued command` 紧跟在 `review fallback judged` 之后、占据 `agent-to-agent dispatch` 本应出现的位置。

## 二、机制（代码读数，标注置信度）

`packages/server/src/execution/serial.ts`：

- `:798` `finalizeRun(...)` 弹队列，命中则 `:813-815` `await drainQueuedCommand(ctx, agent, queuedCmd, claudeRan)`；
- `:830` `if (policy)` 起的 A2A 派发段（`:942` 打 `agent-to-agent dispatch`）**在 drain 之后**；
- `:809-812` 的注释自陈这次次序调整的理由：让队列命令优先，避免它干等当前回复的 A2A 嵌套链（该注释并称 A2A 派发本身是 `await` 的，引用了 d448413a 案例「被两层 A2A await 拖 5.9 分钟」）。

⇒ **机制读数**：drain 内的命令会跑它自己的一整条 A2A 嵌套链（每层 await 下一层），外层帧停在 `:814` 的 await 上；`:830` 的派发于是被排在整条链之后。

**置信度分级**：

- 「两条消息有 mentions 而未派发」= **实测**；
- 「未派发与队列非空 4/4 同现」= **实测相关**（样本 2 对，小）；
- 「因外层帧停在 drain 的 await 上」= **代码读数 + 日志序推断**。`serial.ts:811` 那段注释是**作者自陈**，不是我的测量。

## 三、待证格（本票最重要的一格）

**未证的关键点：延迟 vs 丢弃。**

- 若是**延迟**：当这条嵌套链最终解开、外层帧恢复时，ds猫 的派发会**补发**出来（届时同一条 `c76fa920` 会被执行一次）；
- 若是**丢弃**：永不出现。

判定法：链解开后查全日志有无 `fromAgent=店长 mentionedNames=["ds猫"]` 的 `agent-to-agent dispatch` 行。**本票写下时该链仍在进行中（吐槽猫 12:09:45 起一轮，店长即为本轮执行）**，故这一格留空，不许填推测。

## 四、验收（修好后，行为可验证）

1. **V1 主判据**：构造「执行者有排队命令 + 该轮有 A2A 目标」→ 目标在**本轮回复结束后 30s 内**被派发（不随 drain 链长度漂移）。
2. **V2 反向对照**：修复前同构造 ⇒ 复现「无 `agent-to-agent dispatch` 行」，**先红一次再绿**。
3. **V3 不回归**：drain 优先的原意不得丢——排队命令仍不得干等 A2A 嵌套链（即 d448413a 那类 5.9 分钟干挂不许回来）。**V1 与 V3 是同一根绳的两端，只满足一端不算修好。**
4. **V4 真仓留痕**：`messages.dispatch_state` 不得再出现「mentions 非空而 state 恒 null」的派发行。

## 五、边界

- **不在范围内**：配额与角色白名单（本票已实测排除）；`post_message` 的 route signal 落库（实测正常，`mentions` 列已写入）。
- **不动的**：`finalizeRun` 的 FIFO 语义、`drainQueuedCommand` 自身。
- 形态候选（A：派发不 await drain，先登记后执行；B：把 A2A 派发移出 drain 的前置位；C：给 drain 加超时并把派发挪回前置）——**派活前由店长裁决，不写死在票面**。
