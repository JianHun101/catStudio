# docs/run 存量清理与结论上浮

> 状态：已立票·未派
> 立票：2026-09-29 店长
> 来源：用户问「记忆片跟内容关系不大」→ 归因报告（PR #198）→ 空手事件 60% 桶 =「本仓域内但白名单三目录无对应文档」→ 追问「为什么没上浮到记忆文件夹」

## 背景

- 检索白名单 = `docs/adr` + `docs/lessons` + `docs/plans`（三目录切片同时是 **prompt 教学面**——注入每只猫的 system prompt）。`docs/run` 是在飞草稿面，**不入白名单是既定正确设计**（半成品措辞不该持续投喂）。
- 但约定「活收口即清，结论上浮到 `docs/plans/`」（AGENTS.md Pointers 段）**无人执行**：本会话七票全收口、零上浮；`docs/run/` 现存 **35 个票单目录**（2026-09-29 实数），已收口与在飞混躺。
- 后果：结论停在草稿面，检索只能对着 7 篇 plans + 11 篇 lessons 回答一切——空手桶的「已收口」部分由此而来。

## 目标

1. **存量**：35 个目录逐票定状态，已收口的结论上浮 + 目录清理；在飞/挂账的保留。
2. **流程**：收口链加显式上浮步骤，让「不上浮」从默认遗忘变成有痕决定。

## 上浮判据（本票核心）

上浮对象是**结论**，不是票单。五条判据，逐条过：

1. **持久有效**：脱离票单语境仍独立成立的知识（规格 / 机制 / 判据 / 判别口诀）。过程叙事（派活流水、审查往返、时间线、谁报了什么）**永不上浮**。
2. **有消费面**：答得出「谁会查它」——检索语料 / prompt 教学面注入 / 后人设计查阅。答不出就不上浮。
3. **不重复真相源**：代码、git history、AGENTS.md、既有 plans/lessons/adr 已承载的，不复制第二份（平行真相源是本仓要消灭的东西）。
4. **落点分流**：定稿规格 / 设计结论 → `docs/plans/`（点名，不二选一）；教训 / 坑 / 判别口诀 → `docs/lessons/`；新架构决策 → `docs/adr/`（先读既有编号）；三不沾 = 过程记录，直接清。
5. **未被取代**：结论至今仍真。已被后续变更推翻的不上浮（或按 `retired-docs-tombstone` 先例标 superseded 留碑，视价值定）。

## 流程（两段式勘察型）

**段 1 · 勘察**（产物在 docs/run 内，免审面）：

- 逐目录读 ticket.md + 关联 commit/PR，产出本目录下 `inventory.md`：每目录一行 —— 状态[已收口/在飞/挂账/废弃] ｜ 关联 PR/commit ｜ 上浮建议[plans/lessons/adr/不上浮] ｜ 理由一句。
- 判定拿不准的标「待店长裁」，不硬猜。

**段 2 · 裁决**：店长 + 用户对 inventory 逐批拍板。

**段 3 · 执行**（触 `docs/plans` / `docs/lessons` / `docs/adr` / `AGENTS.md`，**非免审面，走正常审查链**）：

- 上浮 = **改写为定稿形态**（去过程叙事、去时间线、锚可 grep 唯一名、无行号），不是复制粘贴。
- 清目录前先确认上浮落点已落盘。
- 流程补丁：AGENTS.md Pointers 段收口链补「上浮 / 判不上浮 + 理由」显式步骤；同批扫复述面（店长 prompt 收口段、相关 skills 正文）并回报清单。

## 验收

1. `inventory.md` 覆盖 35 个目录零遗漏（与磁盘逐名对账，附核对清单）。
2. 每条「上浮」点名落点文件；每条「不上浮」有一句理由。
3. 段 3 完成后，`docs/run/` 只剩在飞 + 挂账票目录。
4. 上浮文本过行号锚守卫（`scan.test.js`）。
5. 段 3 走审查链 ✅ 后由店长收口。

## 边界

- 不一刀切：在飞票、挂账票（含 `hook-p3-followups`）不动。
- 不改白名单三目录**既有**内容（新增条目可以；改既有须单独说理由）。
- 检索白名单本身不扩——run 仍不入白名单。本票是搬结论，不是给草稿面开闸。
- 段 1 纯 docs/run 产物走免审；段 3 触非免审面必须走审查链，不借段 1 的免审搭车。
