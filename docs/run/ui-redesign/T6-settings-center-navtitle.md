# T6 · 设置页内容居中 + 导航父标题

> 状态：已派活（flash猫） · 基线 = dev 尖端 `eda4d83b` · web-only · 走 worktree
> 用户原话（2026-09-28）：「你参考 catstudy-ui-redesign-prototype-v6.html 这一版的配置页面，内容要居中。导航栏有父标题也舒服很多。」

## 一、病灶实核（dev `eda4d83b` 源码直读）

T5 把 `.settings-layout` 改为贴左（`margin: 0`）修掉了「轨道与导航之间的大片空白」，但**保留了 `max-width: 1100px` 的整页宽度帽**。后果：

- 整页（导航 148 + 内容区）被钉死在轨道右侧 1100px 内；
- 内容区实宽 ≈ 952px（1100 − 148），720 卡片列在其中居中（`.im-pane/.system-pane/.agent-panel { max-width:720px; margin:0 auto }`）；
- 1920 屏下卡片列中心 x ≈ 52+148+476 = **676px**，而视口几何中心是 960px——视觉重心偏左约 300px，右侧余 ~768px 纯空白（即 T5 审查 OQ-1 挂账的「右余白」，当时裁决：观感不顺则另立票——本条即是）。

「内容居中」的目标形态在原型 v6 里有准确定义（逐行实核原型 CSS）：

```
.set-wrap { flex:1; display:flex }                 ← 全宽，无 max-width 帽
.set-nav  { width:188px; flex:none }               ← 导航贴 wrap 左缘（= 贴轨道）
.set-body { flex:1; align-items:center }           ← 内容区整宽，水平居中其子列
.set-col  { max-width:720px }                      ← 卡片列 720，在剩余区正中
```

另：v6 导航有**父标题**（`.nav-t`：`font-size:11px; font-weight:700; letter-spacing:.08em; color:var(--text-faint); padding:10px 10px 6px`），当前 dev 的 SubNav 无此元素。

## 二、改动规格

**A. 摘整页宽度帽**：`.settings-layout` 移除 `max-width: 1100px`（保留 `flex` / `margin: 0` / 贴左）。导航不动——继续贴轨道左缘。

- 摘帽后 720 卡片列的既有 `margin: 0 auto` 自动在「轨道右缘 → 视口右缘」整宽内居中，**不需要新居中机制**。
- 已知偏移：`.settings-content` 的 `scrollbar-gutter: stable` 让居中偏半个滚动条宽（约 8px）——v6 同形态，接受，代码注释写一句。

**B. SubNav 增可选 `title` prop**（`string`，缺省/空串不渲染）：

- 渲染位置：导航项列表**上方**，独占一行；
- 样式按 v6 `.nav-t` 规格逐字落地（11px / 700 / letter-spacing .08em / `var(--text-faint)` / padding 10px 10px 6px）；
- 设置页传 `title="设置"`；**EvaluationView 本轮不传**（用户诉求范围 = 设置页；prop 可选 ⇒ 评估页零影响零 diff）。

**C. 复述面同批**：

- `.settings-layout` 的 T5 注释段补一句「1100 帽于 T6 摘除（内容居中）」——注释只叙事、不复述旧值字面量（该值有测试否定断言钉着，写进注释会喂假红）；
- 既有钉 `max-width: 1100px` 的静态断言/测试改锚——改锚不改判据意图（见验收 4）。

## 三、边界（不做清单）

- 不改导航项集合 / 顺序 / 图标（猫咪管理 / IM 接入 / 系统配置 原样）；
- 不动 EvaluationView 的导航项与内容；
- 不改 720px 卡片列宽、不改轨道 52px、不动聊天区与 trace 页；
- 不做 v6 式分组 IA（「系统配置组含运行参数/铁律/…」是把卡片拆成独立子页的结构改动，超出本条诉求，见 OQ-1）；
- web-only，server / shared 零改动。

## 四、验收（行为可验）

1. **居中实测**（CDP 或测试环境 1920×1080 视口）：卡片列（`.system-pane` 或任一 pane）`getBoundingClientRect()` 中心 x，与「轨道右缘 → 视口右缘」区间中心 x 之差 ≤ 10px（含 scrollbar-gutter 半宽容差）；导航（SubNav 根元素）左缘 == 轨道右缘（±1px）。
2. **父标题**：设置页导航顶部渲染「设置」父标题；组件测试钉：传 title 渲染 / 不传不渲染（缺省路径）/ 空串不渲染。
3. **1366×768 视口**：无横向滚动条、导航项不折行。
4. **测试改锚纪律**：既有断言只改锚不改判据意图；若存在钉 `1100px` 的否定断言，同步更新并保留「整页居中形态不得回退」的否定语义（锚换成对 `max-width` 帽的否定断言）。
5. **功能零削减**：三个大类 pane 的全部控件/绑定/卡片逐项在位（实施第一步从源码抄录控件清单进交接文档，逐项打勾）。
6. web 全量测试 + `node scripts/lint.js` 三包绿。
7. **真机自证截图 ≥2 张**（1920 系统配置 pane 全景 + 1366 同 pane）附审查请求；探针口径同 T1/T2/T5（worktree 起 5174 vite + 活后端 3200 只读，不碰 3200/5173 写口）。

## 五、OQ

1. **父标题文案 =「设置」是否终版？** v6 的父标题是**分组名**（系统配置组 / 接入组），我们设置页的 IA 是三个平级大类、没有分组结构——取单父标题「设置」作视觉锚。若用户要的是 v6 式分组（拆卡片为子页），那是 IA 改动，另立票，不回本票返工。
2. **EvaluationView 要不要也加父标题（如「评估」）？** 本轮不加（用户未点名）；prop 已就位，确认后一行的事。
