## 二、改动规格

### A. 布局骨架（web）

- **52px 图标轨道**（新增，最左）：logo（34px accent 实底圆角块 + 深色平涂爪印 SVG，原型有成品）→ 💬对话 / ⚙执行追踪 / 📊评估中心 → 底部齿轮（Lucide settings 形态真齿轮 SVG，原型有成品，不用放射线太阳形）。激活态 = 左侧 3px 竖条 + accent-soft 高亮块。
- 会话栏降为第二级（236px，可整栏收起只剩轨道）。
- **主区内容列居中 `max-width: 840px`**（聊天列与输入框同列宽）。
- **三栏头行同高 48px 同一水平线**（会话栏「会话 ＋」/ 主区顶栏 / 右栏「成员 · N」顶端对齐——治「左右侧面板上方空缺」）。
- 色板零新增，沿用现有 CSS 变量。

### B. 气泡 footer（web）

- agent 消息 footer 单行：`[彩色 CLI 徽章] 模型名(mono) · ⏱耗时 · in/out tok`；**时间戳常驻气泡右下角**。
- CLI 徽章配色：claude 橙 / deepseek 蓝（#8fb8e8）/ opencode-go 绿（#9ec7a8），细边胶囊（原型 `.cli` 成品样式）。
- **砍掉累计 token 展示**（`n/m tokens`——右栏成员卡已有，三处重复）；单次 `in/out tok` 保留、不写 "in/out" 字样。
- **hover 操作条**：默认隐藏，hover 气泡浮现，移出即隐。agent 消息 = ⧉复制 / ⚙ trace / ↩回退；用户消息 = ⧉复制 / 撤回（既有）/ ↩回退。
- ⚙ trace 本票只做**展示位 + seam**：点击行为留空挂 `title="trace 页随 T2 落地"`（T2 接线跳页）。不因此阻塞本票。
- 既有元素一个不丢：思考折叠块、工具卡、diff 块、📎记忆行、执行中状态行、停止按钮、回复计时。

### C. 同会话回退（server + web）

- **语义**：任意非 welcome 消息 hover → ↩回退 → 确认弹窗（显示「将删除此消息之后的 N 条消息」+ 红色「不可恢复」警示）→ 确认后删除该消息之后的全部消息，会话从该节点继续（**含该条本身**）。
- **server 新端点**：`POST /api/sessions/:id/rollback { messageId }`——事务内删除目标之后的 messages 行 + 关联 execution_logs 行（FK 口径先实核实写）；若有 running 执行先停再删（沿用撤回机制先例）；广播 socket 事件让各端同步移除。
- 回退点插入分隔线「已回退 · 删除了 N 条消息」（前端渲染态，不落库为新消息类型——若需落库标记，OQ 里裁决）。
- 顶栏**移除清空按钮**；`clearSessionMessages` API 保留作运维口，UI 不再暴露。
- 回退后**剩余**消息的 📎记忆行/角标不受影响（按存活 messageId 关联）。

### D. 顶栏

元素 = 汉堡（收会话栏）/ 会话标题 / 连接状态点 / 主题切换。猫名不进顶栏（成员名单唯一归属右栏）。

## 三、边界（Out of Scope）

- **右栏成员面板零改动**（stat-card / 成员卡 / token 用量 / trace 手风琴 / 会话配置全保持）。
- 输入区功能零改动（📎上传图片必须保留——v3 原型曾误删，用户点名过）。
- trace 查询页本身不做（T2）；设置页不做（T3）。
- 不改广播/调度/记忆任何语义。

## 四、验收（行为可验）

1. 布局：1920 与 1280 宽度下，聊天列水平居中且 max-width 840；会话栏/主区/右栏三条头行 `getBoundingClientRect().top` 相等、高 48px。
2. footer：agent 消息 footer 含彩色 CLI 徽章 + 模型名 + 耗时 + `x/y tok`；右下角时间戳；**无**累计 `n/m tokens`、无 "in/out" 字面量。
3. hover：未 hover 时操作图标不可见（`opacity:0` 或等效）；hover 后出现 ⧉/⚙/↩；用户消息含「撤回」。
4. 回退组装式测试（真实 SQLite + handler）：rollback 后 messages 只剩目标及之前；关联 execution_logs 清理；welcome 作为目标返回 4xx；running 执行先停。
5. 回退 UI：确认弹窗显示正确 N；确认后节点后消息消失 + 分隔线出现；剩余消息记忆行仍渲染。
6. 顶栏无清空按钮；`clearSessionMessages` 源码/API 仍在。
7. 现网功能回归清单（实施前先从现网源码抄录一份「既有功能清单」进交接文档，验收逐项打勾）：上传图片、粘贴图片、@补全、停止、撤回、思考折叠、工具卡、diff 块、记忆行三态、抽屉、广播开关、主题切换、连接状态。
8. `pnpm test` + `pnpm lint` 全绿（worktree 内用 `node node_modules/vitest/vitest.mjs run` 口径）。
9. **真机自证截图**（前端改动附自证是 request-review 前置门槛）：聊天页常态 / hover 态 / 回退弹窗 / 回退后分隔线，四张。

## 五、Open Questions（实施中裁决，逐条答进交接文档）

1. 回退分隔线落不落库？（落库 = 新消息类型/标记列；不落库 = 刷新后分隔线消失。建议：落库为 system role 标记消息，与重启完成消息同族——裁决须写理由）
2. execution_logs 与 messages 的 FK 实际口径（ON DELETE CASCADE 是否存在）——实核后决定显式删还是靠级联。
3. 回退目标消息的「之后」按时序（created_at）还是按会话内序——实核消息排序键。
4. 图标轨道在窄窗口（<1100px）的行为：会话栏自动收起还是保持？（建议自动收起，写明）
