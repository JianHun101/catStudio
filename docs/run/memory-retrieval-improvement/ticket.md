## 二、四件待办（均「先建工单」；实施与否逐条另裁）

### 2.1 启发式跳过门 + 埋点（**第一期，本票主项**）

- **做什么**：对「无可检索主题」的消息**跳过记忆注入**。报告读数：47 条空手 event 里 13 条（28%）属「无主题协调语」；而只要检索跑完就 **100%** 必注入，单次检索 p50 1.3s / p90 2.8s——跳过同时省 token 与省时间。
- **怎么判**（店长 2026-10-13 口径）：**不用模型**。清晰案例（「合」「👍」「继续」「@店长 收口」类）用**确定性规则**判死——长度 / 纯确认词表 / 无问号无实体。零延迟、零成本、可单测。
- **为什么不上模型**：模型路由只在中灰区有价值，而灰区判错的代价是**该检索时没检索**（漏比多危险）。且这正是已裁过的分期——第一期启发式 + 埋点，LLM 仲裁留第二期。
- **埋点是第二期的唯一判据**：先用真实数据量出灰区到底多大。若埋点显示启发式准确率已 95%+，第二期永远不用做；若灰区真大，那时再上小模型路由，训练 / 评估数据就是第一期埋点攒出来的。**跳过埋点直接上路由 = 在没量化问题规模前先付了方案成本。**
- **与 2.3 的关系**：2.3 的两处埋点是「让归因可复算」，本条埋点是「让跳过门可评估」——两件事，别合并成一个字段了事。

## 三、clowder-ai 对照（外部勘察，2026-10-13）

用户 2026-10-13 问「clowder-ai 怎么解决检索到无关内容」，勘结论作为**对照材料**记此，供 2.1 实施时参照：

- **它没有意图路由层**——「检索前用轻量模型判断要不要检索」在它仓里不存在。防无关靠四层机制，**没有一层是 LLM 判断**：
  1. **场景门槛（默认不检索）**：普通会话的温热路径完全不做证据检索，只有「冷提及」（未读 > 15 条或累计 > 10K token）才触发自动召回。日常短对话零检索。
  2. **主检索是猫自己拉（pull）**：agent 经 MCP 工具自主决定何时检索，系统提示只放工具指引、不自动注入——从根上消掉「要不要检索」这道判断题。
  3. **FTS 词匹配做硬门槛**：词不命中即无结果，命中为空就**不生成注入块**；它甚至**没有距离阈值**（rerank 只调序不淘汰），靠「无命中 = 无注入」兜底。
  4. **注入预算最先牺牲证据**：超预算时证据行第一个被丢，注入上限 3 条。
- **对本仓的启示（只记不裁）**：它的三件套——**默认不检索 / pull 优先 / 空命中不注入**——没有一件需要模型路由。本仓已有 `search_knowledge` 工具，若长期方向是「猫自主拉取 + 自动注入只做高置信场景」，则「加一层判断」这个中间层可能被架构演化整个消化掉。这条路**改动面大，不宜现在动**，登记备查。
