## 一、要解决的问题

M1 底部行只有**分母**（注入了哪几节），看不出**分子**（哪几节被用上）。R14a 已实测证明「猫会标、且跨 provider 稳」（60 次真实调用：标对 54 / 标错号 0 / 越界号真值 0 / 不标 6）。本票把角标接进生产链：生成时猫写 `[n]` → 后端读口映射 → 前端渲染角标 + hover 卡片。

## 二、三段接线（设计已定，逐段的「为什么」见 R14a §十结论与 R14 §六）

### ① 生成侧：指示语进注入串（server，唯一的行为变更）

- 落点：`renderSections`（`packages/server/src/memory/index.ts` 定义处）。**必须落在函数内部、不能落在调用方**——该函数同时服务预算试渲染（`renderSections([...kept, section])` 调用处）与最终注入，两处同源才能保证 token 核算与实际注入逐字节一致（函数既有注释即此契约）
- 措辞 = **甲版逐字**（R14a 实测过的自变量，一字不动）：

  `（以下为检索到的历史结论。若你采纳了其中某条，请在该处标注其编号，如 [1]；没有采纳的条目不标。）`

- 位置：`【相关记忆】` 头之后、`1.` 之前，独占一行——与探针注入串同形（探针测试夹具 `VARIANTS.jia` 的插入位）
- 零节时函数返回空串的既有行为不变（无头、无指示语）
- a2a 跳过【相关记忆】时整块不出现，指示语随之不出现——天然一致，不做特判

### ② 映射侧：解析放读口，不落库（server）

- **新增纯函数** `extractCitationMarkers(replyText, sectionCount)`（建议落 `packages/server/src/memory/citationMarkers.ts`），判据**按机制不按模式**（R14a 同款口径）：
  - 散文中的合法号（`1..sectionCount`）→ `markers`（去重、升序）
  - 越界号（`> sectionCount` 或 `< 1`）→ **不进 markers、不报错、不做最近邻猜测**（R14 §六-2 既定口径；R14a 实测越界号真值 = 0，此条是**纯防御**——防映射边界错，不是防猫）
  - **代码字面量内**的号（围栏块 + 内联码两种形态）→ 不进 `markers`，进 `markersInCode`——**成列可见，不许静默剔除**（哪天猫把真引用写进反引号，要能被看见）
  - 缩进代码块形态**不处理**（探针语料 90 份零命中 + 前端按 AST 渲染天然豁免），写进已知限制
- **出口 = M1 既有批量口**：`GET /api/sessions/:id/memory-refs` 的 entry 增加两列——`markers: number[]` 与 `markersInCode: number[]`（`state='injected'` 之外恒为空数组）。**additive 变更，不改既有字段、不新建端点、不改 shared Message 类型**
- **映射契约**：`[n]` ↔ `refs` 中 `injectedPosition === n` 的那节（**按位置值匹配，不按数组下标**）——编号唯一真相源是 `renderOrder`，流水与渲染同取它，M1 读口已按此排序
- **不落库**：判据面是会改的（R14a 期间就改过一次），`reply` 是已落盘证据、解析是派生数据；落库 = 把判据固化成第二真相源（R14a 验收 9 刚换来的教训）

### ③ 渲染侧：角标 + hover 卡片（web）

- 角标：消息正文（markdown 渲染面）中 `n ∈ markers` 的 `[n]` 渲染为上标角标；`n ∉ markers`（越界 / 未注入位置）保持字面文本
- **代码豁免在 AST 层天然成立**：`renderMarkdown`（`packages/web/src/utils/markdown.ts`）走 marked，围栏块 / 内联码是独立 token 类型，自定义 inline tokenizer 不会被调用——**这就是「代码块内 `[1]` 不渲染」的实现机制**，组件测试须对此有断言
- hover 卡片内容 = 该节**标题（breadcrumb / sectionAnchor）+ 正文开头（bodyHead）**——数据全在 memory-refs 既有响应里，**不许加新端点、不许为此发新请求**
- markers 按消息传入 `renderMarkdown`（新可选参数）；思考块等无 markers 的调用点传默认值，`[n]` 保持字面
- **底部 M1 行保留**（本票决策留痕 D2）——角标只是分子的下界（R14a：「不标」约 10%）

## 四、边界（越界即返工）

- 不改检索 / 排序 / `renderOrder` / `injected_position` 语义；不动 M1 底部行的任何逻辑
- `markers` / `markersInCode` **不落库**（读口派生）
- **不做复读剔除**（猫转述指示语字面量产生的 `[1]` v1 不识别）——挂观察项：真机若见复读污染分子，再立票。理由：生产面是逐条 hover 展示而非聚合统计，误标代价是一张错的卡片；探针的 echo 判据服务的是离线读数，两者精度需求不同
- 不碰【知识库】区块（角标本票只管【相关记忆】）；不改探针 e2e 脚本本体（只允许更新其测试的守卫期望）
- 不改 `MEMORY_*` 环境变量

## 五、验收标准（行为可验）

1. **注入串新形状**：`renderSections` 输出 = `\n\n【相关记忆】\n<甲版指示语逐字>\n1. …`；单测断言指示语**逐字**（改一字即红）；零节输入仍返回空串
2. **token 同源**：预算试渲染与实际注入同一函数 ⇒ 指示语自动进 token 核算；判据 = `memory/index.test.ts` 既有预算类用例在新形状下复跑全绿（不许靠放宽阈值转绿）
3. **复述面清扫**：§三 三处同批更新；probe 守卫对新形状绿、改回旧形状红（反对照自证）
4. **解析纯函数**单测：混标（`[1][7]`，3 节 ⇒ `markers=[1]`）/ 仅越界（`[7]` ⇒ 空）/ 仅代码内（围栏 + 内联码各一例 ⇒ `markers` 空、`markersInCode` 有值）/ 空文本 / `sectionCount=0`（任何号都越界）
5. **读口契约**（组装式测试，`routes/memory.test.ts` 范式，真 DB）：回复含 `[2]` 且注入 3 节 ⇒ entry `markers=[2]`；回复含 `[7]` ⇒ `markers=[]`；回复无号 ⇒ `markers=[]`；既有用例（三态 / 跨会话 400 / 超 200 条 400）不破
6. **前端三态**（组件测试，`ChatPanel.test.ts` / markdown util 测试范式）：markers 内的 `[n]` 渲染为角标元素（断言标签/class）；markers 外的 `[n]` 保持字面；围栏块与内联码内的 `[n]` 保持字面（不包角标元素）
7. **hover 卡片**：内容 = 对应 ref 的标题 + 正文开头；组件测试或静态源断言证明**无新网络请求**（数据源 = 既有 `memoryRefsByMessage`）
8. **回归**：`pnpm test` + `pnpm lint` 全绿（环境注入变量按既有口径剥，遇假红先剥变量重跑，勿 `--no-verify` 类绕过）
