## 二、独立变量：指示语措辞（**店长定稿，实施者不自拟**）

遵循度是**措辞的函数**——自拟一版测出的数，对定稿版零信息量。故措辞由店长给，甲/乙两版对照：

- **甲版**：`（以下为检索到的历史结论。若你采纳了其中某条，请在该处标注其编号，如 [1]；没有采纳的条目不标。）`
- **乙版**：`（采纳某条时标注其编号，如 [1]。）`

⚠️ 两版都**不作位置要求**（句末 / 词后皆可）——位置本身是待观察量，**别在指示语里加成第二个自变量**。

## 三、依赖变量：**三分判据，不许并成一个「遵循率」**

| 失效模式   | 含义                             | 修法方向                              |
| ---------- | -------------------------------- | ------------------------------------- |
| 不标       | 用了某节但一个号都没写           | 改措辞 / 加强指示                     |
| 标错号     | 标了 `[2]` 但内容其实来自第 3 节 | 改指示里对「编号↔内容」对应关系的描述 |
| 标不存在号 | 只注入 3 节却写 `[4]`            | 后端降级（R14b），**非措辞问题**      |

**并成一个比率会分不清「不会标」和「标错」——而这两者修法相反。**

## 四、探针形态（**店长裁决**）

**不新建离线调用链。** 复用现成的 adapter 工厂（`packages/server/src/llm/registry.ts`），探针只做**调用方**：

- 落点 `scripts/probes/r14a-citation-probe.e2e.mjs`（同目录已有 `dsh-acp-probe.e2e.mjs` 同范式）
- `.e2e.mjs` **不在** vitest include ⇒ 天然隔离、不进 CI
- 理由：新建一条独立调用链 = 又造一个可能与生产不一致的真相源（「离线跑通、线上不通」）；adapter 工厂是现成的，探针没有理由自建

⚠️ **注入串必须与生产同形**——形状规格（逐字取自 `renderSections`）：`【相关记忆】` 头 + 换行 + 逐行 `序号. 正文`：

```
\n\n【相关记忆】\n1. <第1节正文>\n2. <第2节正文>\n3. <第3节正文>
```

指示语插在 `【相关记忆】` 头之后、`1.` 之前。**探针不许自拟记忆段格式。**

⚠️ **判据面**（否则读数被假阳性污染）。三条**按机制定义，不按模式定义**：

- **代码字面量内的 `[n]` 不计入**——判据名是**机制**（「这是代码，不是引用」），不是模式名。
  - **理由**：`[512]` 是 sqlite-vec 的列类型 `float[512]`，猫在**引用注入原文**；把它当角标 = 判据面把代码字面量读成了引用
  - **本语料实测的形态**（店长扫 S1 30 份 + S2 60 份）：**两种**——围栏块（` ``` `）+ 内联码（`` ` ``）；**缩进代码块（4 空格 / tab）零命中**。⇒ 实现按两种，但见下条
  - ⚠️ **实施者须自己重扫一遍**，不许照抄上式：形态清单是**本批语料**的读数，换语料即失效。**假设要标红 + 实测对称**——若扫到第三种形态，同属该机制、同批纳入
- **`markersInCode` 必须成列可见，不许静默剔除**——与 `markersInFence` / `markersInEcho` 同形。本批真值为 0，但**若哪天猫把真引用写进反引号**（`` `[1]` ``），那与 `float[512]` **不同源**，必须能被看见。静默剔除 = 又一支「判据面把真值扫掉」的假绿
- **猫复读指示语 ≠ 标了**：甲版指示语**自身含字面量 `[1]`**，猫转述/解释该指示语时会产生 `[1]`。故判据须取「正文里指向某节内容的标注」，复述指示语那一处要能识别并剔除

### S2 分片跑法（**店长裁决·补充**）

S2 首跑**中断于 30/60**（`claude` 14 / `dsh` 15 / `opencode` 1 / `ollama` 0）。**店长实测判定它不是「在途」而是已死**：全机 8 个 `node.exe` 进程均为生产栈（`dev.js` / tsx server / `embed-server` / `vite` / `cli-supervisor` / `mcp-server`），**无一为探针**；stderr 冻在 `18:53:55` 再无新行。根因是 `--out` 的 JSON **只在全部跑完时才写** ⇒ 进程一死，**30 次调用的读数全部损失**——这是「长任务必须脱离工具调用进程树」那条教训的复发。

**改按 provider 分片**（探针已有 `--provider` + `--out`，s2 模式确实消费 `args.provider` ⇒ **零代码改动**）：

```
node scripts/probes/r14a-citation-probe.e2e.mjs --mode s2 --winner jia \
  --provider <claude|opencode|dsh|ollama> \
  --out docs/eval/r14a-citation-probe-2026-09-23-s2-<provider>.json
```

- 每片 **15 次调用**，须在**一轮之内装完**（进程随轮结束被回收，跨轮的「在途」不存在）
- `claude` / `dsh` / `opencode` 三片可并作一轮；**`ollama` 那片单独一轮**（~79s/次 × 15 是最大片）
- 某片失败**只重跑该片**，不牵连其余

## 七、问题集（实施者从 dev 库挑，判据如下）

3 个问题，每题必须满足：

- 答案**只在索引文档里**（`docs/adr` `docs/lessons` `docs/plans` 白名单切片）——答得出才可能引用
- **非 a2a**（普通用户提问）——a2a 触发时【相关记忆】整体跳过（见 `shouldSkipA2aMemory`），走不到本探针要测的那条路
- **每题必须带答案锚点 `expectSection`（1..n）**：出题时钉死「本题答案出自注入的第几节」，且该题**只有一个**承载节

**为什么 `expectSection` 是必需项（不是可选项）**：§三 三格里的「标错号」——「标了 `[2]` 但内容其实来自第 3 节」——**正则算不出来**，它要的是内容与节的对应关系。没有答案锚点，§八 验收 1 里那一格**只能编**。

出题时把「问题原文 / 本次注入的三个节原文 / `expectSection`」一并落进报告，人工可复核。

## 八、验收标准

1. 报告给出 4 provider × 三分判据的**原始计数**（含分母），非仅比率。四格归类口径**按此实施，不自拟**：
   - **标对** = 合法号集合含 `expectSection`（§七 答案锚点）
   - **标错号** = 标了合法号，但**不含** `expectSection`
   - **标不存在号** = 出现 `> 节数` 或 `< 1` 的号——**单列，不计入「标错号」**（那是 R14b 的后端降级面，不是措辞问题）
   - **不标** = 一个号都没出现
   - 四格**各自成列**；原始 `markers` 必须原样列出——混标（既有合法号又有越界号）时不得互相掩盖
   - ⚠️ **入判据的号 = 正文散文里的号**：代码字面量内（围栏 + 内联码）不计入任何一格，**但必须成列可见**（`markersInCode`，见 §四）。本批真值 = 0（那 2 处 `[512]` 是 sqlite-vec 列类型，见 §六「S2 实测」）
2. 甲/乙两版**同条件对照**（同问题集、同 provider、同 N）
3. 不可达 provider 显式标「未测」+ 原因
4. 探针产出的注入串与 §四形状规格**逐字一致**（建议加静态源断言守卫：格式规格 `renderSections` 一变即红）
5. 结论只答「措辞能不能用 / 哪版更好」，**不预写 R14b 的接入结论**
6. **探针自身非退化**（**新增·承重**）：形状漂移必须**报错**，不许静默返回 0。判据——迭代中「见到 chunk、但无一条带可识别 `content` 字段」⇒ 单列 `shape-mismatch` 状态，**不得**并入「done 但无文本」（后者是本仓实测过的真实形态；两者混同 = 拿假读数当结论）。**仅写注释不算**——本轮已踩一次（`chunk.text` vs `Chunk.content`，四只同形假读数）
7. **原始读数落 `docs/eval/` 持久 JSON**（`--out docs/eval/r14a-citation-probe-<date>.json`）——对齐本批刚落的口径：引「实测」数必须锚**仓库内持久产物**，scratch 工作区只作过程证据
8. **S2 按 provider 分片落盘，且合并产物齐全**（见 §六「S2 分片跑法」）：
   - 每片一个 `docs/eval/r14a-citation-probe-2026-09-23-s2-<provider>.json`，**分片文件保留**（它们是原始证据）
   - 另落一份合并产物 `docs/eval/r14a-citation-probe-2026-09-23-s2.json`：`runs` 为四片拼接，`summary` **重算**（不手抄分片汇总）
   - 合并可新增小脚本 `scripts/probes/r14a-citation-probe.merge.mjs`（同目录、`.mjs`）——**手敲一行命令的合并不可复现**，落脚本才算
   - 报告里的分母必须写**实际跑满的 provider 数**；某片缺失即标「未测 + 原因」，**不得**用别的 provider 顶替，**不得**悄悄改 N
9. **判据面可重算（**新增·承重**）**：新增 `--mode reclassify --in <artifact> --out <artifact>`——读入已有产物的 `runs`，**复用同一个 `extractMarkers` / `classifyReply`** 重算派生字段并重出 `summary`。
   - **为什么要它**：判据面是**会改的**（本轮就改了），而 `reply` 是**已落盘的证据**。判据面一变就重跑 = 每次都用一次新的 LLM 抽样去回答一个原样本已经答过的问题——**证据被换掉，还花了钱**

### OQ-5（2026-09-23 店长仲裁落：prep 连败两轮的墙不在内容面）

**现象**：`275a5b33` 相对审查分支 `b54d67c1` 是**快进**（`merge-base --is-ancestor` 实测通过、`merge-tree --write-tree` 结果树 = `275a5b33` 的树），但 review-view prep 在 19:39:54 / 19:46:00 两次失败，日志 `files: []` / `recovered: false`。

**真因（店长独立复现，非转述）**：审查者 worktree 的**暂存面**压着 16 个未提交的 R13a scratch 文件。`git merge --no-ff` 遇到「索引里有、HEAD 里没有」的路径会**直接拒合**——临时仓实测：`error: Your local changes to the following files would be overwritten by merge`，`exit=2`；紧接着 `git merge --abort` 因无 `MERGE_HEAD` 再抛一次（`There is no merge to abort`）。三个签名逐条对上日志：`exit≠0` → 进 catch、`unmergedFiles()` 空 → `files: []`、abort 抛错 → `recovered: false`。**正对照**：同一临时仓 `git reset` 后原样重跑，`Merge made by the 'ort' strategy`，`exit=0`。

**已执行（店长兜底接管）**：对审查者 worktree 执行 `git reset`（**仅移出索引、不删文件**）——16 个文件逐一核过**全部保留在盘上、内容未动**，reviewer HEAD 未动（仍是 `b54d67c1`）。选这条而非「叫审查者自己清」：索引位移**不丢任何信息**（重新 `git add` 即还原），且 ds猫 侧本无可对齐的内容，等一轮只是空转。

**两条挂账（建议立票，票面由店长补）**：

1. **诊断盲区**：`worktree-fanin.ts` 的 `runGit` 用 `stdio: ['ignore','pipe','ignore']` ⇒ **git 的 stderr 被丢弃**，日志里的 `error` 永远只有命令行，真实报错（`would be overwritten by merge`）进不了任何日志。本轮真因只能靠隔离复现反推，不能直读。
2. **误分类 + 误路由**：任何 `merge --no-ff` 失败都被记成 `merge conflict`，冲突返投也**一律投给 src 侧**。而本例的墙在 **target 侧**（审查者自己的暂存面），src 侧没有可对齐的内容——ds猫 因此空转两轮。判据应改成：**只有 `unmergedFiles()` 非空才叫 conflict**；为空则另立一类（target 侧阻塞，附 stderr 摘录 + 阻塞路径），**投给 target 侧**。
