## 二、三臂定义（同一库快照 + 同一冻结黄金集 `docs/eval/retrieval-golden.json`）

- **臂①** 现状：topK=3 + RRF 序
- **臂②** 最便宜替代：topK=5 + RRF 序（一行配置）
- **臂③** 本票主体：topK=3 + cross-encoder 重排（只改序、不改成员）

判据（写进报告，不许只给绝对恢复数）：

- 臂③ ≥ 臂② ⇒ **有效**
- 臂③ ≈ 臂② 且注入量明显更少 ⇒ **「等价但更省注入」**，这是可写的收益，不是零
- 臂③ = 臂① 或 < 臂② ⇒ **据实关票**，结论写「瓶颈在池的成员，不在序」

⚠️ **臂② 没有 CLI 旋钮**：`retrieval-baseline.mjs` 的 CLI 只有 `--root/--db/--env/--date/--out`（见 `main()` 里 `bootstrap(process.argv.slice(2))` 的参数解析），topK 由 `MEMORY_TOP_K` 决定 ⇒ 走 `--env <临时 .env>` 面注入，**不要改脚本加旋钮**（那会把跑批工具变成被测对象）。

### S0 实测结论（2026-09-22 回填 · 停损点**未触发**）

> ① ② ③ ④ 为 R13a 实施者实测回报；③ 的前提另经店长按缓存产物复核（见下）。

| 项           | 结论                                                                                                                                              |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| ① 权重可得性 | ✅ `Xenova/bge-reranker-base` 200，ONNX 八变体。q8 实下 **279,301,077 B**（与 API 报的体积逐字节相等）。档位：fp32 1061MB / fp16 531MB / q8 266MB |
| ② tokenizer  | ✅ `model_max_length=512`；真实对（40 字 query × 450 字 passage）= 373 token，不截断                                                              |
| ③ pipeline   | ❌ **票面给的两个候选都不是可用路径**（详见下）                                                                                                   |
| ④ 延迟曲线   | q8 安静机、预热后 3 轮取优：per-pair 稳定 **45–49ms**，**批处理无收益**（CPU 绑定，N=1→80 单对耗时几乎不变）；N=80 → **3955ms**                   |

**③ 是本票 S0 最大的价值，必须固化——它防的是一次「假关票」：**

- `text-ranking` **不是** v4.2.0 的合法任务（完整任务表 25 项无它）。模型卡上的 `pipeline_tag: text-ranking` 是 **hub 侧标签**，与 transformers.js 的任务表不是同一回事。
- `text-classification` **不可用**：该模型 `config.problem_type` 为 `null` ⇒ `TextClassificationPipeline` 走 softmax 分支 ⇒ `softmax([x]) ≡ 1` ⇒ **恒返回 `score: 1`**，相关/不相关**不可分**；且其 `_call` 不把 `text_pair` 转发给 tokenizer，喂对象得到退化编码（两条输入同一分）。v4.2.0 **没有** `function_to_apply` 选项可传（dist 里它只是局部变量）。
- **前提已复核**（店长按缓存产物 `config.json` 实读）：`architectures = ["XLMRobertaForSequenceClassification"]`、`id2label = {"0": "LABEL_0"}` 仅一项、**无 `problem_type` 字段** ⇒ 与上述根因链吻合。transformers.js 侧的分支行为未复跑。
- ✅ **可用路径（第三条，本票冻结）**：`AutoModelForSequenceClassification` 直接加载 + **显式 sigmoid**。实测可分：相关 **0.9979** / 不相关 **0.0000889**。

> 若按票面原字面用 `text-classification`，会拿到**恒定重排分 ⇒ 顺序不变 ⇒ 臂③ ≡ 臂①** ⇒ 报告得出「重排无效」⇒ **票被关错**，而所有探针都显示「跑通了」。A5 因此加非退化断言。

**备选 `Xenova/bge-reranker-v2-m3` 不可得**：镜像回 401。**401 的定性靠反对照**——该镜像不用 404，确定不存在的仓库名回同一个 401，而真仓库当场代理 200 ⇒ **401 = 仓库不存在**，不是「需鉴权」。上游 `huggingface.co` 本环境整体不可达（三个对照一致失败）。未实测备胎 = `Xenova/bge-reranker-large`（200, onnx=9）。

**dtype 冻结为 q8**（266MB）：离线跑批与生产（R13b）**必须同 dtype**，否则离线读数不可迁移；若 R13b 改 fp16，本票读数作废重跑。

## 五、S2′：离线跑批（**关键边界——不改生产链路**）

- `packages/server/src/memory/index.ts` 的 `takenSections` 循环、`runRetrievalChain`、`reply.ts` 的记忆注入段：**本票一行不改**。
- 做法：在**跑批侧**重建 `ranked` 全序（`scripts/eval/retrieval-attribution-recheck.mjs` 的重建侧已有同源代码，T5 已把它修成跟生产走——**优先复用，别另写一份**），对全序调 sidecar `/v1/rerank`，重排后取 topK=3，算 recall。
- **配对规则**（合并时一片可能被多趟查询命中）：取 **argmax 贡献趟**——即哪趟给该片贡献的 `rrfScore` 最大就用哪趟与它配对。现内存态只有「首趟命中」的 `queryIndex`，**需在重建侧自行记录贡献趟**（重建侧可自由加字段，因为不改生产）。
- **不截池**：全序一条不砍送打分。截池会让 `finalRank=44` 那类锚点永远救不回，与 R13 立项理由直接冲突。
- ⚠️ 跑批脚本的重建侧若与 `index.ts` 有分叉，**以 `index.ts` 为准**，并把分叉点写进报告。

## 六、验收标准（可证伪，逐条要读数）

- **A1｜三臂读数表**：11 处未召回锚点的**逐条 before/after 名次**，三臂各自 recall；臂③ 相对臂② 的增量单独列出。
- **A2｜负例不劣化（承重）**：negative 组 5 条判红数**不得上升**（现制 4/5，A2 防"召回暴涨稀释精度"）。
- **A3｜延迟（必给读数）** —— **2026-09-22 改口径，取代原「超时率不高于 0.86%」硬条款**：
  - 重排段自身的耗时分布（p50 / p95），以及**加到检索总耗时后的**预计 p50 / p95
  - **① 分母剔除永不检索的行**：`reason=skipped-a2a` 的行 `retrieval_ms` **恒为 0**（a2a 门在检索前短路），永不可能 timeout ⇒ 计入分母属稀释。真分母 = 全部 − skipped-a2a，基线随之重算。店长实读初值 8/846 = **0.945%**（原 8/928 = 0.86%）。**实施者独立复核，不采信此数。**
  - **② 超时率不再作跑批判据，改为结构性条款**：「重排必须在闸内**子预算**内完成，超预算即退回 RRF 原序（**非空返**）」。有这条，重排在结构上**不可能**把一条 `ok` 推成 `timeout`——它只能选择「不做」。此条属 **R13b 实现约束**，R13a 只给推演、不判过否。
  - **③ 改报「降级率」**：给定子预算，多少比例的检索会跳过重排。这是该特性的**真实覆盖率**、也是诚实的收益折损读数。店长实读初值 **1/836 = 0.12%**，且对 **N ≤ 92** 不敏感（耗时分布有断崖：9836ms 之后直接掉到 5240ms；N=93 起才升到 2/836，而设计上限仅 80）。**实施者独立复核。**
  - **④ 撤回「p95 绝对值 ≤ 5s」**：它与 §五「不截池」数学上冲突（N=80 推演 p95 ≈ 7161ms），且 p95 是**重排前**检索本身的分位数，加进重排后阈值含义已变。改为**报实测分布**，不拍阈值。
  - ⚠️ 现网尾部**贴着 10s 闸**（`ok` 里最慢 9836ms，距闸 164ms；次慢仅 5240ms）。报告必须给这条推演，不许只报「平均没变慢」。
- **A4｜确定性**：同输入连跑两遍，跑批 json 与 md **各自 sha256 全等**（B1 已确立，重排不得引入随机性）。
- **A5｜尺子自证不破（承重）**：跑批 canary（必中 + 必不中条钉在同一锚点）仍 ✅；两条不符即拒出报告的行为不变。
  - **追加非退化断言（S0 教训固化）**：canary 必须断言重排分**不是常数**——已知相关对 > 0.5、已知不相关对 < 0.5，且**两者不相等**。缺此断言，`softmax([单logit]) ≡ 1` 那类退化会让臂③ ≡ 臂①、得出「重排无效」的**假读数**（S0 实测，见 §三）。
- **A6｜回归**：`pnpm test` 全绿；`pnpm lint` 过。
- **A7｜诊断脚本自证**：主动跑一次 `retrieval-attribution-recheck.mjs`，确认其承重自证未被打断（T4 有前科）；断了就**另立票**，别静默放过。
