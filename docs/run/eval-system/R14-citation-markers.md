# R14 票：角标引用（**行为变更**·在飞 2026-09-23）

> 来源：用户 2026-09-23 原话——「我要的是生成时输出 [1][2]，后端映射到网页，前端渲染角标。鼠标挪到角标上展示卡片，对应内容为标题及部分开头内容」。
> 前置：**M1 记忆索引**（已上线，已审 sha `bdee856c` → PR #173 → dev `aa2541ba`）。
> ⚠️ **本票改行为**——改的是**猫实际读到的 system prompt**（新增一句引用指示语），与 R13 同性质。审查重心在读数，不在代码形状。
> 行号基线：`dev@4c2de1b7`。**实施者落笔前按自己那棵树重取一遍。**

## 一、要解决的问题

M1 上线后，回复底部那行显示「这次注入了哪几节」。但它只有**分母**：注入了 3 节，这 3 节到底有没有被用上，看不出来。

**「检索白做」（注入了、一句没引）与「检索有用」在 M1 的读数里长得一模一样。**

本票要补**分子**：让猫在生成时标出它引用了哪几节。

## 二、用户要的形态（原话拆解）

| 环节 | 原话                             | 落点                       |
| ---- | -------------------------------- | -------------------------- |
| 生成 | 「生成时输出 [1][2]」            | 猫在回复正文里写 `[n]`     |
| 映射 | 「后端映射到网页」               | `[n]` → 第 n 节            |
| 渲染 | 「前端渲染角标」                 | `[n]` 变角标，hover 出卡片 |
| 卡片 | 「对应内容为标题及部分开头内容」 | 节的标题 + 正文开头        |

## 三、接线面勘察（**已核，非推测**）

**编号链是现成的，不用新建**：

- `renderSections` 把注入节渲染成 `1. <正文>` `2. <正文>` …，序号按**最终位置**编（源码注释：「猫读到的是连续 1..n」）
- `renderOrder` 是这套编号的**唯一真相源**——`renderSections` 与检索流水的 `injectedPosition` **都取它**（源码注释点明：分开写两份的话，流水会静默记下与猫实际读到的位置不符的编号）
- 检索流水 `retrieval_events.injected_position` 存的即此编号
- M1 的 `memory-refs` 端点按 `injected_position` 排序返回 refs

⇒ **映射链：猫写 `[2]` → `refs[2-1]` → 标题 + 正文开头。数据源现成。**

## 四、缺的三件

1. **指示语**——告诉猫「引用某节时标 `[n]`」。**唯一有风险的环节**：不同 provider 的猫遵循度不一样——可能不标、标错号、或标出并不存在的号
2. **后端解析** `[n]` + **越界降级**（猫写 `[7]` 而只注入 3 节 ⇒ 保留纯文本，不做角标）
3. **前端渲染** + hover 卡片 + **代码块豁免**（代码块里的 `[1]` 不渲染成角标）

## 五、拆分

- **R14a**（[角标引用遵循度离线探针](R14a-citation-marker-probe.md)，**不碰生产链**）——先答「猫到底会不会标」。
- **R14b**（接入生产链，**押后**）——指示语进 prompt + 解析 + 渲染。**前置：R14a 读数证明值得接。**

**为什么先探针**：与 R13a 同款打法——先离线证、再接入。遵循度是**措辞的函数**，措辞没定就先建前端，等于拿没验过的自变量去接线。若探针显示猫根本不标（或标得离谱），R14b 整段不必开工，省掉三处改动（prompt / 后端 / 前端）。

## 六、两个待定（**不阻塞 R14a**）

- **底部那行（M1 的）留不留**——店长倾向**留**：底部行 = **分母**（注入了哪几节），角标 = **分子**（哪几节被引）。只留角标则「检索了 3 节、一句没引」彻底不可见，而那恰是「检索白做」的证据，也正是本需求立项时要判断的「使用率与真实性」。**已问用户，待裁。**
- **越界号降级口径**——店长口径：**保留纯文本、不渲染角标、不做「最近邻」猜测**（猜错比不显示更坏）。
