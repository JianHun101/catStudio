### ⚠️ 对派活单估算的订正

店长原估：「把 `injected=1` 的落全文，净增 **≈ 0.6MB**」。实核：

- **0.6 是字符不是字节**——`injected` 行的字符增量正是 **646,239（≈0.65M 字符）**，
  但中文在 SQLite 里是 UTF-8，1 字符 ≈ 3 字节 ⇒ 同级字节增量是 **1.26 MB**。
- 派活单的改动面**不止 injected 行**：验收① 要求「新落库的行逐条相等」，`probe` 行
  同样走这一列 ⇒ 全部候选行都要落全文，字节增量 **3.65 MB**（历史面）。

**两个口径都给出，取舍归店长**：若只想付 injected 面的代价（+1.26 MB），需要把
`probe` 行单独截断——但那会重新引入「同一列按 `source` 语义不同」的分叉，
**我判不取**；若两个数都可接受（3.65 MB 相对 526 MB 的活库是 0.7%），维持现制。
