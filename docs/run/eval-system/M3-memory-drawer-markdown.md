# M3 记忆抽屉内容 MD 化

## 一、背景与根因

M1 的「📎 记忆」抽屉里两处内容区用 `<pre>` 纯文本直出（`packages/web/src/components/ChatPanel.vue`：命中片段 `bodyHead` 一处、当前文档 `docPreview.content` 一处），markdown 源（标题 / 列表 / 代码块）按字面字符显示。用户 2026-09-27 要求兼容 md 格式。

hover 卡片（`bodyHead` 开头片段）**不改**，保持纯文本预览——用户裁决单「1 派」未含此项。

## 二、裁决（已定）

渲染层替换：两处 `<pre>` → `v-html="renderMarkdown(...)"`，复用正文气泡同款管线（marked + DOMPurify，安全面不重审）。**纯渲染层改动**，不碰 useApi / 读口 / 数据形态。

三条注意点（写进验收）：

1. **切片可能切在围栏代码块中间**（chunk 按节切，跨节围栏得到不闭合的 ```）——marked 宽容降级成段落是可接受行为，测试钉一例「不闭合围栏不炸、不泄漏原始 HTML」。
2. **文案纪律不动**：`useApi.ts` 头注的「bodyHead 是命中片 ≠ 猫当时读到的整节」语义、抽屉里「打开的是当前检出，不是当时快照」的提示文字必须原样保留——MD 化只是渲染层。
3. **抽屉内 markdown 罩局部样式**（标题字号、代码块、表格、列表间距），不裸继承正文气泡尺寸。

## 三、边界

- 只动 `packages/web/`（ChatPanel.vue 抽屉两处 + 样式 + 组件测试）；server / shared 零改动。
- hover 卡片的 `bodyHead` 保持纯文本，不 MD 化。
- 不改 `renderMarkdown` 的签名与既有行为；抽屉调用不传 markers（角标面不动）。
- 不加新依赖、不加新端点。

## 四、验收（行为可验）

1. **承重组件测试**：抽屉打开后，命中片段区与当前文档区的渲染产物是 HTML（夹具内容含 `# 标题` / `- 列表` / `**粗体**`，断言 DOM 出现 `h1` / `li` / `strong`），不再是纯文本字面量。
2. **不闭合围栏**：夹具内容为跨节切剩的未闭合 ``` 围栏 → 渲染不抛错、不输出未转义的原始 HTML 标签字面量。
3. **安全面**：夹具内容含 `<script>` / `onerror` → 渲染产物中被剥离（DOMPurify 路径实测，非假设）。
4. **文案保留**：两条纪律提示文案在抽屉 DOM 中逐字在场（静态断言或组件断言）。
5. **真空性反对照**：临时把两处 `v-html` 改回 `<pre>` 纯文本，验收 1 的承重断言必须红；红后还原。
6. `pnpm test` + `pnpm lint` 全绿（环境注入变量按既有口径剥）。

## 五、真机验收（收口后，店长执行）

vite 热更生效后硬刷新，打开任意一条带引用的回复的记忆抽屉：标题 / 列表按 md 渲染，提示文案在场。**web-only，无需重启审批。**
