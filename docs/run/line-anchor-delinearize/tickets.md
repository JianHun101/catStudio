## 一、立票理由

上一票（refs 层收敛）收口时，审查猫在 `docs/adr/0014-skill-delivery-decoupling.md:54` 抓出一处假锚：修订注写的

两件事让这不能只按「改一个数字」处理：

1. **该锚落在 `docs/adr/**`，而 `docs/adr|lessons|plans` 是记忆扫描白名单**（`scripts/flywheel/scan.mjs:60`

2. 上一次的处置已经是去行号化（锚到字面量「唯一审查触发」）而非校准到 `:120`——但那是**单点**。用户指令要求
   **扩面 + 防复发**，故本票做全量实测、立统一口径、加守卫。

**本票治的病**：文档用「文件名 + 行号」指向源码。行号是**源码的一个易变投影**，任何一次插行/删行/文件拆解都会让它失效，
而失效**不报错、不告警**——正是本仓反复认过的「记录≠真相」形态。

## 三、口径：**去行号化**

**锚符号名 / 字面量，不锚行号。** 三条具体规则：

1. **锚可 grep 的唯一名**：函数名 / 常量名 / 类型名 / 字面量字符串（如「唯一审查触发」）。
   判据：`git grep -n <锚>` **一次命中**（多处命中 = 锚不合格，须加限定词）。
2. **需要位置感时用相对描述**，不用绝对行号：「定义处」「调用处」「数组末尾」。
3. **行号一律不留**——包括看起来还准的。本票 22 条有效锚里有 `scan.mjs:60` 这类当前准确的，
   但**「当前准确」不是稳定属性**（`ee54fbc` 给同一文件加 3 行就断了 1 处锚）。**统一口径，不留例外**。

**先例**：上一票已按此口径落过一次——`docs/adr/0014-skill-delivery-decoupling.md:54` 的
`seed-data.ts:119` → `seed-data.ts` 的「请审」条目，字面量「唯一审查触发」。本票把该处置升格为全族口径。
