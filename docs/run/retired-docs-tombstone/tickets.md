# 退役知识降级可检索（墓碑切片）+ ADR 1-6 分级通电 —— 票面

> 来源：2026-09-19 用户裁决（回店长 P1 方案）。裁决原文要点：
> ① **降级可检索**：已退役项目只保留结论，防止其他信息影响 Agent 判断——「如某猫重提 C3 方案，检索退役项目中应该只写『C3 方案 xxx 已废弃』」；

## 一、架构裁决（店长拍板，本票契约面）

**D1 墓碑切片（Tombstone）机制**：退役文档（`status: superseded|deprecated`）在检索世界里只存在**一个结论切片**，正文切片一个不留。

- **C1 写入口闸**：frontmatter 新增约定字段 `verdict:`（一行结论，须含可检索关键词，如「C3 出站总线方案已废弃，2026-09-01 裁定不做」）。`classifyDocument`（`scripts/flywheel/scan.mjs:230`）加闸：status 为退役值而 verdict 缺失/为空 ⇒ **拒绝入库**（fail-loud，与现有「frontmatter/type/evidence 三样齐」同型）。
- **C2 扫描形态**：退役文档**不切正文**，只产 **1 个墓碑片**——`section_anchor` 用固定约定锚 `#tombstone`，`body` = verdict 文本，`breadcrumb` 指向文档级。扫描器自检：退役文档在 chunks 的行数恒 == 1，不符则扫描报告报错。
- **C3 查询过滤改向**：X4 过滤从「退役一律挡」改为「**退役仅墓碑片放行**」——`packages/server/src/db/repository/chunks.ts` 三处查询谓词（`:306`/`:327`/`:358`）与诊断 CASE（`:557`）统一改为 `(status 非退役 OR section_anchor = '#tombstone')`。保留谓词而不删闸的理由：活库现存量里 ADR 0013 的 8 行正文切片已在库，谓词保证**重扫替换完成前**旧片也不漏进检索。
- **C4 注入标记**：渲染层（`packages/server/src/memory/index.ts` 节渲染 `:553-562`）对退役节加固定前缀 `【已废弃·仅留结论】`，标记由 **status 列**驱动（节装配须带 status 字段），不靠正文文本——猫读到结论时不可能把它当成活指导。

**D2 成立 ADR 先核验后通电**：`accepted` 入库 = 内容对照现码逐条核验通过。核验不过先修文，修文后走同一核验。0006 属「需要修改」——文首加注「主链已换 chunks 飞轮，原管线哪部分仍存活」，注完再核验。

## 二、票单

### 票 P1-A · 墓碑切片机制（派 ds猫，worktree，单 commit 链）

- **边界**：只动 `scripts/flywheel/scan.mjs`（+其测试）、`packages/server/src/db/repository/chunks.ts`（+其测试）、`packages/server/src/memory/index.ts`（仅渲染层前缀 + 节装配带 status，**不动 §A2 链段行为**）、`packages/server/src/memory/index.test.ts`。**不改**黄金集、**不改**任何 ADR 正文、**不做**重扫落库（归 P1-B）。
- **契约**：C1–C4 全文如上。`#tombstone` 锚字面量、`【已废弃·仅留结论】` 前缀字面量即契约，不许换写法。
- **验收**（行为可验证，含反对照）：
  1. 退役文档缺 verdict ⇒ `classifyDocument` 拒入库（测试断言拒绝原因）；
  2. 退役文档入库后 chunks 行数恒 1、anchor 恒 `#tombstone`、body == verdict（扫描器自检 + 测试）；
  3. **反对照甲**：库里人为植入退役文档的正文片（模拟 0013 存量）⇒ 检索**不可召回**（证明谓词挡住旧片）；同库墓碑片 ⇒ **可召回**；
  4. **反对照乙**：注入文本含 `【已废弃·仅留结论】` 前缀且由 status 驱动——把 status 改回 active 则前缀消失；
  5. 既有测试全绿（改向的 `:298`/`:398` 用例按新语义重写），lint 三包绿。
- **重启面**：含 server 源码 ⇒ 收口需重启（归店长发起）。

### 票 P1-B · ADR 1-6 分级通电（派 ds猫，依赖 P1-A 契约合入后开工）

- **边界**：只动 `docs/adr/0001..0006`（+0013 补 verdict）与扫描落库对账；**不改**任何机制代码。
- **票面**：
  - (a) 0001/0003/0004：逐条对照现码核验文中声称（文件、机制、默认值），失实处先修文再补 frontmatter（`status: accepted` + type + evidence 按扫描器准入形状，以 `classifyDocument` 实测为准）；核验清单逐条留证据进 commit message 或票面回执。
  - (b) 0006：文首加注（主链已换 chunks 飞轮，写明哪部分仍存活）→ 同 (a) 核验 → 通电。
  - (c) 0002/0005：标 `status: deprecated` + 按 C1 补 verdict（只留结论形态，用户钦定）。
  - (d) 0013：补 verdict（「C3 出站总线方案已废弃…」一行，含 C3 关键词）。
  - (e) 重扫落库 + 对账：退役文档 chunks 行数恒 1。**真实机制是孤儿物理删，不是陈旧代路径**（本行原写「走 `:445-453` 陈旧代删除」，已按实测更正）——退役件缺 `verdict` 时 `classifyDocument` 判 `missing-verdict` ⇒ **不进 `produced`** ⇒ 落 `!produced` 孤儿差集被 `deleteChunksByDocPaths` 三表齐删（0013 的 8 行旧片即由此消失）；补 verdict 重扫后为该件 1 行墓碑片。通电文档可检索性抽验一条。
  - (f) **注销账**（本批不修，登记防丢）：`docs/plans/memory-flywheel.md:81` 的「查询体**必带** `status IS NULL OR status NOT IN ('superseded','deprecated')`（**NULL 放行**）」是 C3 改向前的旧谓词语义复述。定稿规格不抹历史 ⇒ 更正随该族下一票以修订注记形式落，**不在 P1-A 提交里混入 `plans/` 改动**。
- **验收**：扫描零拒绝零孤儿；`chunks` 按 doc_path 对账（退役=1 行/active=正文切片）；抽验「C3 方案」类查询召回 0013 墓碑片且注入带标记。
