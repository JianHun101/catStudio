## 二、三条随票项裁决

### 裁决 1 · 同根并发粒度 → **不修，归 T-2 Phase I（票面口径为准）**

- **事实**（报告 §三之二「V13-补充」）：`isolatedTestDir` 的派生键是 `packages/server/src/test-helpers.ts:39` 的仓库根 ⇒ 同一 worktree 内两个 vitest 进程算出**同一批**隔离目录，实测 4 轮每轮 4–11 条 failed。
- **裁决**：本票**不修**。票面「依赖」段已把该形态归 T-2 Phase I，且 Phase I 落地后**一猫一 worktree**，同根并发**自然消失**——修它等于给一个即将不存在的形态加复杂度。
- **口径更正（责任在我）**：我下派活时写的「两猫在同一个 worktree 里并发提交不互踩」**说过宽了**。准确承诺 = **跨根**隔离（主仓库 ↔ worktree ↔ worktree，即 junction 别名面），同根并发不在此列。以票面为准，不追认派活单的口径。
- **触发重开条件**：Phase I 落地**之前**，若「一条同根并发假红」实际挡死某次提交 ⇒ 按报告给的最小修法（`isolatedTestDir` 末段挂 `process.pid`）立单。
- ⚠️ **该最小修法有未验证前提**（本记录新加，勿直接照抄实施）：`packages/server/vitest.config.ts` 与测试文件是否在同一进程内求值未实测。若配置在主进程求值、worker 另起进程，pid 化会让「两份派生公式同解」那条断言退化为**同进程自比**，失去交叉校验意义。实施前先测进程模型。

### 裁决 2 · V14 护栏进「改 `packages/**` 的提交口」→ **裁 B（追加 `scripts` project），另立单**

- **判据**：护栏是**预防性**控制，预防性控制只在**犯错点**运行才有效。当前 `packages/server/**` 只映射到 `packages/server` ⇒「在 server 测试里顺手敲相对路径」这一**最常见漏网形态**在提交口不跑护栏，只靠审查档 / 落地档全量兜。而审查档是**纪律**（非强制）——本票设计里唯一**强制**的一档就是提交口。
- **契约不破**：`resolveScopes` 契约（`projects` 恒为 `ALL_PROJECTS` 的**子序列**、顺序确定）仍成立；「scope ↔ project 一一对应」**本来就不成立**（`packages/shared/` → 4 个 project；`docs/adr/` 映射到 scope `packages/server`）。故 B 不是契约变更，是映射表补一行。
- **代价（已实测，非估算）**：`scripts` project 251 用例 ≈ **4.4s/次**，相对 server 项目自身的跑批可忽略，不构成新的假红主源。
- **落地形态**：另立单。改动量 = `SCOPE_PREFIXES` 的「附带 project」一张表 + `precommit-scope.test.js` 若干格。

## 四、给票2（`docs-single-writer`）的一处修正

我此前答用户「docs 的编辑只发生在会话 worktree……要补收口记录，也回 worktree 分支写」——**这条对收口记录不成立**：收口记录是 **post-merge 产物**（它记录的就是合并本身），物理上不可能先于合并存在于被合并的分支里。

故「单一写入口」应重述为 **「每份文档只有一个写入方」**，而非「只有一个写入位置」：

- 一般 docs：写入方 = 会话 worktree（跟代码同分支）；
- **收口记录：写入方 = 收口方，写在 dev 上，且绝不回写 worktree** —— 一个写入方，故结构上不产生重复落盘。

本记录本身即按此形态落地。票2 的 `closeout-dupcheck.mjs` 建议把这条判据写进注释，否则「两侧同名文件」的机械扫描会把收口记录误报成重复落盘。
