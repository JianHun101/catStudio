## 三、架构裁决（店长拍板，本票契约面）

**D1 · 首批范围 = 上表 8 条，不追求穷尽。**
判据是 README 的「无取舍的经验」而非「所有教训」。实施者扫面时若发现表中遗漏（如新近收口票的教训段），**可增补**，但须在回报里给出「增了什么 / 凭什么算跨活可复用」。**不设上限**，也不为凑数硬收。

**D2 · 时序 = 本票先于清目录批（G2）执行。**
素材源在 `docs/run/**`，该目录清掉后**只能回 git 历史取**（`git show <sha>:<path>`）。**那是兜底不是常态**——本票的价值正是「在题材还在工作树里时把它固化」。若实施时发现某源目录已被清，**照 git 历史取并注明「已随收口清理，从 <sha> 取」**，不因此缩范围。

**D3 · 卡片形态 = 沿用既有约定，不新造。**
`docs/lessons/<slug>.md`，slug 用 kebab-case、**不加日期前缀**（`docs/lessons/README.md`「命名」段）；frontmatter `status:` 用 ADR 最小口径四值（`proposed`/`accepted`/`deprecated`/`superseded by <ID>`，见该 README「状态值域」段）。**首批一律 `status: proposed`**——「已被后续活复用且成立」才升 `accepted`，首批无此资格。

**D4 · 写入口 = 按 README「必审说明」段执行。**
`docs/lessons/**` **不在免审白名单**内（白名单只含 `docs/run/**`），卡片落此**天然必审**。提交走**独立 commit + `git add <路径>` → 核对暂存区（`git diff --cached --name-only`）→ 裸 `git commit`**；**不得用 `git commit --only`**（`.husky/pre-commit` 的 `unset GIT_INDEX_FILE` 与它冲突，口径见 `AGENTS.md` 提交段）。**也不得 `git add -A`**——本仓 auto-commit 抢收已复发，被抢收即跳过审查链。

**D5 · 不改 `request-review` 技能正文。**
触发点（第 3 问 + 三行落点表）已落地且用户已确认过形态。本票**只产出卡片**。若实施中发现落点表措辞与实际需要不符，**作为 OQ 回报，不顺手改**（改技能正文是另一条面，会引入未授权的 diff）。

**D6 · 卡片不进 `docs/plans/`。**
上浮出口是 `docs/lessons/` 本身（该目录为**长期件**，`README.md` 明写「卡片是常驻件，**不随活收口清理**」）。本票**不产生 plans 文件**。

**D7 · 卡片标题与背景写法（2026-09-26 用户反馈落契）。**
用户原话裁决：「如果要说明一件事至少把背景交代清楚。比如『比对「两侧」』两侧是哪两侧，标题是内容的总结；参考新闻标题写法，看标题至少让人知道是什么事情。」⇒ 每张卡片：

1. **标题 standalone 可懂**——新闻标题式，读标题即知「什么事、什么坑」；禁用未解析指称（「两侧」「外层帧」这类词要么就地展开、要么不用）。
2. **正文首段交代场景**——哪次活/哪张票撞出来的、术语指称就地解析，再讲规则。
3. §二 素材表是**原文抄录**（溯源证据，不改字）；卡片标题以下表为底稿（实施者可润色，不得退回抽象短语）：
