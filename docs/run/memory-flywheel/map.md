### clowder-ai 向量栈实测（2026-09-12，用户指派勘察）

**结论：clowder 用 `Qwen3-Embedding-0.6B` + `sqlite-vec` 的 `vec0` 虚拟表 + BM25/向量 RRF 混合检索；嵌入跑在独立 Python sidecar，不在 Node 进程内。**

- **模型**：mac 默认 `mlx-community/Qwen3-Embedding-0.6B-4bit-DWQ`（~400MB，MLX 4bit 量化；`packages/api/src/domains/services/service-manifest.ts:251-256`）；**win32/x64 档默认恰是 `BAAI/bge-small-zh-v1.5`（512 维 / ~90MB）**——正是本仓要换掉的那个（`scripts/services/recommendation-matrix.yaml:500-502`）。同表另有 jina-v2-base-zh(768, ~640MB) / multilingual-e5-large(1024, ~2.3GB) 档位。
- **维度取 768，非原生上限**：`memory/interfaces.ts:430` `embedDim: 768 // LL-034: 768 is sweet spot for CJK bilingual; 256 too low`；sidecar 做 **MRL 截断到目标 dim + L2 归一化**（`scripts/services/embed-api.py:222-227`）。⚠️ **不可直接搬**：Qwen3-Embedding 官方宣称 MRL，**bge-m3 不宣称**——本条只作「维度可裁」的参照；~~票甲仍按 m3 原生 1024~~（**票甲已关闭**，Decisions 28 三；将来若触发重开，此约束按当时候选模型重判）。
- **存储与本仓同栈**：`sqlite-vec ^0.1.9` + `better-sqlite3`，`vec0` 虚拟表 `anchor TEXT PRIMARY KEY, embedding float[dim]`（`memory/schema.ts:755-786`），段落级另起 `passage_vectors`（`passage_key` 主键）⇒ **零迁移成本**，本仓现状可比。
- **⭐ 直接命中本仓护栏②③**：clowder 有 `embedding_meta(key,value)` 表写 `embedding_model_id / rev / dim`，不一致即 `clearAll()` + 全量重嵌（`VectorStore.ts:32-58`、`embed-utils.ts:22-29`）——**这就是 Decisions 16 护栏②「模型-维度成对声明 + 启动自检」与护栏③「清老向量」的现成实现**，形态可直接照抄。
- **⭐ 最该摆上台面的一条：嵌入不在主进程** —— `EmbeddingService.ts:1-5` 注释原文 `LL-034: must not run model inference in API process` / `Replaces in-process ONNX`；实现在独立 `embed-api.py`（`:9880`，OpenAI 兼容 `POST /v1/embeddings`，`MAX_BATCH_SIZE=64` / `MAX_TEXT_LENGTH=8192` / GPU 侧 `asyncio.Lock` 串行化）。本仓现状是**进程内 transformers.js**（`embedding.ts:66`）⇒ **换 bge-m3（568MB）后冷启动与常驻内存的代价，蓝本用「进程外 + 不用即关」解**。**已裁（Decisions 28 二）：改独立 sidecar**（本仓 token 池 / 硬超时的前车之鉴属同类——大对象压在主进程里，坏起来是全局的）。
- **距离度量**：vec0 建表**未声明 `distance_metric`**（全仓零命中）⇒ 取上游默认 L2；靠 embedding 侧 L2 归一化使 L2 排序 ≡ cosine。本仓走 `vec_distance_cosine`——**做法不同、前提同一条**：向量必须归一化。
- **检索形态**：FTS5 BM25 + 向量 NN 的 **RRF 融合（k=60）**；**中文查询把 NN 权重提到 `CJK_NN_WEIGHT = 1.5`**（`SqliteEvidenceStore.ts:38,1162-1189`），理由是中文 BM25 召回差 ⇒ **纯向量不是唯一解，是本仓 Q7（注入与配额）的参照**。候选池 `min(max(limit*4,20),100)`；rerank 备有多套（MMR λ=0.7 / 消费加权 / authority）但**默认全 off**。三模式（lexical / semantic / hybrid）设计见 `docs/decisions/020-f102-memory-system-architecture.md:65-77`；向量不可用时 **fail-open 退回纯 FTS**。
- **多模态：无** —— 全仓 `CREATE VIRTUAL TABLE` 仅 4 处（2×fts5 + 2×vec0），**无任何图像向量表**；`multimodal` 的两处命中都只是猫的能力标签与视频 feature 设想 ⇒ **本仓 ADR 0009 第二子空间（SigLIP）领先蓝本，无先例可抄**。
- **蓝本本机并未真跑向量**（诚实标注）：`.env:116 EMBED_MODE=off`，`evidence.sqlite` 里只有**空的** `embedding_meta`、无 vec 表 ⇒ 以上全部结论来自**源码与配置**，**非运行态实测**；`docs/decisions/020-...:84` 留有历史运行记录（`evidence_vectors 850 行 · dim=768 · Qwen3-Embedding-0.6B`）。
- **可配置面**（本仓对照）：`EMBED_MODE`(off/shadow/on，默认 **off**) / `EMBED_MODEL`（**无默认、必填**）/ `EMBED_DIM`(768) / `EMBED_URL`(127.0.0.1:9880) / `EVIDENCE_DB` / `embedTimeoutMs`(3000) / `maxModelMemMb`(800)。**真正生效的 modelId 取自 sidecar `/health` 的 `model` 字段**——TS 侧刻意不写死模型白名单（`interfaces.ts:423-426` 注释：`The scripted sidecar is the runtime authority for the concrete model`）。

## Decisions so far

1. **定位与边界** — MD 是唯一真相源（决策/ADR 落文件，用户可观测），向量表只是**索引**，可随时从 MD 重建；**AGENTS.md 是框架语义载体、不是知识载体**（单文件全文嵌入检索粒度糊，全文加载上下文膨胀）。不吞并文档体系、不平行于文档体系。
2. **AGENTS.md 准入判据（三关）** — 关一·适用面：无条件适用 **或** 高频任务域内的必用坐标系；关二·检索不可替代性（两问任一为「会」即过）：问 1 约束型「不知道它 → 会不会做错、且无信号」、问 2 导航型「不知道它 → 会不会**根本不去找**」；关三·形态硬比例：能压进 1~2 行放全文，装不下**只放指针**，导航条目须比其索引的内容短一个数量级。预算测试**降级为防退化护栏**（判据是闸门，测试防慢破）。触发机制：收口 checklist 增必填字段「本轮经验是否够格进 AGENTS.md」，店长裁决，走既有审查链，不发明新审批面。
3. **收录标准（平移 clowder F102，管线不搬）** — 三类枚举（决策/教训/方法）；每条必须带证据（对话 id / commit sha / 原文摘录）；explicit 判定收窄三条（operator 明确拍板 / 有可直接引用的共识语句 / 已对应到 merged doc 或代码事实），「说得像决定」不算；**禁止清单**：未定方案、brainstorm、临时 TODO/WIP、碎片上下文、模型总结性发挥——定位是抽取器不是总结器。
4. **演化原则** — 追加而非重写（APPEND, don't rewrite，保留演化脉络）；**软删除不物理删**（状态标记，检索过滤）；过时的高相似条目比查不到更危险 → `superseded` 降权/过滤；淘汰需强证据 + 提案人审。
   - **形态参照（2026-09-11 调研）**：Graphiti 双时态——事件时间 `t_valid/t_invalid` + 事务时间 `t'_created/t'_expired`，冲突时只打失效标记、旧边留 tombstone；引用计数**不引入布尔 `deprecated`**（无时间轴、做不了 as-of 查询）
   - **工程默认值**：LangMem `enable_deletes` 默认 **False**（inserts/updates 默认 True）；mem0 的硬 `DELETE` 被评测点名批评（丢历史不可审计）
   - **硬约束**：状态字段**必须落在索引侧并参与查询期过滤**——只改存储行不改索引缓存，旧版本照常被返回（headroom commit `93a2bc2` 实证，与本仓「索引是派生投影」同险）
   - **量化（口径待回溯）**：HOH benchmark 过时文档致 ≥20pp 退化（二手汇编）；余弦相似度区分不了「被推翻」与「被复述」（AUROC 0.59，未独立验证）
5. **Q1 关闭：只索引结晶后的 MD，不索引对话原话** — 用户陈述中真有价值的部分本就会落成决策/ADR/文档；未经辨明真伪或价值的原话，检索到也无意义。故 `memories` 的「用户消息实时嵌入」层**退役**，不再作为候选层保留（不搞双索引/双通道）。实证：见 Notes 的既成事实；外部同形：clowder KD-3（什么都 retain → 碎片化垃圾 → 整库废弃）。**推论**：飞轮的成败全部押在「结晶」这一环上——md 是唯一入口，必须另有捕获机制（见 Q1′）。

6. **Q1′ 关闭：捕获通道的「手」落在文件系统，不落在数据库** — 用户裁定「唯一真相源就应该是 MD 文件」。两条录入通道并存：① **派生通道**（定期扫描新决策/沉淀文件 → 按收录标准判定 → 入库）；② **显式通道**（用户经 MCP / skill 明确要求录入·纠正 → 产出/修改 MD 文件）。索引侧**永远无独立写口**——工具写的是 MD，索引里的那行由扫描器写，故索引可整份删除重建、且修正不会在重扫时蒸发。

### 24. Q6-b 关闭：`status` 管到节（2026-09-11 用户裁「status 管到节」）

- **裁决**：状态的管辖单位 = **节**（切片单位），不是文档。文档级 frontmatter 的 `status` 降为**默认值**，节级可**覆盖**。
- **为什么这个粒度是对的（不是口味）**：索引的最小单位本来就是节（Decisions 14：L1 按 `##` 切，**一个 chunk = 一行**）⇒ 「status 管到节」在实现上**就是「status 是 chunk 行上的列」**——粒度天然对齐，**不需要任何额外机制**。反过来，文档级粒度要在「文档 → 节」下钻时做一次不可靠的传递。
- **实现形态（节级覆盖怎么写）**——节内**首次**出现的引用块，形态钉死：

  ```
  ## Redis 用法
  > **status**: deprecated（2026-09-01 Redis 已退役，结论保留供追溯）
  ```

  - 识别（拟）：`^\s*>\s*\*\*status\*\*\s*[:：]\s*(proposed|accepted|superseded|deprecated)\b`
  - 命中 → 该节 status；未命中 → **继承文档级 frontmatter**
  - **值域与 frontmatter 同一套**（不新增词表）；**位置限定在引用块**（不与正文散文混淆）
  - **为什么必须钉死形态**：这正是 Decisions 20 否掉 B 案（正文正则抽取）的同一条理由——形态不定就正则地狱。节级**无法**用 frontmatter 表达（frontmatter 是文档级），故「节内必须有标记形态」是绕不开的；既然必须有，就钉死它。

- **成本不对称（关键）**：**只有「部分退役」的文档才需要写节级标记**，绝大多数文档零成本（文档级一份就够）。样本落位：**0002** → 文档级 `accepted` + 「Redis 用法」节标 `deprecated`；**0005** → 整份退役，**只写文档级** `deprecated`，节级不写。
- **诚实标注**：节级 status 是**声明类**字段、**会漂**（标了 `deprecated` 后想恢复、忘了改）。但它**派生不出来**（机器无从知道一节是否失效），故与文档级 `status` 同类，属「必须人写」——不违 Decisions 21 一的不对称原则。
- **过滤性口径修正（同轮，用户追问「元数据不具有过滤性好吗」）**：Decisions 23 清点过滤力时**只算了 frontmatter 五字段，漏了表列**——`doc_path` / `section_anchor` 是**强过滤维度**（「只在 `docs/adr/` 里找」= 前缀过滤，恰恰是最常用的过滤方式）。修正后：

| 维度                          | 载体                     | 力度           |
| ----------------------------- | ------------------------ | -------------- |
| **时效**（过时的绝不返回）    | `status`（**节级**）     | 强 · 硬排除    |
| **范围**（只在某目录/某类找） | `doc_path` 前缀 + `type` | 强 · 前缀/等值 |
| **时间**（新的优先）          | `date`                   | 弱 · 排序      |

⇒ **不是「元数据不具过滤性」，是「过滤性尚未接入查询体」**（Decisions 23 实测 `memories.ts:203-231` 零 WHERE）。且**不该要求所有元数据都有过滤力**：`evidence` 拿它过滤等于**恒真**（准入已保证非空），`supersedes` 是**图边**不是筛子。**元数据的第一价值是时效性、第二是可解释、第三才是过滤。**

### 29. Q3 补丁：切分回退链补全——「**不存在不能切的内容**，只有不能用同一把刀切的内容」；「不切并记例外」作废（2026-09-12 用户「切分按段落或者语义句子都可以吧，切分完补充合适的上下文。应该不存在没法切的内容」）

**一、被否掉的两条（Decisions 14 就地划改）**

- L3 散文分支的「单段自身超限则**不切**并记例外」、以及铁律「**绝不切句子**」——用户判词否掉两者：段落 / 语义句子都是合法切点，切完补上下文，**不存在没法切的内容**。

**二、为什么用户是对的（不是让步，是目标函数被换了）**

- Decisions 14 安全网原话已定「**碎块只负责命中精度，读到的永远是完整语义**」——碎片**从不被直接读**（命中即返回整节 + 面包屑）⇒ 「切碎了不好读」这条**唯一的反对理由被安全网自身消掉**。
- 而「不切」的代价是实打实的：单段 > 510 字（静默截断实测线，见 Decisions 14 实测条）时**尾部对检索完全不可见**。⇒ 拆开反而**提升召回覆盖**。在本设计的目标函数下，**拆严格优于不拆**。
- 唯一需修正的是措辞：准确形式为「**不存在没法切的内容，只有不能用同一把刀切的内容**」。

**三、回退链补全（每一级都是一个合法边界，只有最后一级留痕）**

| 级   | 刀（切点）                                                                                                            | 适用形态                                     |
| ---- | --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| L1   | `##`（无则 `#`，再无则整文件一块）                                                                                    | 结构                                         |
| L2   | `###`                                                                                                                 | 结构                                         |
| L3-a | **表格行 → 转写句**（Decisions 27 + 28 一，全表无条件）                                                               | 表格                                         |
| L3-b | **条目边界** `^\s*([-*+]                                                                                              | \d+[.)])\s`                                  | 条目列表 |
| L3-c | **空行（段落）**                                                                                                      | 散文                                         |
| L3-d | **句边界 `。！？；`**（标点随前片）                                                                                   | 超长段落内部                                 |
| L3-e | **行边界 `\n`**——**代码块专用**：`。！？；` 在代码里无语义，句刀在此**失效 ⇒ 换刀，不是不切**；围栏语言标记复制到每片 | 代码块（``` 围栏）                           |
| L3-f | **字符硬切（450）** + **记例外（标记，不阻断）**                                                                      | 无任何边界的连续串（长 URL / base64 / 哈希） |

- **转写行的刀插在 L3-c 与 L3-d 之间**：`列名1：值1；列名2：值2` 的自然切点是 **`；`**，不是 `：`。
- **关键语义变更**：**例外不再是「不切」** ⇒ 落到 L3-f 的内容**照样入库**，只被打上标记（哪份文档 / 哪个切片 / 硬切几次）进汇总报告。Decisions 14 的「不切并记例外」**作废**。

**四、「补充合适的上下文」的操作定义（分两级）**

1. **结构级（已裁，Decisions 21 四）**：每片一律前置面包屑 `相对路径 > H1 > H2 > H3`，进嵌入文本。
2. **语义级（本条新增）**：**仅当一片切自某段落内部**（L3-d / L3-f 生效）**且该片不是该段首片**时，前置**该段首句**作话题锚——取**原文**，**不生成概括**（生成式概括引入模型、不稳定，且撞「回退链不引模型」的确定性原则）。
   - **只给非首片**：首片自带段首句，加则重复。
   - **同质化风险（诚实标注，且已被安全网吸收）**：同段多片共享同一锚 ⇒ 该节**内部**碎片互相相似；但最终结果**按节去重**（Decisions 14 安全网）⇒ 同质化落在节内部、被去重吃掉；**跨节竞争不受影响**（锚是本节特有的原句，不是通用套话）。
   - **计入 450 预算**：锚与面包屑都算在 450 内（承 Decisions 14 实测条「面包屑一并计入后仍在线内」）。
3. **片序号不进嵌入文本**：`（N/M）` 只进索引侧表列 / 调试信息——理由同 `status`（Decisions 21 四：「标题进文本、状态进表列」的同一原则 = **语义进文本，结构进表**）。

**五、连带须改的两处**

- **Decisions 28 三 的「静默截断显式化」换了更好的岗位**：原定位是「**不切**那条兜底路径上的告警」，该路径没了 ⇒ 转正为**切片器不变式自检**——上游保证每片 ≤450，嵌入层若见 >510 即**切片器 bug**，告警并记例外。**比原定位更硬**（提示 → 断言）。
- **身份键（Decisions 17）不必带片序号**：`路径 + 小节锚 + 内容哈希` 已足够幂等；带片序号反而使「节内插入一段」导致后续碎片身份全变。节内容变化 ⇒ 该节**整节重嵌**是正确行为；但**孤儿行清理**（重扫后不属新集合的碎片行）须在段三票里钉死，否则积压旧碎片。

### 30. 「附加上下文两层拆分」评估：形态同向、**「完全可复现」不成立**；模型增强层**不立项**（**已裁**）（2026-09-12 用户转述一条外部结论并问「你怎么看」；同日「同意你的说法」裁五）

**一、同向的部分（不是新裁，是既有设计被印证）**

- 用户主张「拆成确定性层 + 模型增强层，确定性层永远跑」= 本图已成形的分工：**结构级面包屑**（Decisions 21 四：所有层级的块一律前置 `相对路径 > H1 > H2 > H3`，进嵌入文本）+ **语义级话题锚**（Decisions 29 四：取**原文段首句**、**明令不生成概括**）。
- 「**情境化改写**」这一项，本设计**已有确定性替代且已裁**（Decisions 29 四）——当初改成「取原文」的理由正是绕开模型。⇒ 这条主张里最实的一块**已经落地在本图里**。
- 用户举的例子 **2/3 已在确定性层内**：**标题路径** ✅（Decisions 21 四）；**表头** ✅（Decisions 27 规则 4：转写句的列名取自表头同列，且转写是**纯字符串变换**）。

**二、三处不接受的**

1. **「80%」是借来的比例，不能当本地结论。** 该口径来自通用 RAG（语料是无自描述结构的长散文/网页，其「上下文」默认只有文档标题一句，其余全靠生成），**与本仓语料形状不同**：13 份 ADR 自带 `##`/`###` 层级 + 字段化状态，且模板**强制正文就是 1~3 句的结论**（Decisions 10，lessons 目录尚空）。⇒ 本仓的诚实口径是：**确定性层是目前唯一有证据支撑的一层**；模型层在本仓**检索质量证据为零**。比例具体是几不重要，重要的是**它不构成引入模型层的论据**。
2. **「结果完全可复现」是过度承诺——缓存是性能机制，不是复现机制。** 命中才等价；未命中即重新生成，而 LLM 输出即使 temperature=0 也不保证逐位相同。更尖锐的是它撞不变量：Decisions 1 / 17 / 20 要求「**删表 → 重扫 → 与删前逐行等价**」；生成文本一旦进索引，重扫结果就**依赖缓存状态** ⇒ **「缓存可随时清空」与「结果完全可复现」不能同时成立**。
   - **据此定一条形态铁律**：这一层只有两个自洽位置——**(甲) 持久化为索引的一部分**（那它就是「有独立状态的数据」，必须与索引同生命周期管理、共用同一套 GC），或 **(乙) 每次重算**（那就承认不可复现）。**不能既当可清空的性能缓存、又当复现保证。** 该论证与 Decisions 20 否掉「元数据只存表」**完全同一条**（只存表 ⇒ 重建不再无损），只是对象从元数据换成生成文本。
3. **缓存键少一维：模型 revision。** 键 = 内容哈希 + 提示词版本 + **模型 ID** 不够——同名模型被服务端静默升级 ⇒ 缓存**全量污染且无信号**。蓝本存的恰是 **`model_id` / `rev` / `dim` 三件**（Notes「clowder-ai 向量栈实测」的 `embedding_meta`）。这与本图反复出现的同一类亏同形（ADR 0012：字段名对、值也对，机器只校存在性会给绿灯）。
   - **顺带**：键含内容哈希 ⇒ MD 编辑一次，旧条目即成为孤儿。**孤儿行清理**正是 Decisions 29 尾刚钉给索引的问题——缓存会复制一份，故**必须与索引共用同一套身份键与 GC 纪律**，不得另起一套。

**三、「重建索引边际成本接近零」算错了账**

- 缓存省的是**生成调用**；重建索引的大头是**嵌入调用**（每片一次，片数远多于文档数，且 Decisions 29 无条件拆片后片数上涨）。⇒ 拿「重建成本」当引入这一层的论据**不成立**；唯一站得住的论据是「检索质量」，而那句在本仓**没有证据**。

### 32. 「检索质量埋点」具体化：它是**阈值前近邻池的留痕**，不是指标面板；由「雾区待裁」改挂为**检索接线票的契约**（2026-09-12 用户「① 卡着你的，具体是什么 说清楚」）

**一、它具体是四件事（逐条对现存代码面）**

1. **「空手而归」零留痕**：`reply.ts:623` 只在 `memoryContext` 非空时才记 `log.info('记忆上下文已注入')`（`:630`，记的是 `memoryChars` / `memoryTokens`）⇒ 空串路径**全无痕迹** —— 而无命中（`memory/index.ts:331`）、检索 10s 超时（`reply.ts:614-621` 的 `Promise.race` 静默 resolve `''`）、`MEMORY_ENABLED=false` 三者**在当前日志里长得一模一样**。

**二、为什么它无法单独判定「该召回的没召回」（分工问题，不是技术问题）**

- 「该」需要**真值**，真值不在日志里——只有人/猫能说「这明明该被召回」。
