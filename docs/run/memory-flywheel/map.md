### ADR 模板 vs skill 合规对账（2026-09-11，用户问「收紧后还符合 domain-modeling 吗」）

**结论：做减法（摘掉愿景/需求/后续项/实施进度）＝回归 skill 原形，合规；做加法（把可选项定为固定段）＝过度收紧，已撤回。**

- skill 原文（`ADR-FORMAT.md`）：模板 = 标题 + 1~3 句（context + decided + why），「**That's it.** ... The value is in recording _that_ a decision was made and _why_ — **not in filling out sections**」；Considered Options / Consequences / Status **均为可选**——「Only include these when they add genuine value. **Most ADRs won't need them.**」
- ⇒ 上轮提议的「收紧到 背景与摩擦 / 决策 / Considered Options / Consequences / Status」中，**后两项定为固定段属越界**，撤回；**唯一保留的偏离 = Status 从可选升为必填**（消费者变了：扫描器无判断力，只读字段——没字段 = 该文件对索引不存在）

## Decisions so far

1. **定位与边界** — MD 是唯一真相源（决策/ADR 落文件，用户可观测），向量表只是**索引**，可随时从 MD 重建；**AGENTS.md 是框架语义载体、不是知识载体**（单文件全文嵌入检索粒度糊，全文加载上下文膨胀）。不吞并文档体系、不平行于文档体系。
2. **AGENTS.md 准入判据（三关）** — 关一·适用面：无条件适用 **或** 高频任务域内的必用坐标系；关二·检索不可替代性（两问任一为「会」即过）：问 1 约束型「不知道它 → 会不会做错、且无信号」、问 2 导航型「不知道它 → 会不会**根本不去找**」；关三·形态硬比例：能压进 1~2 行放全文，装不下**只放指针**，导航条目须比其索引的内容短一个数量级。预算测试**降级为防退化护栏**（判据是闸门，测试防慢破）。触发机制：收口 checklist 增必填字段「本轮经验是否够格进 AGENTS.md」，店长裁决，走既有审查链，不发明新审批面。
3. **收录标准（平移 clowder F102，管线不搬）** — 三类枚举（决策/教训/方法）；每条必须带证据（对话 id / commit sha / 原文摘录）；explicit 判定收窄三条（operator 明确拍板 / 有可直接引用的共识语句 / 已对应到 merged doc 或代码事实），「说得像决定」不算；**禁止清单**：未定方案、brainstorm、临时 TODO/WIP、碎片上下文、模型总结性发挥——定位是抽取器不是总结器。
4. **演化原则** — 追加而非重写（APPEND, don't rewrite，保留演化脉络）；**软删除不物理删**（状态标记，检索过滤）；过时的高相似条目比查不到更危险 → `superseded` 降权/过滤；淘汰需强证据 + 提案人审。
   - **形态参照（2026-09-11 调研）**：Graphiti 双时态——事件时间 `t_valid/t_invalid` + 事务时间 `t'_created/t'_expired`，冲突时只打失效标记、旧边留 tombstone；引用计数**不引入布尔 `deprecated`**（无时间轴、做不了 as-of 查询）
   - **工程默认值**：LangMem `enable_deletes` 默认 **False**（inserts/updates 默认 True）；mem0 的硬 `DELETE` 被评测点名批评（丢历史不可审计）
   - **硬约束**：状态字段**必须落在索引侧并参与查询期过滤**——只改存储行不改索引缓存，旧版本照常被返回（headroom commit `93a2bc2` 实证，与本仓「索引是派生投影」同险）
   - **量化（口径待回溯）**：HOH benchmark 过时文档致 ≥20pp 退化（二手汇编）；余弦相似度区分不了「被推翻」与「被复述」（AUROC 0.59，未独立验证）
5. **Q1 关闭：只索引结晶后的 MD，不索引对话原话** — 用户陈述中真有价值的部分本就会落成决策/ADR/文档；未经辨明真伪或价值的原话，检索到也无意义。故 `memories` 的「用户消息实时嵌入」层**退役**，不再作为候选层保留（不搞双索引/双通道）。实证：见 Notes 的既成事实；外部同形：clowder KD-3（什么都 retain → 碎片化垃圾 → 整库废弃）。**推论**：飞轮的成败全部押在「结晶」这一环上——md 是唯一入口，必须另有捕获机制（见 Q1′）。

6. **Q1′ 关闭：捕获通道的「手」落在文件系统，不落在数据库** — 用户裁定「唯一真相源就应该是 MD 文件」。两条录入通道并存：① **派生通道**（定期扫描新决策/沉淀文件 → 按收录标准判定 → 入库）；② **显式通道**（用户经 MCP / skill 明确要求录入·纠正 → 产出/修改 MD 文件）。索引侧**永远无独立写口**——工具写的是 MD，索引里的那行由扫描器写，故索引可整份删除重建、且修正不会在重扫时蒸发。
   - **术语澄清**：「工具写 MD 卡片」= 工具的动作是**文件写入**（+ 触发重嵌），不是向向量表 INSERT。若工具直写表，重扫时该条会消失或需要「这条别删」的例外逻辑 → 破坏唯一真相源。
   - 用户原话（2026-09-11）：「向量库对其切片做索引，用来供 Agent 查询。同时也支持用户直接调用工具去录入 MD 文件，纠正或者新增相关知识」

7. **Q2 关闭：存量不收，规范化前置，过闸准入**（2026-09-11 用户裁定）—— 用户判词：当前文档的归纳与放置**未经过严格规范标准**（ADR 未完全落地、有过时件需删改），故 ① **不做存量原地索引**；② **先把存量文件的内容与位置规范化**；③ 然后对**后续文件定期过闸准入**。保留例外通道：**可从日期较近的若干文档中抽取为 MD 卡片**。
   - **本裁定的连锁后果**：飞轮的启动不再取决于「扫描器何时建好」，而取决于「文档规范化何时达标」——**规范化成为飞轮的硬前置**（路线图段一 → 段二 → 段三）。

    - **链路（①–⑤ 读源确认；⑥ 为推断，标置信度）**：① `packages/server/src/llm/git-utils.ts:4` auto-commit，**每轮 Agent 完成即提交改动**；② `.husky/post-commit` → `handoff-gen.mjs`，`decideHookDelivery`（`:1033`）判「该 commit 有归属执行 → 静默」——**这步没错**，但静默**不记账本**（`deliverSha:1472-1476`，T-A ① 有意为之：记了会锁死兜底）⇒ **「判过静默」这个事实在系统里不存在**；③ 执行收尾 `execution/review-fallback.ts:66` `judgeReviewFallback`：**本执行有 commit 且回复 mentions 不含 reviewer → 补投**；④ `--fallback-sha` 是独立入口、**不走归属判据**（`handoff-gen.mjs:1191` 注释明说）→ 补投成功、记 delivered；⑤ 投进来的消息唤醒一轮执行 → 又写 tracked 文件 → 回 ③。**实测佐证**：连续 12 个 commit 各带**不同 uuid**（`0b986d60`…`489af016`），即每轮都被一条**不同入站消息**唤醒。**诚实标注**：⑥「唤醒谁」**无法完全复原**（messages 行已被用户删除），**闭环结论系推断**，置信度高但非实测。
    - **根因一句话**：`judgeReviewFallback` 把「本执行**有 commit**」等同于「本执行**有交付物**」——写 `docs/**` 过程文档同样构成 commit，于是被判成「有人提交了东西却没投审查请求」→ 反复补投。
    - **方案 A（店长推荐，形态已裁待时机）**：加**交付物闸**——commit 触及的路径**全部**落在免审白名单（`docs/run/**`，承 Decisions 15）内 → 静默并留痕。落点 `packages/server/src/execution/review-fallback.ts`，**纯函数、同目录已有测试**，行为可单测。**白名单与交付物闸并成一票**（同一纯函数的同一处判断，拆两票要改两遍）。
    - **被否方案**：B 在 auto-commit 层跳过纯 docs 改动（把特例塞进通用机制 = 防御性代码）；C 账本加第三态 `silent`（动的是 T-A 定死过的账本协议，**且治不到真问题**——docs 提交照样产生）；D 行为侧「店长不写 tracked 文件」——**止血不治本**，换任何猫跑长对话都会再踩。
    - **落地需重启**（改 server 代码），走 `request_user_action(type:'restart')`。

19. **流程教训：私有记忆库不可当裁决暂存区**（2026-09-11 用户一句「你落记忆库不会遗漏吗」）
    - **事实**：为回避上述回环，店长自本会话起**停写 tracked 文件**，把 Q3/Q4 等裁决暂存进**店长私有记忆目录**（仓外、不进索引、其他猫与审查链均不可见）。**本条与 Decisions 1 正面冲突**：既然裁了「MD 是唯一真相源」，把裁决留在仓外的私有目录就是亲手造一块**暗知识**；且回环只是**噪声**（多一轮审查），暗知识是**丢失**——**规避手段比问题本身更糟**。
    - **已实证的遗漏**：① 地图停在 Decisions 13（票 E 撤回），Q3/Q4/审查门/DEDUP **一条未落**；② 私有记忆文件是**压缩摘要**（~20 行），已丢 ADR Status 四形态实测表（Q6 的直接输入）、L3 三条判据的正则口径、bge-m3 三护栏；③ **编号漂移**——店长口头称「下一问 Q5-a 元数据形态」，而地图里 Q5 是「自动扫描管线」、元数据实属 **Q6 schema 形态** ⇒ 口头暂存**自造编号**，正是「不可索引」的病症本身。
    - **通则**：地图就是 grilling 的产出物，**边裁边落**。停写只该停「长篇过程叙述」，不该停「结论落图」。`docs/run/**` 恰在免审白名单内 ⇒ 落图的 commit 本就不该触发审查（票乙修好前最多吃一条噪声，**不滚雪球**）。

20. **Q6-a 元数据形态：MD 承载权威、表承载查询，二者不是二选一**（2026-09-11 用户问「知识文件的元数据不能作为字段存到表里吗」）
    - **可以，且应该存表**——但表里那份是**投影**，MD 里那份是**真相源**。判据出自已冻结的 Decisions 1：若元数据**只**存表，删表重建即丢元数据 ⇒ **重建不再无损**，索引就从「派生投影」变成「有独立状态的数据」。这与 Q1′（Decisions 6）否掉「工具直写表」是**同一条原则**。
    - **表字段是必需项，不是可选项**：Decisions 4 的硬约束（headroom `93a2bc2` 实证）要求状态字段**落在索引侧并参与查询期过滤**——只改存储行不改索引缓存，旧版本照常被返回。故 `type` / `status` / `evidence` / `valid_from` / `valid_to` / `superseded_by` **必须**是表列。
    - **不变式（可验收形式）**：**删表 → 重扫 → 与删前逐行等价**。
    - **仍待裁的是「权威副本的载体形态」**：**A** 统一 YAML frontmatter（店长推荐：位置/形态/语言三样一次钉死；且 frontmatter 是元数据不是正文，**不违**「ADR 回归 skill 原形」）；**B** 扫描器从正文提 `Status:` / `状态：` 行（正则须兼容裸行·引用块·中英文·括注，且**无强制力**——忘写就没状态，只能跳过）；**C** 仅 lessons 加 frontmatter（两套机制并存，撞 `CONTEXT.md:73`）。
    - **配套（拟，待 A/B/C 定后确认）**：`evidence` 每条 `{kind, ref}`，`kind ∈ {commit, file, exec-log, external}`；机器只校**存在性**（字段齐 + `git cat-file -e <sha>^{commit}` / 路径存在），**不校真伪**（承 Decisions 11）；禁项（无 frontmatter / `type` 缺失 / `evidence` 空）→ **跳过不入索引 + 汇总报告**，不炸整轮扫描。
    - **A 解决不了「部分退役」**——ADR 0012 的 Status 值是 `accepted`，内容却已半退役（「push 审批部分已退役」写在值里）：**字段名对、值也对，机器只校存在性会直接给绿灯**。⇒ 状态是管**整份文档**的生死还是管**逐条决策**的生死，须另裁（拟编号 **Q6-b**）。
