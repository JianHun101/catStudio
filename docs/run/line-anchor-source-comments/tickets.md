## 一、立票理由

上一票（`line-anchor-delinearize`）§2.5 的「面外实核」只扫了五类**猫可见面**——`AGENTS.md` / `CONTEXT.md` /
`CODING_STANDARDS.md` / `README.md` / 全部 `SKILL.md`——结论是「零行号锚，病害恰好被关在检索白名单内部」。

**那个结论对那五类面成立，但它没扫源码注释面。** 用户指令原文是「检查其他可能被检索的文档」，而现在实测：
**`packages/**` + `scripts/**` 的源码注释里有 76 条「路径:行号」锚 + 1 条目标已删的 C 档锚**（修正后读数，
见 §2.4），其中 9 条已逐条读原文确证失效。

**为什么这仍属本族**（不是新病）：同一机制（拿易变投影当指针）、同一失效形态（不报错不告警）、同一处置
（锚符号名/字面量）。差别只在**影响面**：检索面锚会注入每只猫的 prompt，源码注释锚只在人/猫读该文件时可见
——**小一档，但不是零**，且它有**照抄繁殖**效应：仓库里现存 77 条先例，正是写注释时的现成模板。

> **诚实留痕（本票自己先认一笔）**：店长在上一票的收口回执里报的是「源码注释面 **2 处**」——那是**抽看**得出的
> 印象值，全量实测（77 条，订正后口径）推翻之，量级差约 38 倍。这与本族反复认过的「陈述未经复核」是同一个病，**本条即该病
> 的第 N 次复发**，故立此票时不再采信自己的任何印象值，全部读数附判据与复现命令。

（两个维度都要扫：① 旧词是否还留在别处 ② 同一规则的措辞分叉）。

### 组件 3 · **不做守卫**（本票的取舍，须留痕）

**裁决：守卫不扩到源码注释面。** 三条理由：

1. **影响面小一档**——检索面锚注入每只猫的 prompt（持续投喂），源码注释锚只在读该文件时可见。
2. **假阳性高**——起草期实测：弱词（`node`/`busy`）、IP:端口、模型 tag 都会命中；要压住就得维护豁免白名单，
   而**本仓栽过「门禁退化成静默放行」**（ratchet / 豁免是同一个坑）。一个天天要豁免的守卫，最后没人看。
3. **防复发另有机制**：**存量清零 + 口径立规**。仓里零条先例时，写注释的人不会凭空发明 `file:line`；
   而上一票的检索面守卫仍然在岗（`scan.test.js`），守住真正会注入 prompt 的那一面。

**触发条件（复查此裁决）**：源码注释面**再复发 ≥3 条新锚** ⇒ 重议守卫（届时优先考虑「只扫 `AGENTS.md` 口径
条覆盖的高频文件」这类窄口径，而不是全源码面）。

### 组件 4 · 上一票的两处复述面漏网（**上一票 §七 验收 #5 没扫到**）

1. **`docs/plans/memory-flywheel.md` 的行号引用纪律段**（`type: plan` / `status: closed` ⇒ **在检索白名单内、
   会注入每只猫 prompt**）：它写「票收口时回校票面行号……一律 `grep -n <符号名>` **取行号**」——**后半句正是
   上一票刚作废的「校准到真值」口径**，属典型「同一规则多处措辞分叉」。
   ⇒ 改为去行号化口径；**这是本票优先级最高的一条**（它每天都在往每只猫的 prompt 里投旧口径）。
   ⚠️ 该条**上一票的守卫抓不到**——守卫抓的是行号锚（`file:NNN`），而这是**口径复述**（教人怎么用行号）。
