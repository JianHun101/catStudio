## 三、需店长裁的**口径问题**（我不自行改判）

1. **观察项算不算「未闭项」？** 三种处置都已在票面出现，口径不统一：
   - `hook-fallback-delivery`：观察项 → **明文「勿随本活收口删除」**（用户裁）
   - `test-git-env-pollution`：观察项 → **承 `745535c` 判据不清**
   - `frontend-perf`：观察项 → **无保留指令**，4 条均带钉死触发条件
     ⇒ 建议口径：**「未闭项」的判准是「有无钉死的触发条件」，而非「有没有写下来」**——带触发条件的观察项可随上浮带走，不带的不行。若采纳，`frontend-perf` 可升级为 **A 类**。

2. **上浮出口能不能是手册？** `CONTEXT.md:95` 把上浮出口钉死在 `docs/plans/`（「点名，不二选一」）。但 `line-endings`（仓级行尾策略）与 `vision-retire`（角色注册表）的结论**天然属于手册**（`AGENTS.md` Gotchas / `CONTEXT.md` 术语表），放进 `docs/plans/` 会造出一份无人读的「规格」。⇒ 我按约定**照实填了 `docs/plans/` 落点**，但把口径问题摆在这里；若判手册可作上浮出口，这两条落点改判。

3. **`taste-skill` 的整改活未开票**——它既不是「已收口」也不是「在本目录内能收口」：票 B/D 的报告是**待整改的输入**，整改票还没出。⇒ 本目录在整改票开出前**不能清**（清了报告就断链）。
