## 0 结论先行（回答用户三问）

用户原话问的是两件事：「要把距离调的更严格吗」「还是 topk 不够大？」。数据给的答案：

**① 0.6 不是主因，且收紧它是有害动作。**
`MEMORY_MAX_DISTANCE = 0.6` 这道闸在 1109 个 event 里**只在 6 个上碰到过东西**（0.54%），且被它挡掉的 72 行经逐条查证**全是无关片**——也就是说「误杀」为 0、「放宽」无收益。反向的代价是实的：样本 A 里把阈值收到 0.35，**13 条有效注入会被清掉 7 条**（54%），而 47 条无效注入只清掉 29 条。原因在第 4.1 节：**相关片与不相关片在距离轴上完全重叠**（命中事件最好一节的距离 p50=0.362，空手事件 p50=0.373）。

**② topK 不是漏相关性的一环，加它没有出口。**
活库 topK **已经是 5**（不是票面背景口径写的 3，见 §1.4），样本 A 里确有 2 条 event 的**全部**相关节落在 `section_rank ≥ 3`——加名额确实救回过东西。但主病灶在更上游：**47 条空手事件的候选池（阈值前 KNN top-20，是 topK 的 4 倍）里，一片相关的都没有**。池里没有的，topK 取不出来——把它提到 20 也是空。

**③ 观感差的真因是「问的东西语料里没有」，分三类（样本 A 的 47 条空手）：**

| 细分                     | 条数 | 占比 | 说明                                                                                                                                                |
| ------------------------ | ---- | ---- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 无主题协调语             | 13   | 28%  | 「按你说的顺序做」「已重启」「重投」「换下我看看效果」——消息本身没有可检索的主题，检索无从对齐                                                      |
| 语料域外                 | 6    | 13%  | 简历/kami 字体、dify、boss 直聘——主题属外部项目或外部素材，白名单三目录天生不覆盖                                                                   |
| 本仓域内但语料无对应文档 | 28   | 60%  | UI/视觉/文案/工单/产品形态类（导航栏宽度、角标实现、M3 修法…）——**这些规格落在 `docs/run/**`，而白名单只扫 `docs/adr` `docs/lessons` `docs/plans`** |

一句话：**用户看到的「记忆片跟说的内容关系不大」，绝大多数不是阈值放进来烂片，而是「池子里本来就没有好东西，于是把当时最近的一批不相关片填了进去」。** 调阈值只会改变「填几片」，不会改变「填的是什么」。

### 1.3 判定口径（写死在这里，供复查者按同一条尺子复算）

**相关判据（三档）**

- **相关**：注入片所在节的主题 == 消息所问/所改的对象本身（消息问 A，片讲的就是 A 或其直接机制）。
- **弱相关**：片与消息共享同一上位主题域（都属「记忆系统」「审查流程」「执行调度」），但节内容不是消息所问的那个具体对象。
- **不相关**：无共同主题域。**仅共享通用词不算相关**（例：「skill」一词同时出现在 ADR 0014 与「kami skill 的字体」里，判不相关）。

**分桶判定树（互斥，命中即停）**

1. 注入集中存在 **相关** 节 → **命中**（不计入票面三桶）
2. 否则，若相关片被 `droppedReason='threshold'` 挡掉 → **阈值误杀**
3. 否则，若相关片进了池但未进注入（`not_topk` / `budget` / `section_dup`）→ **过阈值但被 topK/排序/预算截断**（票面三桶未列的第 4 态）
4. 否则 → **空手而归**（池里没有相关片），再按下位细分：

   - **无主题**：消息是纯协调语/确认语/泛问，本身无可检索主题
   - **语料域外**：主题属外部项目或外部素材
   - **语料域内无对应文档**：主题属本仓，但白名单三目录里没有对应文档

**四处口径选择（影响计数，明写以免歧义）**

- 票面「阈值误放」字面定义是「final 注入的片判不相关」，与「空手而归」**在本次数据上完全重叠**（47/47 同时满足两条定义）。故本报告用的是上面的互斥判定树，并单列「第 4 态」以保留「池里有好东西却没进来」这一类——它对回答 topK 问题才是关键。
- 「弱相关」在主口径里**不计入命中**（严格）。同时给出宽松读数：把弱相关计入后 A 为 15/60、B 为 5/30，**两种读法都不改变本文任何一条关于旋钮的结论**。
- **纯关键词通道的注入行 `distance = NULL`（全库 8 节，§3.1）不参与「最小注入距离」的计算**：§4.1 清算表的判据一律取该 event 注入集**向量通道**行的 min。若把 NULL 当 0 算，EV#1014（其 5 条注入里 3 条走 keyword 通道、距离 NULL，最小注入距离将由 0.467 变成 0）会被误判成「任何阈值下都清零」。复算者请按「排除 NULL 行后取 min」这一口径对齐。
- **阈值分界值 `d = T` 视为被挡，保留条件是 `d < T`（严格小于）**——这是代码语义，不是本报告的取舍：向量召回的 SQL 判据是 `v.distance < ?`（函数 `searchChunksByVector`，`packages/server/src/db/repository/chunks.ts`；同处注释「余弦距离 ≥ 此值不召回」），流水侧 `probe` 行的 `droppedReason='threshold'` 亦由 `c.distance >= params.maxDistance` 判定（`packages/server/src/memory/index.ts`）。故 §4.1 的「清零」判据写作「最小注入距离 **≥** T」，与「平均保留节数」的 `d < T` 同源——分界值上两者不再各自为政。

### 1.4 一处票面背景口径订正（有实证，非翻案）

票面背景口径写「`MEMORY_TOP_K = 3` 按节计注入名额」。**活实例当前是 5**：

- 流水侧同源印证：`param_top_k` 在 `2026-09-21T08:38Z` 及之前全部为 3（826 条），从 `2026-09-21T08:57Z` 起全部为 5（283 条）。

## 4 三个杠杆的定量清算

### 4.1 杠杆一：`MEMORY_MAX_DISTANCE = 0.6`

**它现在拦到了什么？**

- 全库只有 6 个 event（0.54%）的探针池里出现过 ≥0.6 的片，被挡 72 行，距离区间 0.602–0.658（`p50=0.613`）——**全部紧贴阈值上沿**，且逐条读过后全部与触发消息无关。
- 探针池（top-20）的最大距离分布：p10 0.211｜**p50 0.262**｜p90 0.501｜max 0.658。也就是说九成以上的 event，池子里第 20 近的片离消息还不到 0.5。

⇒ **放宽 0.6**：只对这 6 个 event 生效，加进来的还是无关片——**零收益**。

**收紧会付出什么？** 用样本 A 做清算（判据：该 event 的「最小注入距离」**≥** T ⇒ 该 event 注入清零；「平均保留节数」= 该 event 注入集中 `d < T` 的节数在全 60 条上的均值、排除 NULL 行——两条判据同源，分界口径见 §1.3）：

| 阈值 T   | 命中事件被清零 | 空手事件被清零 | 平均保留节数      |
| -------- | -------------- | -------------- | ----------------- |
| 0.25     | 11/13          | 45/47          | 0.18（现状 4.88） |
| 0.30     | 11/13          | 39/47          | 0.45              |
| **0.35** | **7/13**       | 29/47          | 1.37              |
| 0.40     | 4/13           | 19/47          | 2.63              |
| 0.45     | 2/13           | 12/47          | 3.35              |
| 0.50     | 1/13           | 1/47           | 4.33              |

⇒ **收到 0.35（直觉上的「更严格」档）会误杀 54% 的有效注入，只换来 62% 的无效注入被清空**；收到 0.25/0.30 则等于把记忆注入功能整体关掉（命中 11/13 清零）。

**根因：距离轴分不开两类片。** 样本 A 里「每 event 最好一节的距离」：

- 命中事件（n=13）：min 0.172｜p10 0.199｜**p50 0.362**｜p90 0.477｜max 0.532
- 空手事件（n=47）：min 0.192｜p10 0.283｜**p50 0.373**｜p90 0.479｜max 0.540

两条分布几乎完全重合（连极值都交错）。**任何单一距离阈值都不可能「筛掉不相关、留下相关」**——这是本报告最硬的一条读数，也是「调 0.6 治不了观感」的充分理由。

### 4.2 杠杆二：`MEMORY_TOP_K`

**当前值 = 5（不是 3）**，已在 §1.4 证明。

**加名额救回过东西吗？救回过，但很少。** 样本 A 的 13 条命中事件里，有 2 条（EV#1105 / EV#973）的**全部**相关节落在 `section_rank ≥ 3`，即 **topK=3 时这两条会变成零相关注入**：

- EV#1105（用户立归因票那条原话）：唯一相关节 = `docs/lessons/scoring-model-pipeline-degeneracy.md › 现象`（d=0.386，`section_rank=4`）——讲「已知相关/不相关的输入得分都是 1.0」，正是「检索判别力退化」这个主题。
- EV#973：相关两节 `memory-flywheel §2.6 检索`（0.439，rank 3）与 `knowledge-base-v1 §3.3 检索通道`（0.445，rank 4）。

**但对主病灶无效**：47 条空手事件里，候选池（20 片，是 topK 的 4 倍）内**一片相关都没有**。把 topK 提到 20 等于把整池注入，结果仍是「一片相关的都没有」——**topK 只能从池里挑，池里没有的东西它变不出来**。

⇒ 结论：topK 是从 3 到 5 都试过的旋钮，**边际收益已见顶且与主病灶无关**。它当前的主要作用是「多注入 2 节更远的内容」，而这两节在样本 A 里只救回 2/13 条命中、却在 47 条空手事件里各多塞 2 片无关内容。本报告不建议在归因为「语料/主题错配」为主的前提下继续加名额；若要动，方向只能是往下（回 3），但那会牺牲上面那 3 条——**属权衡，不属调参**，不作为建议（§6）。

### 4.3 杠杆三：召回与改写（本次探到的第三个疑点）

**「池内无相关片」里，有一部分不是语料缺口，而是没召回到。** 可证的一例，以及一处必须承认的不可证：

### 4.4 语料面的结构缺口

样本 A 的 47 条空手事件里，28 条（60%）的主题属本仓、但**白名单三目录里没有对应文档**：UI/视觉（导航栏 188px、内容居中、字体加粗）、产品形态（回退 vs 分叉、气泡元素取舍）、工单细节（M1 怎么修、8 条素材是哪些）、文案（铁律 md 化、去 AI 味）。这些规格的真实落点是 `docs/run/**` 与代码，而扫描白名单是 `docs/adr/` `docs/lessons/` `docs/plans/`（常量 `SCAN_PREFIXES`，定义在 `scripts/flywheel/scan.mjs`，消费方 `packages/server/src/routes/memory.ts`）——**语料不覆盖，检索再准也答不上**。

## 5 判据边界与可证性限制（请审查者按此打折）

1. **相关性判定是人判的**，判据已写在 §1.3。全部 90 条 event 的判定与依据摘录都在附录里，可逐条复核；边界事件（`borderline=true`）共 14 条，两种读法下的命中率为 **13/60（严格）与 15/60（宽松）**，**不影响任何旋钮结论**。
2. **「池内无相关片」是逐节标题 + 摘要级的判定**，未逐片读全文；样本 B 出现 1 例（EV#790）池内确有相关节而被挤压出——**同类风险在样本 A 中不能排除**，故「池内无相关片」应读作「**未观察到相关片**」。要根治这一不确定，需要 §6 提议的埋点增强。
3. **索引新鲜度不可复原**：`retrieval_candidates` 只记「当次召回了什么」，不记「当次索引里有什么」；扫描器只在 server 启动时重扫。凡语料文件的写入时间与查询时间接近（EV#975 那类），是否属召回失败**不可判**——本报告一律按「不可判」处理，未计入任何桶。
4. **样本偏斜**：样本 A 是「最近 60 条」，单会话最多占 27/60，且该窗口正逢一批 UI 迭代（主题高度集中在「视觉/文案」），域外比例被抬高；14 天全库的口径见 §1.1 与 §3（机械读数均为全库）。
5. **topK 时代对比含混淆**：topK=3/5 两个窗口的会话构成不同，§3.1 的距离对比只能作旁证，不能当因果。
6. **`probe` 行 `rrfScore` 恒 NULL**：探针行不参与 RRF，因此「若 topK 更大 / 阈值更紧，会注入哪几节」在现有流水里**无法复原**——本报告对第 4 态的计数因此是「按池内节标题人工判定」而非「按融合分推算」。这是本次取证最硬的一处盲区。
7. **未越界**：全程只读快照与源码，未改 `MEMORY_MAX_DISTANCE` / `MEMORY_TOP_K`、未动黄金集、未重启实例、未碰 3200/5173、未跑 `retrieval-baseline` 跑批。
