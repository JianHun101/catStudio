## 三、零夹带核验（本票自证的核心）

审查者审的是**分支 tip 的内容**，推上远端、落进 `dev` 的是**合并提交**。二者一有偏移，审查就不覆盖实际落地的东西。

**判据 = 双向并集等式**（上轮经双方独立复现后定案的形态，取代了被证伪的「树哈希三重相等」）：

```
$ git diff fd119c6 0db79e9 | git hash-object --stdin   →  d7e2ab364a663ce0efef583a5445b717c82a145d
$ git diff 8949e89 9294de1 | git hash-object --stdin   →  d7e2ab364a663ce0efef583a5445b717c82a145d   ✅ 相等
$ git diff 9294de1 0db79e9 | git hash-object --stdin   →  e13dafdbf8c688de0b37da24326f716e5eff034d
$ git diff 8949e89 fd119c6 | git hash-object --stdin   →  e13dafdbf8c688de0b37da24326f716e5eff034d   ✅ 相等
```

（`fd119c6` = 合并第一父，`9294de1` = 第二父，`8949e89` = `git merge-base`。）

**合并对两个父各自引入的，恰好等于该支相对 merge-base 的自有增量 —— 两个方向都不多不少。** 反向那条还顺带证了「没有解冲突改写」。

**基线必须取 `git merge-base`，不能取「当时的 dev」** —— 以 `c0383c9` 为基线会得到 9 文件（含两个票面，它们在合并两侧祖先上都已存在、本就不属引入面），看起来像夹带。这是上轮踩过的假红，记此以免重踩。

### 门禁 `LAST_REVIEWED` 语义逐笔记账（我上轮自定的纪律）

门禁判据是 `LAST_REVIEWED == 本地推送 sha`。本轮：

- 审查者逐字看的是 **`9294de1`**；
- 推的是 fan-in 之后的会话分支 tip **`0db79e9`**，它是 `9294de1` 的直系后代；
- 故 `.push-gate` 被写成一个**审查者从未逐字看过的 sha**。

**我认为这在本轮是对的，理由是可验证的**：上表两向相等即「fan-in 是内容零新增的机械合并」。**但门禁本身分不清「内容零新增的合并」与「在合并里夹带改动」** —— 这正是已立的 `docs/run/closeout-gate/tickets.md`（未派活）。在那之前，**收口记录必须逐笔写明合并的内容差分** —— 本节即是，§一可加性核对为辅证。

## 六、Phase I-b 行为面：落地的同时，它自己的那格**仍未证**

形态 G 的活实例行使需要「一只 `role === 'reviewer'` 的猫跑一轮」。**本票落地后、重启生效前，跑着的仍是 Phase I 代码 ⇒ 尚未行使过。** 实据（服务端日志）：

```
cat worktree ready      : 7 次（Phase I 已生效并在跑：三只猫各建过树，含后续轮次）
review view prepared    : 0 次（Phase I-b 新增串 —— 未行使，符合预期）
```

**下一格断言点**：重启后**第一次真审查者执行** ⇒ 日志应出现 `review view prepared`（带 `merged` / `skipped` 计数），且该审查者树 HEAD = 其猫分支上的 merge commit（`git log -1 --format=%s session/<sid8>-<猫名>` ⇒ `review view session/<sid8>-<来源猫分支>`）。**这条是「可审计」的落点，也是 ADR 0015 转正前最后一个空格的候选填充物。**

## 八、留一句给将来的读者

这一票的价值不在「审查者终于能读对被审内容了」，而在**它把「读不出是旧的」这件事变成了可断言的红格**：

- 第 1 笔的 V16-b 证的是「审查者工作区**不含**被审提交」——那时它是一条**推断**；
- 第 2 笔把它翻成 `ancestor`、**两条对照原样保留**，于是「缺口存在」与「缺口已修」用的是**同一格**，翻的是期望值、不是删格。删掉任一对照，这格就退化成恒绿门。

**顺带一个结构性巧合值得记**：同一个「worktree 共享 object store」的性质，既是 `serial.ts:770` 被**证伪**为缺口的原因（猫分支的 sha 在会话树里读得到），也正是 G 方案**成立**的原因。**同一机制面既能解除一个担忧，也能支撑另一个方案 —— 判据落在具体读数上，不落在机制名上。**
