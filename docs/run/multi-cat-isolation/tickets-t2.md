## 一、为什么「模拟」不能直接变成「写测试」

T-1 是「测试先行」：被测面是**两行调用点**，写 `it.fails` 编码目标行为即可。**T-2 不是同一个形状**：

| 面       | T-1                    | T-2                                                                                                      |
| -------- | ---------------------- | -------------------------------------------------------------------------------------------------------- |
| 被测对象 | `serial.ts` 两处调用点 | 分支模型 + worktree 生命周期 + fan-in 合并 + 回收                                                        |
| 未知量   | 已知（改哪两行）       | **未知**（E1 已证：初稿命名根本建不出来）                                                                |
| 现有代码 | 可测（改调用点）       | **fan-in 枚举/守卫/回收全部不存在**（全仓 `for-each-ref` / `MERGE_HEAD` **零命中**，已 `git grep` 复核） |

⇒ 先做**模拟勘验**：用真 git 命令把 T-2 落地后的完整生命周期跑一遍，把「哪些格子会炸、正确顺序是什么」量出来。**Phase S 的结论直接喂给 Phase T 写测试**——否则测试写的是我的想象，不是 git 的实际行为。

## 二、模拟矩阵（12 格，逐格必须有实跑读数）

> E1–E5 已验 5 格（斜杠命名不可实现 / ff-only fan-in 必挂 / no-ff 自幂等 / 冲突留 `MERGE_HEAD` / 空合并静默成功），**不重跑**，本票承接并补齐余下 12 格。
> 每格产出：**命令 + 原始输出 + exit code + 一句结论**。

### 组 A · 建立（3 格）

| #   | 格                     | 要验什么                                                                                                                   | 已知风险                                                           |
| --- | ---------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| A1  | 猫 worktree 分叉与共存 | `git worktree add -b session/<sid8>-<cat8> <path> session/<sid8>` 能建；**同时** `session/<sid8>` 分支与其 worktree 均存活 | 路径 `<sid8>-<cat8>` 与会话路径 `<sid8>` 是否互相干扰              |
| A2  | 同猫重复建 → 幂等复用  | 第二次建走「已存在 → 复用」，**不重建、报错为 0**；（对照 `ensureSessionWorktree` 现有语义 `git-utils.ts:379`）            | 现有实现在「分支已被别的 worktree 占用」时不复用——**猫分支下必现** |
| A3  | 双猫并存 + 提交作用域  | catA / catB 同时活着；catA 侧 `git add -A` **扫不到** catB 的未提交文件                                                    | 这是 F1/F4 的病根，必须实测而非推断                                |

### 组 B · 审查侧（2 格）

| #   | 格                     | 要验什么                                                                                         | 已知风险                                                                |
| --- | ---------------------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------- |
| B1  | detached 审查 worktree | `git worktree add --detach <path> <sha>` 读到的是**该 sha 的树**，不受任何工作区未提交改动污染   | —                                                                       |
| B2  | 审查 worktree 回收     | `git worktree remove` 后无残留（含 symlink 空壳）；**Windows EPERM**（他进程持 cwd）下的失败形态 | 本仓有前科：`remove` 只注销 git 层留 symlink 空壳，需逐链接删（不跟穿） |

### 组 C · fan-in（5 格，**核心**——T-2 新建面）

| #   | 格                 | 要验什么                                                                                                                          | 已知风险                                            |
| --- | ------------------ | --------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| C1  | 猫分支枚举         | 按前缀 `session/<sid8>-` 列出猫分支；**含空集**（无猫提交过）；**不误收** `session/<sid8>` 本身与 `session/<sid8>-x` 之外的同类名 | 全仓零 `for-each-ref` ⇒ 纯新增原语，前缀边界要实测  |
| C2  | 两猫按序 no-ff     | catA 合完再合 catB，两条都真进集成分支（E2 已证 ff-only 在第二条挂 ⇒ 此格验 no-ff 走通）                                          | —                                                   |
| C3  | 整链幂等           | 全链**重跑**⇒ 无新 merge commit、HEAD 不变、exit 0（E3 只验了单条，此处验**整链**）                                               | 中断重跑的基础                                      |
| C4  | 真冲突 → 守卫      | 冲突后 `MERGE_HEAD` + `UU` 存在 ⇒ **守卫能探测到** ⇒ 恢复路径（`merge --abort` / `reset`）能把仓库带回可重跑态                    | E4 只验了「会留半合并态」，**没验恢复**             |
| C5  | 空合并（猫零提交） | 某猫分支 == 分叉点 ⇒ 合它**不造 merge commit**（否则每轮收口都多一笔垃圾 commit）                                                 | 与 E5 同源但方向相反（E5 是集成侧空，此格是猫侧空） |

### 组 D · 收口与回收（2 格）

| #   | 格             | 要验什么                                                                                  | 已知风险                                                     |
| --- | -------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| D1  | dev 侧 ff-only | 集成分支快进合进 dev 后，**猫的提交确实出现在 dev 上**（端到端锚点，不是「命令 exit 0」） | E5 的教训：`exit 0` 不等于「东西进去了」——必须验**内容在场** |
| D2  | 回收           | 删猫 worktree + 猫分支；**孤儿分支**（worktree 已被删，无 `.git` 标记）也能被枚举到并回收 | 本仓有前科：worktree 删后留 symlink 空壳                     |

> **D2 的硬前提**：回收**必须排在 fan-in 成功之后**且**必须能识别「已合的猫分支」**——否则会把未合的活删掉。此格须显式验「未合分支不被回收」。

## 三、判据（逐条可执行）

- **S1 矩阵齐**：12 格逐格有实跑读数，无一格压成「同上」或注释。
- **S2 反向对照（防恒真）**：**至少**下列三条须有反向验证，证明判据是活的：
  - **C3 幂等**：故意造一次真变更（新提交）⇒ 判据必须能测出 HEAD 变化；然后回滚 ⇒ 判据回到「不变」。
  - **A3 隔离**：故意在 catA 放一个未提交文件 ⇒ catB 侧的「不可见」判据必须**能测出可见**才算被判过（先让它红一次）。
  - **D1 内容在场**：判据是「猫的提交出现在 dev 上」——须用一个**已知不在场**的文件名做反对照，证明该判据不是恒真。
- **S3 缺口清单**：模拟中发现的、ADR 未覆盖或判断错误的地方，逐条列出（含「ADR 原文怎么写的 / 实测是什么」）。**这一条与 12 格同等重要**——E1 就是这么抓到的。
- **S4 零本仓改动**：`git status` 结束时只有本票产物（脚本 + 报告）；`packages/` 一行未动。
- **S5 闸绿**：提交时 `pnpm lint` + `pnpm test` 全绿（本票只加文档与 `.mjs` 脚本，不触生产代码）。

## 四、红线（硬，违一条即停并报店长）

1. **绝不碰本仓的 git 状态**。所有实验在**系统 temp 下的一次性仓**跑。**不得在仓库根或 `catStudy-sessions/` 下建临时目录**——本仓有 `handoff-test-*` 落在仓库根被 auto-commit 扫走的实证（复发 2 次）。
2. **不 `git add -A`**。限定路径 add → `git diff --cached --name-only` 核对 → 裸 `git commit`。
3. **删 symlink 绝不 recursive 跟随**。删临时目录前先确认里面有没有指向别处的 junction/symlink；本仓实测过「跟穿会删掉主仓库 `node_modules`」。
4. **不 push 任何东西**（临时仓无远端；`origin` 一律不碰）。
5. **结束前删净临时目录**，并在报告里留「删净」的复核读数。
6. **卡住或发现 ADR 与实测矛盾 → 报店长裁，不自行改 ADR / 不自行改设计**（缺口写进 S3 清单即可）。

## 决策留痕

### 为什么分 Phase S / T / I 三段，而不是 T-1 式的两段

T-1 的形态是「Phase 1 只写测试 → Phase 2 改代码」——它成立的前提是**目标行为已被设计定死**（改哪两行、改成什么，票面写得明明白白）。

T-2 不满足这个前提：`adr-0015-draft.md` 是 **proposed**，且它的 §6 刚刚被五组实测推翻过一次（初稿的分支名建不出来、幂等判断错误、T-3 方向错）。**在一个刚被推翻过一轮的设计上直接写测试，写的是想象的固化。**

⇒ 中间插一段**勘验**：先把 git 层跑通，让 Phase T 有实测依据。这不是流程洁癖——E1 那条（分支名不可实现、失败会静默降级）如果留到 Phase I 才发现，代价是一次返工 + 一次静默降级上线。

### 为什么模拟必须能反向对照

本仓已栽过「恒真绿门」：judge 扫消息 `content` 却去 grep 工作区文件 ⇒ 门恒真、结论无意义。模拟跑出 12 个绿，如果判据本身测不出红，这 12 个绿**一个都不能采信**。

⇒ S2 强制三条反向对照。**「先让它红一次」= 证明探针活着。**

### 与 T-1 的关系

T-1 已收口（`b6b7a0f`，PR #88）：`serial.ts:1167` / `:1238` 的降级路径已收窄——**这是 T-2 的前置**。本票的模拟矩阵里，A2「建不出 worktree」的失败形态正走在那条收窄后的路上（不动作 + 显式告警），不再落主仓库。
