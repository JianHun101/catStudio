**真正的缺口（F 级，Phase I 直接引入）**：

```
接线前：实施猫与审查猫同在会话树，提交落在 session/<sid8> ⇒ 审查猫工作区 = 被审内容
接线后：实施猫 → 自己的猫树，提交落 session/<sid8>-<实施猫>（fan-in 前不在集成分支上）
```

**危险度不在"读到旧代码"，在"读不出是旧的"**：文件都在、路径都对，只是内容是旧版 ——
审查者若用工作区读文件工具（而非 `git show <sha>:path`），会**静默**审一份不存在的版本，
且回执上写得头头是道。这正是本仓反复点名的「假绿门」形态，而这次它落在**质量保障本身**上。

**git 语义层面的定性已确凿、无需实测**：猫分支自集成分支 fork，fan-in 前集成分支不含其提交。
本票第 1 笔要把**后果**（审查者实际读到什么）变成实测读数，而不是停留在推断。

## 二、契约（不得擅改）

1. **判据（本票靶心，唯一）**：审查者执行时，其**工作区内容必须包含被审 sha 的改动**。
   断言形态：审查者执行后，在其 cwd 内 `git merge-base --is-ancestor <被审sha> HEAD` 为真，
   **或**实现方举证等价的、可机检的判据。**"审查者应该自己 `git show`" 不算达成** ——
   那是行为纪律，本仓已立过规矩：**纪律会失守，结构不会**（ADR 0015 §4）。
2. **零分支移动**：任何实现形态不得移动、重建、删除既有分支 ref（含 `session/<sid8>` 与 24 个存量分支）。
3. **不静默**：形态求解路上的任何失败（合并冲突 / 树不可用 / 权限）⇒ **显式抛错 + error 留痕**，
   不回落主仓库、不静默降级到共享 `workspace/`。
4. **回滚成本 = 去掉创建点**：实现不得引入需要人工清理的残留态（detached 树、临时 ref 必须在
   正常路径与异常路径**对称**清理）。
