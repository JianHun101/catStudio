# 判「要不要重启 server」看跑着的那个进程行为会不会变，不看文件名/目录名归类

## 撞出来的场景

一张改工具面的票收口时，收口记录里写了「不需要重启 server（实测判定，非按文件名归类）」，
而理由一栏填的是——「**无 server/shared 生产码**」。那句话是**按文件名归类**得出的，
**没看 diff**（记录自己事后承认：「与本仓反复复发的那类病同型——陈述未经复核的事实」）。

对同一区间实测 `git diff --name-status`：`packages/` 下 10 个文件、**非测试 3 个**。
逐条读改动性质后，三条理由没有一条是「文件名里没有生产码」：

| 文件                                     | 实测改动性质                                               |
| ---------------------------------------- | ---------------------------------------------------------- |
| `packages/server/src/restart-request.ts` | 纯 JSDoc 注释——hunk 内只有注释行，**零可执行行变更**       |
| `packages/server/src/test-helpers.ts`    | 新增测试设施；`git grep` 掉 `*.test.ts` 后**零生产消费者** |
| `packages/server/vitest.config.ts`       | vitest 专用，运行实例不加载                                |

`restart-request.ts` **确实是生产文件**——「文件名里没有生产码」是错的，只是这次没动它的可执行行。

## 现象

判据一旦退化成「按目录名归类」，两个方向都会错：

- **假「要重启」**：动的是注释、测试设施、跑批配置 ⇒ 白停一次服务。
- **假「不要重启」**：改动只在**下次启动的初始化路径**生效（建索引、补建缺失物体、新增迁移）⇒
  运行中实例行为不变，重启是白停；反过来，动的是 `import` 进主进程的执行模块 ⇒ **必须重载**
  才生效，不重启就是把改动当没做。

两个方向的代价不对等，但**根因是同一个**：判据面（哪个目录）与被判面（跑着的进程）不同面。

## 机制

判据在仓内有两处完整复述（`09bedc27` 与 `cadd96ce`），都以「**含 server 文件 ≠ 要重启**」起句，
**分叉点只在「进程」后面那个逗号**：

- 「**含 server 文件 ≠ 要重启**，要的是『跑着的那个进程**，**行为会不会变』」
- 「**含 server 文件 ≠ 要重启**，要的是『跑着的那个进程行为会不会变』」

两处之外还有两处**截短复述**（把后半句压成「运行实例」四字：「判定看运行实例而非改动面」
与「重启判定看运行实例而非改动面」）。⇒ **两种写法都在用**，引用时别把其中一种当唯一正确写法；
按措辞全仓扫时，两种措辞（含截短形）都要扫。

真正要答的不是「改了哪个目录」，是**这个改动到达不到正在跑的那个进程**：

| 改动落在哪                                                 | 何时生效                     |
| ---------------------------------------------------------- | ---------------------------- |
| `import` 进主进程的模块（执行引擎、路由、调度）            | **须重载进程**才生效         |
| spawn 的子进程（钩子每提交新起、扫描器每次运行自己 spawn） | 下次运行自生效，无需重启     |
| 启动期初始化路径（`initDb` 的迁移 / 建索引 / 补建物体）    | 下次启动生效，运行中实例不变 |
| 只被 `*.test.ts` 消费的模块                                | 运行实例行为不变             |

## 可复用的动作

1. **先取改动面读数**：`git diff --name-only <base> <tip>`（或 `--name-status`）。
   **先数文件，不先按目录名下结论。**
2. **两级粗筛够用就不必上三列**：
   - `git diff --name-only <base> <tip> -- 'packages/*/src/**' | grep -v '\.test\.'` → 空 ⇒ 不需重启
   - `git diff --name-only <base> <tip> | grep -c '^packages/'` → 0 ⇒ 不需重启
3. **粗筛非空时上「行级三列」取证**，逐文件数：**新增行 / 其中非空 / 其中非注释**；
   非注释列 > 0 ⇒ 要重启。
   - 列判据：「新增行」= `^+` 开头且非 `+++` 头（**含空行**）；「其中非空」= 去掉 `+` 后
     `trim()` 非空；「其中非注释」= 再排除**去缩进后**以 `//` / `/*` / `*` 开头的。
   - **列名必须与判据同面**：首版「新增行」列装的其实是「非空新增行」，抽验按 `--numstat`
     口径复算即判不符——**是列名与判据不同面，不是数字造假**。宁可拆成三列并逐列写明判据。
   - **判前缀前必须去缩进**：同一批改动按字面（不 `trim`）口径读，非注释列会虚高
     （实测一票里 96 → 141、59 → 104、76 → 131、7 → 24），差异**全部**来自带缩进的注释行。
     引用这三列时**连判据一起引**。
4. **有运行实例可探时，把判断降级成读数**：探一个只属于运行实例的活口（如嵌入 sidecar 的
   `/health`）→ 期望码；**同时探一个已知不该通的对照口**，证明探针非恒真（对照读数实测是
   `bad port` 与 `ECONNREFUSED` 两串不同的错误）。
5. **判「谁 import 它」，不判「它在哪个目录」**：`git grep -ln "<模块名>" -- packages/server/src`
   后过滤掉 `*.test.ts`，为空即生产码零消费者。
6. **不要混引「三读数」**：本仓「三读数」的固定所指是**收口链闭合读数**
   （`dev = origin/dev = .push-gate` 三方对齐），**不是重启判据的一部分**。
7. **审批与动作边界**：不自 kill、不自重启——**重启审批归用户**。
