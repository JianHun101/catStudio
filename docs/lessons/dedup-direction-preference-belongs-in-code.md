# 去重规则「宁多报勿漏报」的方向偏好，只写在注释里等于没写——必须由代码谓词承载

## 撞出来的场景

写一个静态检查器（扫源码找违规写法的守卫）时，「同一条违规会不会被相邻两行各报一次」
需要一条**去重规则**。第一版规则是「上一窗口命中过就跳过」——作者在注释里写了
「本规则偏保守，宁多报勿漏报」，然后就交付了。

自查推演时作者判断「这样没问题」，实测把它推翻了：**两处相邻的真实违规会被并成一条**
（输入是两处相邻，旧规则只报 1 条）——方向正好倒向了**漏报侧**，与注释里写的偏好相反。

## 现象

- 注释声明的是一个方向（宁多报勿漏报），代码谓词实现的是**另一个方向**（宁漏报）
- 两者不一致时，**生效的是代码**——注释不产生任何约束力，测试也不会因为它而红
- 这个偏差只在「边界输入」上显形：单条违规、相隔很远的违规都正常，只有相邻的会漏

## 机制

「方向偏好」是一个**关于模糊输入如何取舍**的语义，它不由作者的意图决定，
由**谓词的构造**决定。上面那条规则里，真正的判据是「锚点取哪一行 + 后续几行内须有另一半」：

- 锚点若取「窗口起始行」+ 「上一窗口命中则跳过」⇒ 相邻两处共用锚点 ⇒ 并成一条（漏报侧）
- 锚点若取「**携带前半段字面量**的那一行」+ 后续固定行数内须有另一半
  ⇒ 同一输入报 **3** 条（多报侧，fail-closed）——多出来的那条是「第 1 处的后半 +
  第 2 处的前半」这个跨组合，属**故意**保留的多报

## 可复用的动作

写完任何一条判重 / 判缺 / 去重 / 合并规则后：

1. **问一句「它在模糊输入上倒向哪一侧？」**（宁多报还是宁漏报？宁合并还是宁拆分？）
2. 构造一个**正好骑在边界上**的输入（两处相邻、恰好相隔 N 行、恰好相等），实测它的读数
3. 把读数写成测试断言 —— 方向偏好由这条断言钉住，而不是由注释描述
4. 若方向偏好的选择本身是**有取舍的决策**（如 fail-closed vs 漏报的成本对比），
   把取舍写进 ADR；但**无论取舍结论是什么，落地都必须是谓词 + 断言**，不能只是注释
