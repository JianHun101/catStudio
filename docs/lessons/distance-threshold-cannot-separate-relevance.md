# 距离阈值分不开相关与不相关——池子里没有的，topK 变不出来

## 撞出来的场景

用户报「记忆片跟说的内容关系不大」。第一反应是旋钮拧坏了：`MEMORY_MAX_DISTANCE` 太松
（不相关的也放进来）或太紧（相关的被挡）。于是拉活库全量 `retrieval_events`（1109 条 / 14 天窗口）
逐条分桶，样本 = 最近 60 条「触发消息 `role='user'` 且 `reason='ok'`」的 event（9 个会话）。

## 现象（分桶计数，样本 n=60）

| 桶                                 | 计数                              |
| ---------------------------------- | --------------------------------- |
| 空手而归（候选池内无一片相关）     | **47 / 60**                       |
| 阈值误杀（池中有相关片、被阈值挡） | **0**                             |
| 阈值误放（注入片不相关）           | 47 / 60（与空手桶 **100% 重叠**） |

**「阈值误杀 = 0」是决定性的**：没有任何一条相关片段是被阈值挡掉的。既然误杀为零，
收紧阈值只会伤害、不会改善。

## 机制

「每 event 最好一节的距离」分布（命中事件 n=13 / 空手事件 n=47）：

| 组   | min   | p10   | **p50**   | p90   | max   |
| ---- | ----- | ----- | --------- | ----- | ----- |
| 命中 | 0.172 | 0.199 | **0.362** | 0.477 | 0.532 |
| 空手 | 0.192 | 0.283 | **0.373** | 0.479 | 0.540 |

两条分布几乎完全重合，连极值都交错 ⇒ **任何单一距离阈值都不可能「筛掉不相关、留下相关」**。

清算表（判据：该 event 的最小注入距离 ≥ T ⇒ 它的注入被清零；阈值口径是严格小于）：

| 阈值 T   | 命中事件被清零 | 空手事件被清零 | 平均保留节数 |
| -------- | -------------- | -------------- | ------------ |
| 0.25     | 11 / 13        | 45 / 47        | 0.18         |
| **0.35** | **7 / 13**     | **29 / 47**    | 1.37         |
| 0.45     | 2 / 13         | 12 / 47        | 3.35         |

现状平均保留 4.88 节。收到 0.35 = 用 **54% 的有效注入**换 62% 的无效注入被清空 ⇒ 不值；
收到 0.25/0.30 等于把记忆注入整体关掉。

放宽方向同理：`MEMORY_MAX_DISTANCE` 取 0.6 时，它在 **1109 个 event 里只在 6 个**（0.54%）
上碰到过东西，被挡的行逐条读过**全是无关片** ⇒ 放宽零收益、误杀为零。

**主病灶在池子更上游**：47 条空手事件的**阈值前**候选池（KNN top-20，是 topK 的 4 倍）里，
一片相关的都没有（**47 / 47**）。池子里没有的东西，把 `MEMORY_TOP_K` 调多大都变不出来——
提到 20 等于整池注入，结果不变。

## 正解

**两个旋钮都不动**（`MEMORY_MAX_DISTANCE` 保持 0.6；`MEMORY_TOP_K` 维持 5——**5 是活库 `.env` 的取值**，
**代码默认是 3**（`packages/server/src/memory/index.ts` 的 `envNumber('MEMORY_TOP_K', 3)`，
`.env.example` 也写 3），引用时别把 5 读成默认值）。
真因是**语料覆盖**：47 条空手事件里，28 条（60%）主题属本仓、但真实规格落在白名单扫描面
（`SCAN_PREFIXES` 只扫 `docs/adr` `docs/lessons` `docs/plans`）之外；13 条（28%）是无主题
协调语（纯确认/指令，检索无从对齐）；6 条（13%）语料域外。

## 可复用的动作

1. **调阈值前先分桶，别凭观感拧**：先答「误杀多少条 / 误放多少条」。误杀为零 ⇒ 问题不在阈值，
   收紧只会伤害有效结果。
2. **阈值类判据要画两条分布再定**：只有两条分布在阈值附近**分得开档**，这个阈值才有判别力；
   分布重叠时它是恒真门（同族形态见 [判据的盲区与「本就无可指」同形](criterion-blind-spot-looks-like-truth.md)）。
3. **检索效果差先看上游池，不先看下游截断**：把候选池放宽到 topK 的数倍重搜一次，若池里
   仍无相关片 ⇒ 缺陷在召回/语料，不在排序/阈值。
4. **凡「总是有输出」的链路，单独问一句它的下限**：实测 `reason='ok'` 的 906 条 event
   **100% 至少注入 1 节**——没有「宁可空手也不塞」这一档。这决定「检索质量差」在观感上
   永远表现为「塞了不相关的」，而不是「什么都没塞」。
5. **调参建议必须与桶计数的方向一致**：分桶的结论是「不动」，就不要顺手加一个「小幅收紧更稳」
   的尾巴——那是把观感当证据。
