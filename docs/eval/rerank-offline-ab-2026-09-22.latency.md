## 二、A3 ① timeout 基线 + ③ 降级率推演

### A3 ① timeout 基线（**实施者独立复核**，票面明令不采信店长给的数）

| 读数                                          | 值                         |
| --------------------------------------------- | -------------------------- |
| 分母（reason ≠ `skipped-a2a`）                | 847                        |
| 分子（reason = `timeout`）                    | 8                          |
| **基线**                                      | **8/847 = 0.945%**         |
| 对照：不剔 `skipped-a2a` 的分母               | 940 ⇒ 0.851%               |
| `skipped-a2a` 行数（全部 `retrieval_ms = 0`） | 93                         |
| 非 timeout 行的最慢一条                       | 9836 ms（距闸余量 164 ms） |

> 余量的意义：翻线所需的最小池深 N = ceil(164 / 258.653) = 1 对。⚠️ 这是**当前活库快照**上的读数，活库每条新检索都会移动这条最慢行 ⇒ 余量是**会变的**。

### A3 ③ 降级率推演

| 面                                         | 分母 | **新增**降级 | 降级率  | 闸外总数 |
| ------------------------------------------ | ---- | ------------ | ------- | -------- |
| 黄金集（实测 retrievalMs + 实测 rerankMs） | 40   | 21           | 21/40   | —        |
| 活库全量（推演：+38.0 对 × 258.7ms）       | 847  | 837          | 837/847 | 845      |

> 「新增」= 闸外总数 − **本来就闸外**的行。活库那 847 行里已有 **8** 行是 `reason=timeout`（ms 本就 ≥ 10000）—— 不剔掉的话，加一笔固定开销会把它们原地重复计一遍，「新增」当场虚高。

> 生产侧**尚未接重排**，「跳过重排」在今天是结构性条款（票面 A3 ②），不是既存行为。
> 本表是「若接上、给定子预算」的推演，**不作 R13a 的判据**。
>
> ⚠️ 活库面用的是**均对数**（37.98 对/条）——那 40 条金标查询的池深**不代表真实流量**的池深分布。要精确推演得先采真实流量的池深，本票没采。
