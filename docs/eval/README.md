# docs/eval —— 跑批产物索引

本目录是**检索评估线的跑批快照**（产物，不是活文档，也**不是垃圾**）。回答三件事：哪份产物是
哪一批、由哪个脚本产出、当时回答什么问题。

## 口径（引用这些数字前先读）

- **手工快照机制**：没有自动重跑，产物是某一刻手工跑出来的。故「这份读数还能不能引」的判据
  不是日期，是报告 §一 的 `chunks 行数 / doc_path 数` 与「索引新鲜度」能不能对上**当前**库。
- **基线数字随语料过期**：同一脚本、同一黄金集，语料变了数字就变（实证：09-19 读 395 行/13 文档，
  09-20 读 410 行/19 文档）。跨批次比数字前先对语料读数。
- **报告断档**：09-20 之后到 2026-11-12 之间无新基线；11-12 已出 v2（黄金集扩到 59 条）。跨批次比数前先对语料读数与黄金集版本——**v2 与 v1 的 recall 不可直接比**（题面不同）。
- 引「实测」数必须锚**本目录的持久产物**；scratch 工作区的临时读数不作数。

## ⚠️ 禁移动

`retrieval-golden.json` **同时是评估中心的仓库根哨兵**（`packages/server/src/routes/eval.ts` 的
`RETRIEVAL_REPO_MARKER`）——它缺席则报告目录解析不出来。另有多处硬编码路径引用本目录文件名。
**要挪文件先扫消费面**，别按「目录整洁」的直觉动。

### 记忆检索归因数据附录（2026-09-28）

产出：活库（`cat-study-dev.db`）**只读快照**上的一次性归因取证，产出脚本不在本目录清单内（自包含
抽取，快照来源与时刻记在 JSON 的 `generated_from` 键）。回答的问题：**「记忆片跟说的内容关系不大」
到底卡在哪一环**——阈值放进了烂片，还是池子里本来就没有相关片。

| 文件                                             | 一句话                                                                                                                                                                                                                                                                                                |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `retrieval-attribution-appendix-2026-09-28.json` | 90 条 event 逐行：消息 / 会话 / `params` 快照（当次 `max_distance` 与 `top_k`）/ 判定（桶 + 细分 + 是否边界 + 相关节数 + 依据摘录）/ 距离读数（注入节逐节 doc + 节标题 + distance + rank、该 event 最小注入距离、池内 min/max、threshold 挡行）/ 计数（注入节数、池行数、池文档数、挡行数、查询条数） |

> **复算口径**（引用这些数字前先读；人判部分不可自动复算）：
>
> - **样本两分**：A = 最近 60 条「user 触发且 `reason='ok'`」（topK=5 时代），B = 对照 30 条（topK=3 时代）；`rows[].sample` 区分。
> - **相关性三档是人判的**（相关 / 弱相关 / 不相关），取严格口径：弱相关**不计入**命中；`judgement.bucket` 保留原始判定（含「命中(弱)」「命中(部分)」两个带括号取值），`judgement.headline` 是主口径桶。
> - **分桶判定树**（互斥，命中即停）：注入集含相关节 → 命中；否则相关片被 `threshold` 挡掉 → 阈值误杀；否则进了池但未进注入（`not_topk` / `budget` / `section_dup`）→ 被名额 / 排序 / 预算截断；否则 → 空手而归（再分无主题 / 语料域外 / 语料域内无对应文档）。
> - **两处口径选择**：① 阈值分界 `d = T` **视为被挡**（保留条件 `d < T`，与代码语义同源）；② 纯关键词通道行 `distance = NULL` **不参与**「最小注入距离」计算（否则该 event 会被误判成「任何阈值下都清零」）。
> - **结论落点**：`docs/plans/memory-flywheel.md` §6「检索质量：两个旋钮都不该动」= 这些读数的定稿面。
