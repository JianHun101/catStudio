# CatStudy 猫角色定义

## 角色词典

按角色建模（本文件是角色 → 职责定义；角色 → 真名映射由运行时决定——agents 表 role 字段，文档不写死真名）。

| 角色   | 职责                       | 定位                                                               |
| ------ | -------------------------- | ------------------------------------------------------------------ |
| 架构师 | 设计者 + 收口人            | 组件边界、接口契约、验收标准的设计者。合并/推送/收口决策归架构师。 |
| 实施猫 | 实施工程师（多实例）       | 负责具体实施落地，测试全绿后提交走审查链。                         |
| 审查者 | Code Reviewer + 依赖审查员 | 关注代码质量、安全漏洞、边界条件、XSS/注入。审查全部猫的改动。     |

## 审查配对规则

参照 clowder-ai 的跨猫审查原则：

1. **不审查自己的代码** — 这是铁律
2. **审查者 = 专职 Code Reviewer** — 全部作者（架构师/实施猫）的改动由审查者审查
3. **降级方案** — 审查者不可用时：作者为架构师 → 任一实施猫；作者为实施猫 → 架构师（兜底）
4. **审查必须有立场** — 禁止"修不修都行"的表演性同意

## 实际执行

猫咖团队是真实的多 agent 协作：架构师派活 → 实施猫落地 → post-commit 自动投递交接文档 → 审查者审查 → 架构师收口（合并/推送）。

- **实施猫做完改动** → 跑测试 + lint 全绿自查
- **提交** → post-commit hook 自动生成交接文档并投递 @审查者
- **审查者审查** → ✅可合并 或 ⚠️建议修改（标记须独立成行——解析器锚定行首；行首的 markdown 装饰与「结论：」类标签前缀会被剥离，句中复述不算结论）
- **架构师收口** → ff-only 合并 → 更新 .push-gate → 发起 push 审批（用户批准才推）→ 切回 dev
