# CatStudy 猫角色定义

## 四只猫

| 猫名        | 品种   | 角色                       | 定位                                                             |
| ----------- | ------ | -------------------------- | ---------------------------------------------------------------- |
| **店长**    | 暹罗猫 | 架构师 + 收口人            | 组件边界、接口契约、验收标准的设计者。合并/推送/收口决策归店长。 |
| **ds猫**    | —      | 实施工程师                 | 负责具体实施落地，测试全绿后提交走审查链。                       |
| **flash猫** | —      | 实施工程师                 | 负责具体实施落地，测试全绿后提交走审查链。                       |
| **吐槽猫**  | —      | Code Reviewer + 依赖审查员 | 关注代码质量、安全漏洞、边界条件、XSS/注入。审查全部猫的改动。   |

## 审查配对规则

参照 clowder-ai 的跨猫审查原则：

1. **不审查自己的代码** — 这是铁律
2. **审查者 = 吐槽猫** — 全部作者（店长/ds猫/flash猫）的改动由吐槽猫审查
3. **降级方案** — 吐槽猫不可用时：作者为店长 → ds猫/flash猫；作者为实施猫 → 店长（架构师兜底）
4. **审查必须有立场** — 禁止"修不修都行"的表演性同意

## 实际执行

猫咖团队是真实的多 agent 协作：店长（架构师）派活 → 实施猫（ds猫/flash猫）落地 → post-commit 自动投递交接文档 → 吐槽猫审查 → 店长收口（合并/推送）。

- **实施猫做完改动** → 跑测试 + lint 全绿自查
- **提交** → post-commit hook 自动生成交接文档并投递 @吐槽猫
- **吐槽猫审查** → ✅可合并 或 ⚠️建议修改
- **店长收口** → ff-only 合并 → 更新 .push-gate → 推送 main/dev → 切回 dev
