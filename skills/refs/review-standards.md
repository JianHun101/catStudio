# 审查标准

## P1 / P2 / P3 严重度定义

### P1 — 阻断性（必须修）

触发条件：

- **安全漏洞**：XSS、注入、越权访问、密钥泄露、`v-html` 未消毒
- **数据丢失风险**：SQLite 写入未 catch、事务未回滚、数据迁移不可逆
- **功能崩溃**：`process.exit()` 调用路径、未捕获的 Promise rejection、无限递归无断路器
- **类型安全破坏**：绕过 Zod 校验、`as any` 强制转换、API 边界无校验
- **测试破坏**：现有测试失败、测试被 skip 而非修复

修复要求：

- 立即修复，不得延迟
- 修复后重新运行完整审查周期
- 同一 P1 在 2 轮内复现 → 升级为架构问题，暂停代码修改，重新设计方案

### P2 — 必须修（不可延迟）

触发条件：

- **逻辑错误**：边界条件遗漏（空数组、null、undefined）、竞态条件、错误的状态转换
- **性能问题**：N+1 查询、重复解析/计算、阻塞主线程的操作
- **内存/资源泄漏**：未清理的定时器、未关闭的连接、未释放的 event listener
- **架构违规**：跨越 monorepo 包边界、依赖方向错误、shared 包含副作用
- **错误处理缺失**：无超时保护、无降级策略、错误被静默吞掉

修复要求：

- 在合并前修复
- 可按作者判断修复（不需要重新完整审查，除非引入新文件）
- 同一 P2 跨 3 轮未解决 → 升级为 P1

### P3 — 可选修（现场处理）

触发条件：

- **命名**：变量/函数/文件命名不够清晰
- **注释**：缺少必要注释或注释过时
- **代码风格**：与项目风格不一致但不影响功能
- **重复代码**：可提取为工具函数的小段重复
- **测试补充**：额外边界条件测试（非阻断性）

修复要求：

- 现场修或明确放弃
- **禁止写 BACKLOG** — catStudy 无 BACKLOG 跟踪机制
- 放弃的 P3 必须在审查结论中列出并说明理由

## 审查结论

审查完成后必须给出明确结论：

| 结论            | 含义                                       |
| --------------- | ------------------------------------------ |
| ✅ **可以合并** | 无 P1/P2，P3 已处理                        |
| ⚠️ **建议修改** | 存在 P2，修复后可合并（无需重新审查）      |
| ❌ **需要重做** | 存在 P1 或设计方向错误，修复后必须重新审查 |
