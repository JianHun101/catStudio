# CatStudy Review 严重度标准

## P1 — 阻塞（必须修才能合入）

影响正确性或安全性的问题：

| 类别 | 示例 |
|------|------|
| **安全漏洞** | XSS、注入、未消毒的 v-html、data: URI 钓鱼、密钥泄露 |
| **数据损坏** | SQLite 写入错误、FK 约束违反、数据静默丢失 |
| **功能崩溃** | NPE/undefined 访问导致白屏、Socket.IO 断连不重连 |
| **业务逻辑错误** | 消息发给错误的 agent、context 过滤规则失效 |
| **测试红灯** | 已有测试失败、新增功能无测试覆盖关键路径 |

**合入规则**：P1 必须全部修复，reviewer 逐项确认后才能合入。

## P2 — 应该修（强烈建议修，除非有明确理由）

影响代码质量但不立即导致故障：

| 类别 | 示例 |
|------|------|
| **性能退化** | 每次渲染都重新计算、N+1 查询、不必要的大依赖 |
| **可维护性** | 硬编码魔法数字、缺少类型守卫、as 断言掩盖运行时错误 |
| **边界遗漏** | 空输入不处理、falsy 值未守卫、并发竞态 |
| **样式/UX** | markdown 渲染异常、移动端布局破碎、word-break 激进断词 |
| **可访问性** | 缺少 alt 文本、语义化 HTML 缺失 |

**合入规则**：P2 必须当轮修完，不允许标记为"后续处理"。特殊情况需要明确记录 tradeoff。

## P3 — 锦上添花（可修可放，不记 backlog）

改善但不影响交付：

| 类别 | 示例 |
|------|------|
| **代码美化** | 变量命名可以更好、注释可以更清晰 |
| **微小重构** | 提取常量的时机、不影响行为的结构调整 |
| **格式一致性** | 已有 biome 自动处理，人工指出的风格偏好 |

**合入规则**：当场修或放下，不记 BACKLOG。不允许 P3 积累成技术债务——下次自然遇到时再修。

## 不属于 review 范围

- 功能范围变更（"能不能再加个 X"）→ 回到 plan/design 阶段
- 架构重设计（"整个方案应该换"）→ 升级为愿景级反馈，回读原始需求
- 个人代码风格偏好（biome 已覆盖的格式问题）
